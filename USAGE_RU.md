# mem-tool: инструкция пользователя

`mem-tool` состоит из трёх консольных программ:

- `mem.exe` — локальная база знаний, поиск, ответы по источникам и карта знаний;
- `mem-index.exe` — отдельный семантический каталог файлов;
- `mem-bot.exe` — Telegram-интерфейс к базе знаний.

Текущая версия единого релиза: **1.72.0-alpha.13**. Все три программы используют один
номер по правилам Semantic Versioning из `VERSIONING.md`.

Если создание карты по источникам завершилось ошибкой или было отменено,
нажмите **«Продолжить с сохранённого места»** в существующей карте.
Программа проверит и использует готовые части, включая сохранённые шаги группировки.
После остановки самой программы незавершённая карта продолжится автоматически
при следующем запуске. Пользовательская отмена требует явного нажатия кнопки.
Если карта, источники или настройки изменены, продолжение будет отклонено.
Общий двухчасовой срок снят; ожидание одного запроса остаётся ограниченным.
Одиночные порции также делятся при подтверждённом отказе модели по размеру;
временные сбои автоматически повторяются до двух раз с паузой.
Подробнее: [адаптация фрагментов к модели](docs/MINDMAP_ADAPTIVE_RU.md),
[возобновление и адаптивные порции](docs/MINDMAP_RESUME_RU.md).

После «Создать карту по источникам» задание может ждать предыдущую работу.
Баннер показывает **номер в очереди этой базы**, число заданий впереди
и прогресс первой карты. «Открыть карту впереди» позволяет следить за ней.
Не создавайте повторную карту для ускорения: новое задание встанет в очередь.
Обработчик общий для баз, импорта и индексирования, поэтому № 1 тоже может ждать.
Вкладку можно закрыть, но программу `mem` нужно оставить запущенной.
После остановки программы карта по источникам продолжает незавершённую обработку.
Зафиксированные результаты не запрашиваются повторно. Запрос, ответ на который
не успел сохраниться, может быть выполнен ещё раз. Готовый сохранённый предпросмотр
восстанавливается и публикуется без повторной генерации.
Подробнее: [очередь создания карты](docs/MINDMAP_SOURCE_QUEUE_RU.md).

В классической карте кнопки **«Назад»**, **«Вперёд»** и **«История переходов»**
возвращают к прежним узлам, видам и открытым источникам, в том числе другой карты
той же базы. Эти кнопки также есть в окне сравнения узла с документом.
История правок карты не меняется. До 100 переходов хранятся в памяти вкладки;
перезагрузка, выход и смена базы очищают их. «Очистить историю» оставляет
текущий вид. Если карта изменилась, возврат показывает актуальную редакцию
с предупреждением; источник прежней ревизии автоматически не открывается.
Подробнее: [история переходов](docs/MINDMAP_NAVIGATION_RU.md).

В карте нажмите **«Именованные виды»**, введите название и нажмите «Создать вид».
Можно сохранить до 20 рабочих состояний каждой карты. Выберите вид в списке:
«Открыть вид» применяет его настройки, «Заменить текущим видом» перезаписывает
настройки выбранного вида, «Переименовать» меняет только название, «Удалить вид»
удаляет только этот вид. Сами узлы, источники и история карты сохраняются.
Обычное «Сохранить вид» по-прежнему задаёт один вид для открытия карты по умолчанию;
именованные виды независимы от него. Подробнее: [именованные виды](docs/MINDMAP_PRESETS_RU.md).

В открытой классической карте выберите «Вид»: **Схема**, **План** или **Таблица**.
Схема поддерживает раскладки «Вправо», «Сверху вниз» и «В обе стороны».
План показывает иерархию, таблица позволяет искать и сортировать строки;
сортировка не переставляет ветви карты. «Править» открывает поля названия,
описания и текста прямо в строке. При конфликте ревизии введённый текст сохраняется
в форме, но поверх чужих изменений автоматически не записывается.

Нажмите «Сохранить вид», чтобы сохранить выбранный узел, представление, раскладку,
свёрнутые ветви, масштаб, положение прокрутки и настройки таблицы. Вид личный:
он восстанавливается при открытии этой карты тем же пользователем и не меняет
историю карты. «Загрузить вид» возвращает сохранённые настройки. Закрытие окна
само по себе новые настройки не сохраняет.
Кнопка «SVG видимых узлов» скачивает текущую раскладку без свёрнутых потомков.
Для выгрузки всей карты используйте прежнюю кнопку «Скачать».
Подробнее: [представления и сохранённый вид карты](docs/MINDMAP_VIEWS_RU.md).

В разделе «Карты» нажмите «Импорт карты», выберите OPML (`.opml`), FreeMind
(`.mm`), XMind (`.xmind`), Markdown (`.md`) либо прежний JSON mem-tool. Нажмите
«Проверить файл», просмотрите дерево и предупреждения, затем «Создать новую карту».
Для четырёх внешних форматов кнопка «Исходник импорта» в открытой карте скачивает
неизменённый оригинал. Создаётся отдельная карта с новыми IDs; история других
редакторов, вложения, пространственная раскладка и учебный прогресс не переносятся.
Если ответ сервера потерян, «Повторить создание» проверяет прежнюю попытку без дубля;
она сохраняется при закрытии диалога в той же вкладке, но не после перезагрузки
страницы. После перезагрузки сначала проверьте библиотеку карт.

Предпросмотр из консоли: `mem --dir <база> mindmap import --file <путь> --format markdown --json`.
Для создания повторите команду с `--apply --digest <digest_предпросмотра> --request-id <32_символа_hex>`.
Используйте один и тот же request-id для повторной отправки; новый ID означает новую
попытку создать отдельную карту. Форматы CLI: `opml`, `freemind`, `xmind`, `markdown`.
Подробности и пределы: [импорт внешних карт](docs/MINDMAP_IMPORT_RU.md).

Кнопка «Рабочее место чтения» открывает личный набор до 24 фрагментов документов.
Чтобы добавить материал, откройте фрагмент и нажмите «Сохранить в рабочее место
чтения». Сохраняются первые 8000 Unicode-символов,
страница и редакция. В сравнении узла с документом также сохраняется выбранный узел.
Список и активный фрагмент восстанавливаются при повторном открытии. После прокрутки
нажмите «Сохранить позицию»: закрытие окна само по себе новую позицию не записывает.
Выберите второй фрагмент в списке сравнения для просмотра рядом. При изменении
документа остаётся прежний текст с предупреждением; он не подменяется новой редакцией.

В тексте узла доступны заголовки Markdown, плоские списки, код, цитаты и выделение.
Для ссылки на другой классический узел используйте `[название](mem://map/<map_id>/node/<node_id>)`.
Ссылка относится к текущей базе. HTML не исполняется, таблицы и математическая
вёрстка не поддерживаются этим просмотром; исходный текст редактируется без изменений.
Подробнее: [личное рабочее место чтения](docs/MINDMAP_READING_RU.md).

В «Документы» откройте фрагмент, выделите текст и нажмите «Аннотировать выделение»
либо «Аннотировать весь фрагмент». Добавьте комментарий, выберите цвет и сохраните.
Кнопка «Аннотации документов» открывает сохранённые цитаты; внутри документа список
отфильтрован по нему. Доступны история, архив и возврат из архива.
В классической карте выберите узел → «Привязать аннотацию» → нужную цитату →
«Привязать к …». После сохранения нажмите «Обновить карту». Действие поддерживает
undo/redo. В аннотации «Связанные узлы» возвращает к карте, «К источнику» показывает
исходный текст и, когда доступен проверенный оригинал, PDF на нужной странице.
Изменённый источник отмечается явно; прежняя цитата сохраняется. Подробности и
границы: [инструкция по аннотациям](docs/MINDMAP_ANNOTATIONS_RU.md).

В alpha.4 откройте сохранённую аннотацию → «Выбрать новый источник» →
«Найти цитату в новой версии». Выберите нужное совпадение, сравните обе цитаты
и подтвердите новую привязку. Поиск точный, без исправления пробелов или регистра;
он работает внутри фрагментов того же документа. Предел — 50 совпадений,
1024 фрагмента и 8 МиБ текста. Неполный поиск не доказывает отсутствие цитаты;
ручной выбор новой цитаты остаётся доступен. Старая запись и её связи сохраняются.

В alpha.3 сохранённые цитаты подсвечиваются в читателе. Нажмите выделение
или перейдите к нему клавишей Tab, чтобы открыть аннотацию. Пересечения показывают
выбор записей. После первых 50 записей остальные загружаются кнопкой, до 500;
интерфейс сообщает, когда подсветка неполна.

В аннотации PDF нажмите **«Области PDF» → «Показать оригинальную страницу»**.
Выделите прямоугольник мышью либо задайте положение и размер в процентах, затем
сохраните область. Область привязана к отпечатку физического файла. Без проверенного
оригинала сохранение недоступно; старая область не переносится на новый PDF сама.
Для изображения нужен настроенный `pdftoppm`, `mutool` или Python с PyMuPDF.

**«Экспорт аннотации»** подготавливает JSON с цитатой, комментарием и областями PDF
либо Markdown для чтения. В списке **«Импорт аннотаций»** сначала проверяет файл,
показывает состав и состояние источников, затем создаёт независимые копии. JSON:
до 8 МиБ и 200 аннотаций; интерфейс экспорта выбирает одну открытую запись,
API также принимает набор ID. Оригиналы PDF, история и связи карт не переносятся.

Для перепривязки откройте прежнюю аннотацию → **«Выбрать новый источник»**.
Закройте окна, откройте нужный документ, выделите актуальную цитату и нажмите
«Аннотировать выделение» → **«Перепривязать прежнюю цитату»**. Сравните обе цитаты
и подтвердите новую привязку. Создаётся новая запись; старые связи и области
остаются у прежней. Переходы доступны в **«Истории перепривязок»**.
Неопределённый результат записи повторяйте той же кнопкой: отправка сохраняется
в памяти этой вкладки до её перезагрузки. После перезагрузки сначала проверьте список.
Подробности: [читатель, области и перенос](docs/MINDMAP_STAGE3_RU.md).

В аннотации **«Объекты графа»** позволяет создать заметку, вопрос, карточку,
гипотезу, решение или задачу с точным основанием. Введите название и собственный
текст; созданный узел имеет статус черновика. Ссылка открывает его в графе.
В действиях узла **«Аннотации источника»** возвращает к связанным цитатам.
Комментарий аннотации и текст узла остаются отдельными редактируемыми данными;
сохранённая связь показывает исходное и текущее состояния.

В классической карте «Работа с ветвью» теперь сохраняет учебные попытки в базе.
Введите собственный ответ и, при желании, уверенность; затем откройте ответ и
выберите «Ещё раз», «Трудно», «Хорошо» или «Легко». Следующее повторение назначается
автоматически. Фильтр «Только новые и назначенные к повторению» формирует текущую
очередь. После раскрытия доступна «История моих ответов»: исходный материал,
ваш ответ, оценка, уверенность и отметка подсказки. История показывает последние
20 попыток в пределах 2 МиБ; полный журнал остаётся в базе. Расписание отдельно для
каждого пользователя и сбрасывается при изменении материала. Программа не
оценивает смысл свободного ответа автоматически.

В меню «Снимки» можно открыть сохранённую карту и подтвердить её восстановление.
Восстанавливаются также прежние блокировки и ручной текст, что показано в
подтверждении. Текущее содержимое сохраняется в истории; восстановление можно
отменить обычным undo. Оригинальные документы и вложенные файлы не заменяются.

В библиотеке «Ментальные карты» нажмите «Импорт JSON», выберите файл собственного
JSON-экспорта mem-tool и откройте предпросмотр. Проверьте число узлов и состояния
источников, затем создайте отдельную карту. Исходная карта сохраняется.
Пределы: 8 МиБ файла, 1000 узлов, 2000 источников, а также обычные ограничения
редактора. Это импорт формата mem-tool; JSON Canvas, XMind и FreeMind пока не
поддерживаются. Карты с файловыми вложениями `external_file` отклоняются:
сначала сделайте копию карты и удалите в ней такие привязки, затем экспортируйте её.

При AI-построении по нескольким пакетам появится этап «Глобальная группировка».
Он добавляет общие темы и сохраняет исходные поддеревья и цитаты. Это не
автоматическое удаление дублей: разный смысл и условия остаются доступными.
Если модель вернула неполную группировку или общий контекст не помещается,
программа сообщает об ошибке; увеличьте контекст модели либо сузьте выбранный корпус.

В `mem gui` раздел «Обслуживание базы» содержит фоновые операции с графом,
пересоздание фрагментов, историю/восстановление документов и перенос базы ZIP.
«Граф знаний» открывает прежний расширенный редактор в общей сессии.
В большой карте сначала показывается «Темы и связи». Выберите тему, затем
карточку «Содержание и источники» для просмотра утверждения и цитат. Внутри темы
можно перейти к связанным темам или открыть подробный граф. Поиск и фильтры
действуют и в обзоре; группы и карточки разбиты на страницы по 24 элемента.
Пустые повторные обозначения темы внутри кластера свернуты в один узел.
Нажмите его, чтобы выбрать исходное упоминание и открыть цитаты. Кнопка
«Все исходные записи» возвращает отдельное отображение каждого упоминания.
Если в источнике явно раскрыто сокращение, карта показывает полное название.

В карточках с формулами PDF показывается оригинальная страница. Нажмите
«Увеличить / выделить формулу», обведите нужную область и нажмите «Вставить область
в карточку». Границы можно ввести в процентах с клавиатуры. Изображение сохранит
дроби, степени и корни так, как они выглядят в PDF. Выделение помнится только в
текущей вкладке, для этой цитаты и редакции. «Вся страница» возвращает полный вид.
Повреждённая извлечённая строка остаётся под «Текст, извлечённый из документа»;
программа не считает её восстановленной или проверенной формулой.
Для остальных PDF-цитат кнопка «Показать страницу изображением» доступна в
«Источниках» и «Сверке с источником». Нужны доступный оригинал и pdftoppm, mutool
либо Python с PyMuPDF (пути берутся из настроек импорта / MEM_PDFTOPPM,
MEM_MUTOOL, MEM_PYTHON / PATH). Повторный импорт ради просмотра не требуется,
если отпечаток исходного файла уже сохранён. При изменении PDF просмотр блокируется.
Автономный HTML сохраняет текст и ссылки, но не изображения страниц.

В alpha.37 повторный импорт создаёт редакцию, учитывающую исходные байты и
сохранённый путь оригинала. Изменение изображения или формулы при том же
извлечённом тексте больше не обновляет физический источник старой цитаты.
Первый явный повторный импорт документа из старой версии может создать новую
редакцию и перевести прежние ссылки графа в состояние `stale`; историю программа
сохраняет. Уже утраченную привязку старой цитаты к оригиналу автоматически
восстановить нельзя. При переносе базы используйте штатный ZIP-экспорт/импорт,
который сохраняет логические пути цитат и отдельное расположение файлов.

Недоступные локальные базы в веб-библиотеке отмечаются отдельно. После возврата
диска или каталога обновите список: доступность проверяется повторно. Такая база
не мешает операциям остальных локальных баз; серверный режим сохраняет строгий
учёт общей квоты. Достигнутая квота не запрещает открыть источник найденной записи.

«Источники и фрагменты» содержит исходный текст. «Без тематических связей»
показывает знания, которым ещё не найдена тема. Группировка не подтверждает
правильность утверждений и не добавляет смысловых связей за модель.
Удалённые карты доступны через «Корзина карт». В «Источниках узла» доступны
вложения до 8 МиБ и ссылки на граф. [Подробная инструкция](docs/WEB_COMPLETION_RU.md).

Актуальные Windows-сборки устанавливаются в `C:\Users\ZMII\bin`.

Для установки из исходников выполните `./deploy/windows.ps1` в PowerShell из
корня проекта. Скрипт сначала проверяет право создавать, переименовывать и
удалять файлы в каталоге установки. При `Deployment target ... is not writable`
тесты и сборка ещё не запускались: нужен запуск с доступом к этому каталогу.
После завершения прежние переменные окружения Go восстанавливаются.

## Системный журнал

Каждая программа автоматически пишет **mem-tool.log в текущую папку запуска**.
Флаг `--dir` выбирает базу, но не переносит журнал в другую папку. В журнале —
технические события всех подсистем, время, ошибки, этапы заданий и обращения
к моделям. Содержимое документов, запросов, ответов и секреты не записываются.
При 10 МиБ создаётся датированный архив; архивы не удаляются автоматически.

Просмотр последних событий и новых записей:

```powershell
Get-Content .\mem-tool.log -Tail 50 -Wait
```

При проблеме сохраните журнал и архивы за нужное время. Формат, состав событий,
поведение при ошибках записи и VDS: [Системный журнал](docs/LOGGING_RU.md).

## 1. Первый запуск

Убедитесь, что `C:\Users\ZMII\bin` присутствует в переменной `PATH`, затем
откройте новый PowerShell и проверьте установку:

```powershell
mem version
mem-index version
mem-bot version
```

Для семантического поиска нужен запущенный Ollama и embedding-модель `bge-m3`.
Проверить доступные модели можно командой:

```powershell
ollama list
```

Если Ollama уже установлен, но не запущен:

```powershell
ollama serve
```

## 2. Где хранится база

Обычный режим является локальным для текущего каталога. Данные находятся в
подкаталоге `.mem` того проекта, из которого запущена команда.

```powershell
cd C:\Projects\my-project
mem init
```

`mem init` нужен только для явного создания базы. Команды добавления также могут
создать её автоматически. Не копируйте открытый SQLite-файл как единственный
способ резервного копирования; перед ручным копированием закройте процессы,
использующие базу.

Другие варианты выбора базы:

```powershell
mem --global stats
mem --dir "D:\Knowledge\ProjectA" stats
mem --dir "D:\Knowledge\ProjectA" recent
mem open "D:\Knowledge\ProjectA"
mem where
```

`mem.exe` может находиться в `C:\Users\ZMII\bin`: Windows запускает его с текущим
рабочим каталогом PowerShell, поэтому обычный `mem` использует `.mem` именно из
каталога, показанного командой `Get-Location`. Для исключения сомнений выполните
`mem where`; она печатает абсолютный путь к реально открытому `store.db`.

В TUI абсолютный путь показывается при запуске. Команда `/where` повторяет его,
а `/open D:\Knowledge\ProjectA` безопасно закрывает текущую SQLite-базу и открывает
другую существующую локальную базу. Этот выбор действует в текущей сессии и не
создаёт скрытой глобальной настройки.

## 2.1. Веб-библиотека и обработка документов

```powershell
mem gui
mem --dir "D:\Knowledge\ProjectA" gui
mem gui --port 8765 --no-browser
```

`gui` открывает браузер и остаётся работать в терминале; `Ctrl+C` останавливает
сервер. Без `.mem` появляется предложение создать или открыть базу. При наличии
`.mem` в выбранной папке она автоматически добавляется в список веб-баз.
`--global` поддерживается. Команда не меняет рабочую папку процесса.

В браузере доступны создание базы, открытие существующей, список документов,
фрагменты, создание и редактирование заметок, поиск, ответы, настройки, загрузка
документов и задания обработки. Кнопка «Обновить» показывает изменения из CLI/TUI.
Библиотека и просмотр классических карт описаны ниже; прежние команды работают.

### Ментальные карты в браузере

Откройте **«Ментальные карты»** в выбранной базе. В списке показаны классические
карты с ветвями; переключатель **«Показывать архивные карты»** добавляет архив.
Нажмите на карту — она займёт рабочую область окна. **«На весь экран»** убирает
также верхнюю панель; вернуться можно той же кнопкой или Escape. **«Все карты»**
возвращает библиотеку и её навигацию.

Сначала видны центральная тема и основные ветви, масштаб — 100% для чтения текста.
Кнопка **+** справа от темы
раскрывает её дочерние узлы; **−** сворачивает. Под темой указано, сколько узлов
скрыто. **«Свернуть всё»** оставляет только корень, **«Раскрыть всё»** показывает
все узлы. Скрытие ветви не удаляет данные. Состояние вложенных ветвей сохраняется
при сворачивании родителя и обновлении текущей карты, но не после перезагрузки
страницы или перехода к другой карте.

Чтобы продолжить карту, выберите родительский узел и нажмите **«Добавить ветвь»**.
Введите название; описание и текст необязательны. Новая подтема добавится
последней среди детей выбранного узла. После сохранения путь к ней раскроется,
сама ветвь будет выделена и показана при масштабе 100%. Другие ветви сохранят
своё состояние. К заблокированному родителю добавить ветвь нельзя.

Сохранение проверяет ревизию карты; при конфликте текст остаётся в форме.
Повтор неизменённой отправки после сбоя связи не создаёт дубликат. После
перезагрузки страницы сначала проверьте карту. Добавление сохраняется в общей
истории; отмена доступна через кнопку «История». Квитанции добавлений, правок, отмен и возвратов
имеют общий лимит 1000 на базу; сохраняйте все таблицы при копировании store.db.

В панели узла нажмите **«Редактировать текст»**. Можно изменить название
(до 512 символов), описание и текст (до 65 536 символов каждый). **«Сохранить»**
записывает правку и предыдущее состояние в историю карты, без вызова модели.
Название центрального узла не переименовывает саму карту. Заблокированный узел
нужно сначала разблокировать в прежнем редакторе.

Если карта изменилась после открытия, сохранение остановится с конфликтом.
Введённый текст останется в форме: скопируйте нужные правки, закройте форму,
обновите карту и повторно откройте редактор. При сбое связи можно повторить
неизменённую отправку: успешная первая попытка не создаст второй записи.
После перезагрузки страницы сначала обновите и проверьте узел.

Редактирование ограничено картой до 1000 узлов, 2000 источников и 4 МиБ данных;
историей до 64 МиБ и 1000 квитанциями правок в одной базе. При превышении
используйте прежний редактор. Для отмены откройте «История» или используйте CLI.

**«История»** показывает действия от новых к старым, по 30 записей.
У действия показано текущее название узла; это не название на момент старой
правки. Для удалённого узла показано последнее сохранённое название.
**«Показать узел»** обновляет карту, раскрывает путь к нему и открывает текст.
Масштаб становится 100%, остальные ветви сохраняют своё состояние.
У удалённого узла перехода нет. Если узел исчез во время просмотра истории,
переход сообщит об этом; обновите историю.
«Более ранние» открывает следующую страницу; «К новым действиям» возвращает начало.
У последнего доступного действия нажмите «Отменить это изменение», затем
«Подтвердить отмену». «Оставить изменение» закрывает подтверждение без записи.
Карта вернётся к состоянию до этого действия, а сама отмена появится в истории.
После отмены можно отменить предыдущее доступное действие. Создание карты
не отменяется. Чтобы вернуть отменённое действие, нажмите **«Вернуть отменённое»**
у доступной записи отмены и **«Подтвердить возврат»**. «Не возвращать» закрывает
подтверждение без изменения карты. Возврат появится отдельной записью истории,
и его также можно отменить. После новой правки возврат может быть недоступен:
ядро проверяет совпадение текущего содержимого с состоянием после отмены.

Если карта изменилась, обновите историю перед отменой или возвратом. При сбое связи повтор
той же отправки не отменяет следующий шаг. После перезагрузки сначала проверьте
историю. Помимо общих лимитов веб-редактирования, каждый before/after снимок
отменяемого действия ограничен 8 МиБ. В полную резервную копию базы должна
входить таблицы `web_map_undos` и `web_map_redos` вместе с остальными таблицами.

**«Найти в карте»** ищет введённое слово или фразу в названиях, описаниях и
полном тексте узлов, включая скрытые ветви. Нажмите «Найти» или Enter; регистр
и е/ё не различаются. Результаты идут по порядку ветвей, по 30 на странице;
«Назад» / «Далее» показывают остальные. В каждом результате есть путь и фрагмент.
Нажатие результата раскрывает только путь к узлу, выбирает его, открывает текст
и устанавливает масштаб 100%. Состояние других ветвей сохраняется. Закрытие
поиска само по себе не меняет карту; Escape закрывает окно поиска первым.
Поиск локальный по текущей открытой карте; после обновления карты запрос
сбрасывается. Для поиска в документах используйте раздел «Поиск и ответы».

**«Основные темы»** возвращает к центральной теме и её непосредственным ветвям.
В поле **«Показать»** можно выбрать **1 / 2 / 3 уровня** под центральной темой:
корень в это число не входит. Более глубокие ветви сворачиваются. Эти команды
заменяют ручное раскрытие и возвращают масштаб 100%, чтобы текст был читаемым.
При выборе глубины скрытый выбранный узел заменяется ближайшим видимым предком.
После ручного раскрытия или команд для всей карты поле показывает «Выборочно».

**«Вписать в окно»** подбирает масштаб видимой схемы в пределах 5–100%; кнопки −/+
позволяют менять масштаб до 200%. Для перемещения тяните свободное поле мышью
или прокручивайте область карты; на телефоне — свайпом. **«К корню»** возвращает
к центральной теме. Выбранный узел сохраняется при масштабировании.

Нажмите название узла, чтобы открыть полный текст. Кнопка **«Текст узла»** и крестик
убирают панель, освобождая место для карты. На телефоне она открывается поверх
схемы. Кнопки работают через Tab/Enter; на теме стрелки ←/→ сворачивают/раскрывают
ветвь. **«Обновить»** перечитывает изменения из CLI или прежнего редактора.

**«Создать карту»** открывает форму названия (до 200 символов), описания (до 4000)
и начальной структуры. Можно создать пустую карту либо использовать шаблон
мозгового штурма, изучения темы, решения, проекта или разбора документа. Вызова
модели нет: шаблон создаёт только заготовки ветвей. Новая карта сразу открывается.
После сетевого сбоя повторите ту же отправку в открытой форме; после перезагрузки
страницы сначала проверьте библиотеку, чтобы не создать ещё одну карту.

Просмотр ограничен 1000 узлами и 4 МиБ текста карты; при превышении данные не
усекаются и остаются доступны в прежнем редакторе. Создание через веб ограничено
1000 картами, включая архивные/удалённые, и 1000 квитанциями на базу. Журнал
`web_map_creates` сохраняется в store.db вместе с обычной историей и снимками карт.

Редактирование ветвей, прикрепление/открытие источников и AI в общей оболочке
пока не подключены. Используйте прежний редактор `mem --dir '<папка базы>' mindmap open`;
в локальном просмотре показана команда с выбранной базой. Расширенный граф знаний
по-прежнему запускается через `map open`. Счётчик источников показывает число
прикреплённых связей, их актуальность проверяется в прежнем редакторе.

### Заметки в браузере

1. Выберите базу, откройте **«Заметки»** и нажмите **«Добавить заметку»**.
2. Введите текст до 2000 символов. Название необязательно (до 200 символов),
   теги задаются через запятую (до 20 тегов по 80 символов). При необходимости
   отметьте **«Важная заметка»**.
3. Нажмите **«Сохранить заметку»** и дождитесь результата. Новый текст обрабатывает
   текущая модель поиска, поэтому она должна быть доступна. Долгий текст добавляйте
   как документ — он будет разбит на фрагменты.
4. Для изменения нажмите на заметку в списке. Название, теги и важность сохраняются
   без вызова модели. При изменении текста пересчитывается его вектор.

Если запись изменена другим клиентом, сохранение отклоняется: закройте форму,
обновите список и снова откройте заметку. Существующая запись сохраняется при
ошибке модели. Запрос длится до 100 секунд; во время сохранения дождитесь результата.
После сетевого сбоя можно повторить ту же отправку в открытой форме — успешная
попытка не создаст вторую запись. Перед новой формой или после перезагрузки страницы
сначала проверьте список: черновик и ключ попытки в браузере не восстанавливаются.

У старых заметок длиннее 2000 символов здесь доступны только название, теги и
важность, исходный текст не обрезается. Максимум для чтения в редакторе — 100000
символов текста и 1 МиБ основных данных записи. Документные фрагменты изменяйте
повторным импортом.
Журнал повторных отправок находится в таблице `web_note_writes` внутри store.db;
после 100000 веб-операций действует явный лимит, CLI доступен по-прежнему.

**История изменений:** откройте заметку и нажмите одноимённую кнопку. Выберите
сохранённое состояние, посмотрите его текст и нажмите **«Восстановить эту версию»**.
Текущая сохранённая запись останется в истории; несохранённые правки формы закроются.
При конфликте закройте окно и заново откройте заметку из обновлённого списка.

**Удаление:** в редакторе нажмите **«В корзину»**. Сохранённая заметка исчезнет из
обычного списка и поиска. Откройте **«Корзина заметок»**, выберите запись и нажмите
**«Вернуть из корзины»**. Вернутся прежний ID, текст, теги, важность и вектор.
Модель не вызывается; дата записи обновляется. Вектор прежней модели может быть
несовместим с текущим поиском по смыслу — используйте поиск по словам.

История сохраняет изменения через веб. Правки из CLI сохраняются как исходное
состояние при следующем веб-изменении; промежуточной истории CLI нет. Удаление
командой терминала не отправляет заметку в веб-корзину. Документные фрагменты
в корзину заметок не попадают.

До 10000 сохранённых состояний / 256 МиБ снимков на базу, до 2 МиБ на снимок.
При достижении лимита новая операция отменяется без изменения заметки. Очистки
истории и безвозвратного удаления через веб пока нет. Для резервного копирования
сохраняйте store.db целиком с `web_note_history`, `web_note_trash`, `web_note_writes`.
После сетевого сбоя повторите ту же попытку в открытом окне; после перезагрузки
страницы сначала проверьте список и корзину.

### Добавление документов

1. Выберите базу и нажмите **«Добавить документы»**.
2. Выберите файлы Markdown, PDF, DjVu, DOCX или текст UTF-8
   (TXT, CSV, TSV, JSON, XML). При необходимости задайте теги и важность.
3. Нажмите **«Загрузить и обработать»**. Дождитесь завершения передачи файлов.
   В разделе **«Обработка»** появятся этапы и результат; вкладку можно закрыть.
4. После статуса **«Готово»** откройте документы и их фрагменты. Частичный импорт
   показывает число пропущенных страниц; его можно повторить.

Модель поиска должна быть доступна: используется конфигурация выбранной базы.
Новая база по умолчанию использует Ollama/bge-m3. PDF/DjVu/OCR требуют тех же
установленных инструментов, что `mem import`; программа ничего не устанавливает
и не скачивает автоматически. Модель можно изменить в разделе «Настройки» либо
командами `mem --dir <папка базы> config ...`.

### Настройки базы и модели

1. Выберите базу и откройте **«Настройки»**.
2. Задайте модель поиска и отдельно модель ответов. В локальном режиме укажите
   точное имя уже доступной модели, на сервере выберите разрешённую администратором.
   Пустая модель ответов отключает генерацию. Сохранение не проверяет доступность
   и не устанавливает модели.
3. Задайте размер фрагмента (100–2000 символов), перекрытие (до 1000 и меньше
   размера) и способ разбиения. При необходимости раскройте **«Бюджет ответа»**.
4. При смене модели поиска подтвердите, что старые векторы не пересчитываются,
   и нажмите **«Сохранить настройки»**. Несовместимые записи по-прежнему доступны
   по словам; для поиска по смыслу потребуется повторная обработка.

Разбиение применяется к новым запускам обработки, в том числе к ожидающим заданиям.
Сохранённые данные и уже выполняемая обработка не меняются. Автоматический пересчёт
индекса с откатом пока не реализован. Веб-ответ ограничен 90 секундами модели,
4096 токенами и 48 000 символов контекста; большие бюджеты базы сохраняются для CLI.

Если настройки изменились в другой вкладке или терминале, сохранение отклоняется.
Нажмите **«Перечитать настройки»** и повторите нужные изменения. Это заменяет
несохранённые значения формы. CLI при таком конфликте также требует повторной
команды. Не редактируйте одновременно через старые бинарники: они не поддерживают
новую блокировку конфигурации.

Адреса сервисов и ключи остаются в конфигурации базы и не показываются в браузере.
Для Polza заранее задайте ключ через существующую команду `config set-polza-key`.
В серверном режиме это делает администратор. Его список `models` в server.json
разрешает конкретные имена, а не новые сетевые адреса, например:

```json
"models": [
  {"role": "embedding", "backend": "ollama", "model": "bge-m3"},
  {"role": "answer", "backend": "ollama", "model": "YOUR_INSTALLED_CHAT_MODEL"}
]
```

Используйте реальные имена моделей своего сервиса и перезапустите `mem serve`
после изменения server.json. Без списка можно сохранять текущие модели и менять
остальные параметры; новая модель должна быть разрешена администратором.

Оригиналы сохраняются в `.mem/uploads/<source-id>/<имя файла>`, задания — в
`.mem/web-jobs.db`. Не удаляйте их во время обработки. На сервере пользователь
передаёт файл из браузера, а не путь к файлу на сервере.

**Повторная загрузка** одинакового файла возвращает существующее задание;
метаданные документа не перезаписываются. Если содержимое изменилось, создаётся
отдельный документ.

**Папка с документами.** В форме «Добавить документы» переключите «Что добавить»
на «Папку с документами» и выберите папку на своём компьютере. Вложенные папки
включаются автоматически. Проверьте список и число пропущенных файлов: передаются
Markdown/PDF/DjVu/DOCX и текст UTF-8 (TXT/CSV/TSV/JSON/XML). Допускается до 20 подходящих документов за одну загрузку;
для большей папки выберите меньшую подпапку или отдельные файлы. Одинаковые имена
в разных папках не смешиваются; одинаковое содержимое считается дубликатом.
Дождитесь окончания передачи файлов, затем вкладку можно закрыть. Уже принятые
задания продолжаются, пока работает программа mem.

**Новая редакция.** Откройте веб-документ → «Загрузить новую редакцию» → выберите
один файл. Проверьте подставленные теги и важность и отправьте на обработку.
Имя нового файла может отличаться. Прежний оригинал и история сохраняются;
документ обновится после обработки без создания второго документа в библиотеке.
Если он изменился за время ожидания, задание получит статус «Документ изменился».
Закройте форму, обновите список и заново выберите редакцию, учитывая текущие данные.
Ошибка обработки или конфликт не заменяет содержимое документа. Статус «Готово
с пропущенными страницами» означает запись доступных фрагментов; проверьте результат.
Эта кнопка доступна для документов, ранее загруженных через веб. Для старых
CLI-документов пока используйте обычный импорт.

При первом обращении для записи очередь обновляется до схемы 2. Для возврата
к alpha.2 потребуется копия всей `.mem`, сделанная до обновления при остановленных
писателях. Простое понижение номера схемы не поддерживается.

**Отмена** останавливает очередь либо запрашивает остановку текущего импорта.
Если атомарная запись уже завершилась, результат остаётся «Готово».
**Повторить обработку** запускает новую попытку с начала, с текущими настройками
базы. Оригинал сохраняется. После остановки сервера незавершённое задание получает
статус «Обработка прервалась»; ожидающие задания продолжаются при новом запуске.
Сбой после успешной записи документа распознаётся по журналу импорта.

Лимиты одной базы: до 20 активных заданий, 1000 оригиналов, 1 ГиБ оригиналов;
один файл — до 64 МиБ. Выбор в браузере — до 20 файлов за раз. Обработка ограничена
30 минутами, 20 000 фрагментами и 20 попытками. Эти лимиты не включают размер
векторов и временных OCR-файлов; общие квоты сервиса ещё предстоит реализовать.
Раздел показывает активные и последние завершённые задания (до 100 записей).

### Поиск и ответы в браузере

Откройте «Поиск и ответы», введите запрос и нажмите **«Найти фрагменты»**.
Режим «По смыслу и словам» использует модель поиска базы. «По словам» работает
без обращения к модели поиска, в том числе для записей с прежними векторами.
«Только по смыслу» сравнивает совместимые векторы; несовместимые записи обозначаются
сообщением и доступны через поиск по словам.

В «Фильтрах» задаются теги (любой из перечисленных), важность, дата добавления,
диапазон физических страниц и минимальная оценка. Оценка ранжирования не означает
вероятность правильного ответа. Можно вывести от 1 до 50 фрагментов.
Для ограничения одним документом откройте его в библиотеке и нажмите
**«Искать в документе»**; **«Искать во всей базе»** снимает это ограничение.

**«Получить ответ»** сначала выполняет такой же поиск, затем обращается к модели
из `answer.model`. Настроить её пока можно прежними CLI-командами. Без модели
ответов найденные фрагменты останутся доступны. Ответ содержит ссылки `[1]`, `[2]`
и страницы; ниже показаны использованные источники. Ответ без корректных ссылок
отклоняется. Проверяется принадлежность ссылок найденным данным, а не истинность
каждого вывода нейросети. Если данных недостаточно, уточните вопрос или фильтры.

**«Открыть фрагмент источника»** показывает сохранённый текст из базы. Это не
открытие оригинального PDF на диске. При изменении записи после поиска появится
сообщение с предложением повторить поиск. Для ответов актуальность использованных
записей проверяется и после генерации. В результатах видны первые 2000 символов;
в окне фрагмента — до 100 000 символов с явной отметкой об ограничении.

Запрос можно отменить; переход в другой раздел или базу также останавливает ожидание.
Один пользователь выполняет один запрос, сервер — до двух одновременно, до 100 секунд
на запрос. Веб-поиск этого этапа ограничен базой до 20 000 записей и 64 МиБ сохранённого
содержимого с векторами. Для большей базы пока используйте CLI. Для ответа используются
до 48 000 символов контекста и до 4096 токенов вывода; меньшие настройки базы сохраняются.

### Размещение баз

При создании можно оставить путь пустым: программа выберет свою папку. Чтобы
создать `.mem` в определённой папке, сначала создайте саму папку и укажите её.
Существующая `.mem` никогда не перезаписывается. При открытии можно указать папку
проекта или `.mem`. Просмотр существующей базы не запускает миграции или модели.

Каталог веб-баз по умолчанию: `%APPDATA%\mem-tool\web` в Windows и
`<UserConfigDir>/mem-tool/web` на других ОС. `catalog.db` хранит ссылки и владельцев,
а `workspaces/` — созданные в управляемом хранилище базы. Это не перенос и не
синхронизация существующих документов: ссылки на исходные файлы пока сохраняются.
Для изолированной проверки или другого каталога состояния:

```powershell
mem gui --state-dir "D:\Knowledge\WebState" --no-browser
```

### Серверный режим для закрытого доступа

```bash
mem serve --config /etc/mem-tool/server.json
```

Образец конфигурации: `deploy/web-server.example.json`. `data_dir` — каталог
серверного состояния; относительный путь разрешается от папки конфига.
Каждому пользователю задаются ID, имя и `token_env` — имя переменной окружения
с отдельным случайным ключом входа длиной не менее 32 символов. Сам ключ не
записывается в JSON. Для браузерного входа используются ID пользователя и ключ.
SSO, самостоятельная регистрация и совместные роли появятся отдельно.

`listen` допускает только loopback. Внешний доступ идёт через HTTPS-прокси;
`public_origin` должен точно соответствовать адресу в браузере, без пути и
завершающего `/`. Прокси передаёт исходный Host. HTTP-origin допустим только на
loopback для локальных проверок. Для этого режима `--dir` и `--global` запрещены.
Пользователь сервера создаёт базы в выделенном хранилище; доступ к произвольным
путям сервера через API отсутствует. Доступ к каждой базе ограничен её владельцем.

Сессия действует 8 часов и сбрасывается после рестарта. API требует cookie;
изменения также требуют точный Origin и `X-Mem-CSRF`, получаемый из
`GET /api/v1/session`. Запросы с других сайтов отклоняются. Ключи моделей и
серверные пути не выдаются в JSON. Ограничение входа — 10 попыток в минуту на
непосредственный IP; за одним reverse proxy это общий лимит. Переданные
`X-Forwarded-*` не используются как доказательство личности или адреса.

`GET /healthz` проверяет работу HTTP, `/readyz` — доступность каталога баз;
эти проверки не удостоверяют готовность Ollama или OCR. `SIGTERM` корректно
останавливает HTTP. Шаблон systemd: `deploy/mem-web.service`. Первый alpha-релиз
предназначен для проверки закрытого сценария; публичная регистрация, квоты
хранилища, перенос базы и восстановление фоновой обработки ещё не реализованы.

### Работа в TUI

Запустите `mem` без аргументов в каталоге с `.mem`. TUI поддерживает тот же
операционный набор, что и обычный `mem <команда>`: `/ask`, `/add-file`, `/import`, `/import-status`,
`/import-runs`, `/import-run`, `/index`, все `/map ...`, все `/config ...`, CRUD-команды, `/stats`, `/sources`,
`/where`, `/open`, `/version` и переход в `/repl`. Обычный текст без `/` остаётся
сокращением для поиска.

Введите `/`, чтобы открыть прокручиваемую палитру. Можно продолжить набор для
фильтрации, например `/map a` или `/config set-answer`. Пути, заголовки и теги с
пробелами заключайте в кавычки:

```text
/import "D:\Мои книги\manual.pdf" -tags "Журнал Радио"
/ask "Как настраивается устройство?" -limit 5
/map analyze "требования к давлению" -batches 4
```

В классическом `mem repl` slash-команды разбираются так же: одинарные и двойные
кавычки сохраняют пробелы, обратная косая черта позволяет экранировать кавычку
или пробел, а обычные Windows- и UNC-пути, включая завершающий `\`, остаются
буквальными. Незакрытая кавычка выдаёт ошибку и ничего не выполняет. Неверные
аргументы всех команд с автосозданием (`add`, `add-file`, `import`, `index`,
`config`), а также лишние аргументы у `init`, `version`, `help`, `stats`,
`sources`, `where/current`, `source`, `show/get/view` и `repl` отклоняются до
смены каталога, создания `.mem` или открытия SQLite.
`--` завершает разбор флагов, если имя файла начинается с дефиса.

Для `/map build` и `/map analyze` программа автоматически использует минимум
4096 выходных токенов: структурированная карта с узлами, связями и citations не
помещается в обычный короткий лимит ответа 512. Настройка
`answer.max_tokens`, если она больше 4096, сохраняет приоритет. Перед генерацией
TUI показывает фактически выбранный output budget.

Во время выполнения команда не выглядит зависшей: stdout и stderr появляются в
окне построчно сразу после их выдачи обработчиком. Например, `/import` показывает
этапы анализа документа, извлечения/OCR, разбиения и embedding, включая счётчики
вида `[текущее/всего]`. В нижней строке постоянно видны имя активной команды,
прошедшее время и количество обновлений. После окончания TUI добавляет итоговую
строку с длительностью и числом сообщений. Для быстрых команд или обработчиков
без собственных счётчиков всё равно показываются запуск, время и завершение.

Длинный вывод, включая полный текст чанка из `/show`, переносится внутри окна и
не обрезается справа. При изменении размера терминала TUI автоматически заново
компонует всю видимую историю под новую ширину; повторно выполнять команду не
нужно. Для прокрутки используйте `↑`/`↓`, `PgUp`/`PgDn`, `Home` и `End`.

`Esc` всегда возвращает на главный экран и не завершает программу. Выйти из TUI
можно только командой `/exit` или двойным нажатием `Ctrl+C` в течение двух секунд.
`Ctrl+D`, `/quit` и одиночный `Esc` программу не закрывают. Если тяжёлая операция
ещё завершается, безопасный выход ждёт её окончания, чтобы не закрыть SQLite под
работающим обработчиком.

Не путайте `mem stats` и `mem map status`: первая команда считает импортированные
записи/chunks, а вторая показывает только review-состояние графа знаний. После
`mem import` карта остаётся пустой до выполнения `mem map build` или анализа.

## 3. Заметки и поиск

Добавить данные:

```powershell
mem add "Сервер использует Ubuntu 22.04" -title "Конфигурация VDS" -tags "сервер,ubuntu"
mem add "Критически важное решение" -important
mem add-file .\notes.md -tags "документация"
```

Найти данные:

```powershell
mem search "какая ОС установлена на сервере"
mem search "архитектура" -tags "документация" -limit 10
mem search "сервер" -from 2026-01-01 -min-score 0.5
mem recent -limit 20
mem show 15
mem stats
```

Изменение записей:

```powershell
mem edit 15 "Новый текст" -title "Обновлённый заголовок"
mem retag 15 -tags "сервер,linux"
mem important 15
mem delete 15
```

`mem delete` удаляет запись безвозвратно.

## 4. Импорт документов

Для импорта Markdown, PDF, DjVu, DOCX и текстовых файлов UTF-8
(TXT, CSV, TSV, JSON, XML) с provenance используйте `mem import`:

```powershell
mem import .\manual.pdf -title "Руководство" -tags "оборудование"
mem import .\specification.md -tags "нормативы"
mem import-status --document .\manual.pdf
mem sources
```

Начиная с 1.30.0 успешный импорт PDF/DjVu сохраняет манифест каждой физической
страницы, включая страницы без текста и chunks. Проверить качество можно так:

```powershell
mem import-status
mem import-status --document "D:\Books\manual.pdf"
mem import-status --document "D:\Books\manual.pdf" --all-pages
mem import-status --json
mem import-runs
mem import-runs --document "D:\Books\manual.pdf" --status failed
mem import-run 12
```

Обычный вывод показывает сводку и проблемные страницы с реальной причиной:
пустой текстовый слой, пустой результат OCR или предупреждение о качестве.
`--all-pages` выводит также успешно сохранённые страницы. Для старой ревизии без
манифеста программа предлагает повторный import и не пытается угадать физические
страницы по разрозненным chunks.

Начиная с 1.31.0 каждая попытка импорта остаётся в локальном журнале:

```powershell
mem import-runs
mem import-runs --status partial -limit 50
mem import-run 12
mem import-run 12 --all-pages
mem import-run 12 --json
```

Статусы: `succeeded` — документ обновлён полностью; `partial` — документ обновлён,
но отдельные физические страницы получили ошибку; `failed` — база не менялась;
`cancelled` — отменено через Ctrl+C/контекст; `interrupted` — предыдущий процесс
завершился, не успев зафиксировать результат. `mem import-status` показывает
только текущую успешную ревизию, а `mem import-run` объясняет конкретную попытку.
В обычном выводе используются путь и физические страницы, а внутренние хэши не
нужны.

`mem add-file` предназначен для обычных UTF-8 текстовых файлов. Если ему передать
PDF или DjVu, начиная с версии 1.18.3, автоматически переключится на тот же безопасный
provenance-aware `mem import`. Иные бинарные файлы отклоняются до embedding.

Лимит одного текстового файла — **64 MiB** для `add-file`, `index` и импорта
Markdown. Большие тексты предварительно разделите на отдельные документы.
Импорт Markdown учитывает отмену `Ctrl+C` до сохранения документа.

При открытии физического источника цитаты обе карты проверяют сохранённый
SHA-256. Если файл изменён либо импортирован старой версией без отпечатка,
повторите `mem import <путь к PDF/Markdown/DjVu>` (для TXT/CSV/JSON —
`mem index <путь>`), затем обновите evidence карты обычным рабочим процессом.
Программа не выдаёт заменённый файл как источник прежней цитаты.

Для PDF сначала используются Poppler/MuPDF, а при их отсутствии — уже установленный
Python с модулем PyMuPDF (`fitz`). Путь можно явно задать полем `ingest.python` в
`.mem/config.json` или переменной `MEM_PYTHON`. Если на странице есть короткий,
но непустой текстовый слой, а OCR недоступен, текст сохраняется с предупреждением
о неопределённости вместо отказа от всего документа.

Ошибка рендеринга или OCR одной страницы не уничтожает результат остальных:
такая страница получает статус `failed`, а успешный документ — `partial`. Если
не извлечено ни одной страницы, прежняя ревизия остаётся активной, а причины
доступны в журнале. Отмена OCR всегда останавливает импорт. Переключение базы через `/open` во время
фоновой операции блокируется до её завершения, а целевая конфигурация и SQLite
проверяются до закрытия текущей базы.

Импорт документа атомарный: сначала извлекается текст и строятся embeddings всех
chunks, затем они вместе с манифестом страниц одной транзакцией заменяют предыдущую версию документа. Пока не
появилось итоговое сообщение `[OK] Документ импортирован`, `mem stats` не покажет
частично готовые chunks. При Ctrl+C документ не обновляется — это защита от
полупустой базы, а не потеря уже сохранённых данных.

Программа сохраняет путь к источнику, страницу, блок, chunk, ревизию документа и
хэши evidence. Для PDF/DjVu сначала используется встроенный текст. Для сканов
могут потребоваться локальные `pdftotext`/`mutool`, `djvutxt` и Tesseract.

Повторно импортируйте изменившийся документ, чтобы обновить его chunks и
provenance. Не редактируйте текст импортированного source-chunk через `mem edit`.

## 5. Ответы только по найденным источникам

`mem search` всегда показывает сырые результаты поиска. Команда `mem ask`
дополнительно формирует локальный ответ и сохраняет ссылки на evidence:

```powershell
mem config set-answer-model qwen2.5:7b-instruct
mem ask "Каков порядок запуска оборудования?" -limit 5
```

Answer-модель должна быть локальной chat/instruct-моделью Ollama. `bge-m3` — это
embedding-модель, она не подходит для генерации ответа. Если доказательств не
хватает или ответ модели не проходит строгую проверку citations, команда
завершается без неподтверждённого ответа.

Начиная с версии 1.19.1, `mem ask` отключает скрытое thinking и запрашивает у
локального Ollama JSON-ответ. Внутри prompt модель использует короткие ссылки
`E1`, `E2`, ...; mem-tool преобразует их в полные citation ID и показывает точные
источники. Если генерация завершилась по лимиту, увеличьте его, например:

```powershell
mem config set-answer-max-tokens 1024
```

В версии 1.32.0 для локальных YandexGPT-моделей автоматически применяется
строгая JSON Schema, потому что некоторые сборки возвращают `{"answer":"..."}`
без citations даже при `format:"json"`. Схема разрешает модели ссылаться только
на `E1`, `E2`, ... из найденных фрагментов. Настройки в `.mem/config.json` при
этом не меняются, а прежние совместимые модели продолжают работать по старому
контракту. Если ответ всё равно не содержит проверяемых ссылок, программа не
показывает его как подтверждённый.

В обычном выводе версии 1.21.0 технические хэши скрыты. После утверждения
показывается ссылка вида `[1, стр. 222]`, а в разделе «Источники» — соответствующие
название и полный путь PDF, физическая страница, блок и фрагмент. Поэтому источник
можно открыть и проверить вручную; внутренние citation ID и evidence hash всё
равно проверяются программой до показа ответа.

В интерактивной HTML-карте версии 1.21.4 действует тот же принцип: справа сразу
видны путь к документу, страница, блок, фрагмент и выдержка. Внутренние ID и
SHA-256-хеши доступны только в закрытом разделе «Технические данные» — раскрывать
его при обычном чтении карты не требуется. Карты, экспортированные предыдущими
версиями, необходимо создать заново командой `mem map export-html ... --force`.

Модели с тегом `:cloud` передают prompt через Ollama Cloud. Для полностью
локальной работы выберите установленную модель без cloud-тега. Начиная с версии
1.20.1, mem-tool безопасно снимает одиночную Markdown-оболочку с языком `json`,
которую Ollama Cloud иногда добавляет к корректному grounded JSON. Содержимое
после этого проходит ту же строгую проверку claims и evidence-ссылок.

Посмотреть текущую конфигурацию:

```powershell
mem config
```

## 5.1. Классические карты мыслей

Классическая карта мыслей — отдельный артефакт с одним корнем и упорядоченными
ветвями. Она не заменяет расширенную карту знаний из следующего раздела:
knowledge graph нужен для сложных перекрёстных связей, противоречий и анализа,
а `mindmap` — для спокойного древовидного конспекта, который можно раскрывать,
сворачивать и вручную редактировать. В одной локальной базе может храниться
любое количество независимых карт.

### Библиотека и визуальный редактор

Из каталога нужной локальной базы запустите:

```powershell
mem mindmap open
```

Откроется отдельная библиотека классических карт. Сервер работает только на
`127.0.0.1` до `Ctrl+C` в PowerShell и использует именно `.mem` активного
каталога. Фиксированный порт и ручное открытие:

```powershell
mem mindmap open --port 8766
mem mindmap open --no-browser
```

На экране библиотеки можно:

- создать пустую карту;
- найти карту по названию или описанию;
- изменить название и описание;
- создать независимую копию со своими ID и историей;
- убрать карту в архив и вернуть её через «Показывать архив»;
- переключить светлую/тёмную тему.

Внутри карты используйте один щелчок для выбора узла, двойной — для
сворачивания ветви. Вверху доступны поиск по названиям/summary/тексту, глубина,
«Раскрыть», «Свернуть» и параметры карты. Внизу холста находятся `−`, «Вписать»
и `+`. Перетаскивание узла на другой узел делает второй узел новым родителем;
цикл, перенос корня и изменение закреплённого узла будут отклонены.

На вкладке «Содержание» можно добавить дочерний или соседний узел, изменить
название, тип, краткое и подробное описание, закрепить, точно переместить или
безопасно удалить. При удалении явно выбирается целая ветвь либо только текущий
уровень с поднятием детей. «Источники» показывает привязанные фрагменты с
понятными координатами и состоянием `current/stale/missing`, ищет по активной
базе и добавляет локальные файлы, ссылки и узлы графа знаний. «История» содержит
snapshot, undo и redo. Горячие клавиши: `/` — поиск, `Insert` — дочерний узел,
`Ctrl+S` — сохранение формы.

Тема и свёрнутые ветви запоминаются локально в браузере отдельно для каждой
карты. Содержимое карт, история и источники остаются в текущей SQLite-базе.

Создать пустую карту и посмотреть библиотеку:

```powershell
mem mindmap create "Категорирование помещений" --description "Рабочая карта проекта"
mem mindmap list
mem mindmap show "Категорирование помещений"
```

Название карты одновременно становится названием корневого узла. В обычных
командах карту и узлы можно указывать по названиям; служебные ID нужны только
интеграциям, использующим `--json`. Если одинаковое название встречается больше
одного раза, программа не угадывает объект, а просит уточнить ссылку.

Добавить ветви и содержимое:

```powershell
mem mindmap add-node "Категорирование помещений" "Категорирование помещений" "Общественные помещения"
mem mindmap add-node "Категорирование помещений" "Общественные помещения" "Зальные помещения" `
  --kind subtopic --summary "Классификация по назначению" `
  --body "Подробный текст узла в формате Markdown"
```

Поддерживаемые типы: `topic`, `subtopic`, `fact`, `note`, `quote`, `question`,
`task`, `decision`, `link`. Параметр `--position N` задаёт нулевую позицию среди
соседних узлов; без него элемент добавляется в конец.

Изменить и переместить узел:

```powershell
mem mindmap edit-node "Категорирование помещений" "Зальные помещения" `
  --label "Зрительные и актовые залы" --summary "Уточнённая группа"
mem mindmap move-node "Категорирование помещений" "Зрительные и актовые залы" `
  --parent "Общественные помещения" --position 0
```

`--lock` закрепляет узел от изменения, перемещения и удаления; `--unlock` снимает
защиту. Программа запрещает перенос узла внутрь собственной ветки и тем самым не
допускает циклы.

Есть два явно различающихся удаления:

```powershell
# Удалить узел и всё его поддерево
mem mindmap delete-node "Категорирование помещений" "Временная ветвь" --branch

# Удалить только сам узел, сохранив и подняв его дочерние элементы
mem mindmap delete-node "Категорирование помещений" "Лишний уровень" --promote-children
```

Удаление мягкое и входит в версионируемую операцию. Закреплённый узел внутри
удаляемой ветви останавливает операцию целиком.

Привязать узел к точному импортированному фрагменту:

```powershell
mem search "требования к зальным помещениям" -limit 5
mem mindmap source-add "Категорирование помещений" "Зрительные и актовые залы" --entry 42
```

`--entry` — номер записи, показанный `mem search`/`mem show`. По умолчанию
привязывается полный chunk. Параметр `--excerpt "точная выдержка"` разрешает
сохранить только дословную часть, реально присутствующую в этом chunk. Mem
проверяет document ID, ревизию, chunk hash и excerpt перед записью. В выводе
`mindmap show` источник отображается как имя файла, физическая страница, блок,
фрагмент, понятная выдержка и состояние `current/stale/missing`; технические
хэши не засоряют обычный экран.

В 1.61.0 источниками можно управлять и прямо в браузере:

```powershell
mem mindmap open
```

Откройте карту, выберите узел и вкладку «Источники». Команда «Из активной базы»
ищет по current-chunks, умеет ограничить документ и физическую страницу и
привязывает выбранный фрагмент целиком. Кнопка «Файл» позволяет либо выбрать файл
в браузере и сохранить независимую копию в `.mem/mindmap-files`, либо указать
существующий абсолютный путь. Рядом доступны веб-ссылка и уже сохранённый узел
графа знаний. Current PDF открывается на сохранённой физической странице.

Те же операции доступны из CLI/TUI:

```powershell
# Локальный файл по существующему пути
mem mindmap source-add "Категорирование помещений" "Залы" `
  --file "D:\Документы\СП.pdf" --title "СП 1.13130"

# Веб-ссылка и узел сложного knowledge graph
mem mindmap source-add "Категорирование помещений" "Залы" `
  --url "https://example.org/spec" --title "Официальная публикация"
mem mindmap source-add "Категорирование помещений" "Залы" `
  --knowledge-node "kn-example"

# ID источника виден в `mindmap show --json`
mem mindmap source-move "Категорирование помещений" "Залы" `
  --source "mms-example" --position 0
mem mindmap source-remove "Категорирование помещений" "Залы" `
  --source "mms-example"
```

`source-remove` удаляет только связь с узлом: запись базы, исходный файл и
импортированная копия не стираются. Перестановка и отвязка входят в историю и
отменяются обычной командой `mindmap undo`. Веб-ссылка хранится как справочная и
не считается подтверждённой выдержкой локального документа. Разрешены только
абсолютные адреса `http://` и `https://` без имени пользователя и пароля;
`javascript:`, `data:`, `file:` и относительные адреса отклоняются до записи.

### AI-помощник и безопасный предпросмотр

Начиная с 1.62.0 модель не может записать ответ прямо в карту. Любая AI-команда
сначала создаёт сохранённый preview, который привязан к текущей ревизии карты и
точным versioned chunks. Только отдельная команда `ai-apply` публикует выбранные
предложения. Ошибка, отмена или закрытие интерфейса до публикации не меняют
рабочее дерево.

Создать предпросмотр новой карты по документу:

```powershell
mem mindmap ai-new "Составь подробную карту требований к АУП" `
  --document "E:\temp\mem-test4\SP10.pdf" --title "Требования к АУП"
```

Ограничить материал физическими страницами или точными chunks:

```powershell
mem mindmap ai-new "Разложи требования по темам" `
  --document "E:\temp\mem-test4\SP10.pdf" --page-from 10 --page-to 35
mem mindmap ai-new "Сопоставь выбранные фрагменты" --entry 41 --entry 57 --entry 63
```

Полный набор флагов области одинаков для генерирующих команд:

Если не указан ни один evidence-флаг, вариант «Вся активная база / без фильтра»
берёт все current versioned chunks активной локальной базы. При количестве выше
512 нужно сузить область либо явно задать `--limit`; молчаливого обрезания нет.
Это правило не действует с `--without-sources`: такой запуск намеренно не читает
локальные документы.

- `--document <путь|document-id>` выбирает один current-документ;
- `--page-from N` и `--page-to N` ограничивают физические страницы;
- `--query <текст>` оставляет chunks с этим текстом в содержимом, названии или
  тегах;
- повторяемый `--entry N` задаёт точные записи базы; если одновременно указаны
  документ, страницы или query, каждый такой entry обязан им соответствовать;
- `--node-sources` берёт current evidence выбранной ветви существующей карты:
  сначала самого узла и его дочерних узлов, а при отсутствии такого evidence —
  первого ближайшего родительского узла. Соседние ветви автоматически не
  включаются. Источник типа `knowledge_node` раскрывается в точные evidence
  anchors связанного объекта расширенной карты;
- `--limit N`, где `N` от 1 до 10000, детерминированно берёт первые N current
  chunks после сортировки по документу, странице, блоку, фрагменту и ID. Это
  лимит evidence, а не числа узлов будущей карты, и он не гарантирует обработку
  полного корпуса. Без `--limit` действует безопасный автоматический порог 512
  current chunks: при 513 и более совпадениях команда ничего не обрезает молча,
  а завершается до вызова модели и просит сузить документ/страницы/query/entries
  либо осознанно задать явный лимит;
- `--json` оставляет машинно-читаемый preview в stdout; ход обработки по-прежнему
  выводится отдельно в stderr.

`--without-sources` включает только явный непроверенный мозговой штурм и не
совмещается с `--document`, страницами, `--query`, `--entry` или
`--node-sources`. Действие `ai-sources` всегда требует current versioned
evidence и без источников не запускается.

Для уже открытой карты доступны три независимых действия:

```powershell
mem mindmap ai-expand "Требования к АУП" "Сигнализация" `
  "Добавь подтверждённые дочерние темы" --node-sources
mem mindmap ai-fill "Требования к АУП" "Испытания" `
  "Дополни описание, не стирая мой текст" --document "E:\temp\mem-test4\SP10.pdf"
mem mindmap ai-sources "Требования к АУП" "Водяные установки" `
  "Найди самые точные подтверждающие фрагменты" --query "водяные установки"
```

Команда выводит ID предпросмотра `mmg-...`. Его можно спокойно проверить и
применить позже:

```powershell
mem mindmap ai-show mmg-...
mem mindmap ai-apply mmg-...                 # применить все предложения
mem mindmap ai-apply mmg-... --select mmaip-...,mmaip-... --expect 7
```

При частичном выборе родитель каждого выбранного дочернего узла также должен
быть выбран. Перед применением mem-tool заново проверяет ревизию карты,
закреплённый digest preview и актуальность каждого document/revision/chunk
anchor. Изменившийся документ, параллельная правка или заблокированный узел
останавливают всю операцию без частичного результата. Расширение, заполнение и
подбор источников создают ровно одну новую ревизию, которая отменяется одним
`mindmap undo`.

Для свободного мозгового штурма без документов требуется явный флаг:

```powershell
mem mindmap ai-new "Варианты структуры проекта" --without-sources
```

Такая карта помечается как непроверенная модельная заготовка. В документном
режиме содержательный узел без точной citation отклоняется. Для AI-команд нужна
отдельная локальная chat/instruct-модель в `answer.model`; embedding-модель
`bge-m3` не используется как генератор.

В `mem mindmap open` те же действия находятся в отдельной широкой AI Studio.
Она последовательно показывает настройку области, реальные пакеты обработки и
предпросмотр с флажками. Правая панель узла остаётся компактной и не смешивается
с длинным процессом генерации.

### Расширенная работа: ветвь, шаблоны, сравнение и обучение

Начиная с 1.64.0 над редактором находится отдельная кнопка **«Расширенная
работа»**. Она открывает широкое рабочее пространство с четырьмя независимыми
режимами и не добавляет новые вкладки в компактный инспектор.

Задать вопрос только по выбранной ветви:

```powershell
mem mindmap ask-branch "Требования к АУП" "Сигнализация" `
  "Какие требования к проектированию и проверке указаны в источниках?"
```

В область входят выбранный узел и все его дочерние узлы. Перед генерацией
mem-tool закрепляет ревизию карты, content/state digest, точный список узлов и
все current versioned evidence. Модель не получает stale/missing источники и не
может сослаться на неизвестный фрагмент. Ответ показывает документ, физическую
страницу, блок и chunk и не изменяет карту. Если current evidence нет, команда
останавливается до вызова модели.

Посмотреть встроенные шаблоны и создать ручную карту:

```powershell
mem mindmap templates
mem mindmap template-create study "Основы радиотехники"
mem mindmap template-create decision "Выбор оборудования" `
  --description "Сравнение вариантов"
```

Доступны `brainstorm`, `study`, `decision`, `project` и `document`. Шаблон
создаёт только упорядоченные пустые ветви с origin `manual`; модель не
вызывается и непроверенные утверждения не появляются.

Сравнить два полных дерева:

```powershell
mem mindmap compare "Проект А" "Проект Б"
mem mindmap compare "Проект А" "Проект Б" --json
```

Отчёт локально сопоставляет устойчивые структурные пути и содержимое и считает
`added`, `removed`, `changed`, `moved` и `unchanged`. Переименование корня не
превращает автоматически все дочерние ветви в удалённые. Операция read-only и
не вызывает answer/embedding-модель.

Собрать учебные карточки из выбранной ветви:

```powershell
mem mindmap study "Основы радиотехники" "Усилители" `
  --output ".\amplifiers-study.md"
```

Узел типа `question` использует свой заголовок как вопрос, остальные
содержательные узлы получают нейтральную формулировку «Что важно знать о…?».
Ответ берётся только из уже сохранённых summary/body либо списка дочерних
ветвей. Источники и manifest ветви сохраняются в Markdown; новых фактов модель
не придумывает.

### Переносимый экспорт классической карты

Релиз 1.63.0 экспортирует полное текущее дерево, а не только раскрытую в
браузере часть. Формат и путь обязательны:

```powershell
mem mindmap export "Требования к АУП" --format html --output ".\aup-map.html"
mem mindmap export "Требования к АУП" --format svg  --output ".\aup-map.svg"
mem mindmap export "Требования к АУП" --format png  --output ".\aup-map.png"
mem mindmap export "Требования к АУП" --format json --output ".\aup-map.json"
mem mindmap export "Требования к АУП" --format opml --output ".\aup-map.opml"
mem mindmap export "Требования к АУП" --format markdown --output ".\aup-map.md"
mem mindmap export "Требования к АУП" --format mermaid --output ".\aup-map.mmd"
mem mindmap export "Требования к АУП" --format obsidian --output ".\aup-map.obsidian.md"
```

- `html` — один автономный файл с поиском, раскрытием ветвей, переключением
  темы, текстом узлов и панелью понятных источников;
- `svg` — векторный чертёж полного дерева с embedded provenance-метаданными;
- `png` — растровый снимок полного дерева с видимыми revision/digest и embedded
  `iTXt`-блоком `mem-provenance`;
- `json` — полный машинно-читаемый документ карты с источниками, ревизией и
  digest;
- `opml` — переносимая иерархия; summary/body, типы, origin и источники
  без потерь сохраняются в Base64-полях namespace `mem`. Обратный импорт OPML
  в mem-tool в этом релизе ещё не реализован;
- `markdown` — полный читаемый outline с текстами и человекопонятными
  document/page/block/chunk координатами;
- `mermaid` — код `mindmap` для документации и систем с поддержкой Mermaid;
- `obsidian` — одна Markdown-заметка с front matter, Mermaid-схемой, block ID,
  полным содержанием и источниками.

Markdown, Mermaid и Obsidian дополнительно несут полный canonical provenance в
Base64-комментарии. Это позволяет сохранить точные ID, порядок, тексты и
источники даже там, где видимая схема показывает только подписи.

SVG и PNG показывают всё дерево, но очень длинная подпись внутри карточки может
быть визуально сокращена. Полный текст остаётся в SVG-tooltip и embedded
provenance, а в PNG — в `mem-provenance`; HTML и JSON сохраняют его полностью.

Путь может быть относительным к текущему каталогу, но его родительский каталог
должен уже существовать. Расширение файла программа не угадывает: указывайте его
в соответствии с `--format`. Успешная команда печатает абсолютный путь, размер,
ревизию, число узлов/источников и SHA-256 digest исходной карты.

Существующий файл по умолчанию не меняется:

```powershell
# Явно разрешить замену уже существующего артефакта
mem mindmap export "Требования к АУП" --format html `
  --output ".\aup-map.html" --force
```

Без `--force` используется exclusive create. При `--force` новый артефакт
сначала полностью записывается во временный файл рядом с назначением и только
затем заменяет его. Активный `.mem\store.db` нельзя выбрать результатом даже с
`--force`. Защита распространяется также на служебные `store.db-wal`,
`store.db-shm` и `store.db-journal`. Экспорт не вызывает embedding/answer-модель,
не меняет карту и работает с тройной фиксацией revision + content digest +
state digest источников. Ограничения релиза: до 10000 узлов,
16 MiB сериализованного входа и 128 MiB готового файла. Для PNG предел строже:
до 512 узлов, 12000×12000 и 24 млн пикселей; для более крупного дерева выберите
SVG или HTML.

В браузерном редакторе `mem mindmap open` нажмите **«⇩ Экспорт»** над картой,
выберите формат и кнопку «Скачать». Диалог показывает полное число узлов и
источников и отдельно предупреждает, что файл содержит выдержки, локальные пути
и координаты документов. Место сохранения выбирает браузер; live-сервер не
получает и не принимает путь к файлу на диске.

Каждое изменение увеличивает номер ревизии. Для защищённого сценария сначала
посмотрите текущую ревизию, затем передайте её в изменяющую команду:

```powershell
mem mindmap show "Категорирование помещений"
mem mindmap add-node "Категорирование помещений" "Общественные помещения" "Новый раздел" --expect 7
```

Если карта уже стала ревизией 8, операция с `--expect 7` будет отклонена без
частичной записи. Это понадобится браузерному редактору и защищает параллельные
вкладки.

История, undo и контрольная точка:

```powershell
mem mindmap history "Категорирование помещений"
mem mindmap undo "Категорирование помещений" --expect 8
mem mindmap redo "Категорирование помещений" --expect 9
mem mindmap snapshot "Категорирование помещений" --reason "Перед крупной переработкой" --expect 10
mem mindmap snapshots "Категорирование помещений"
```

История append-only: undo не стирает старую запись, а создаёт новую ревизию,
которая ссылается на отменённое изменение. Можно последовательно отменять
несколько последних действий. Контрольные точки неизменяемы. Для автоматизации
добавьте `--json` к `create`, `list`, `show`, изменяющим командам и `history`.

В 1.60.0 хранилище и CLI дополнены защищённой визуальной библиотекой и
полноценным браузерным редактором, в 1.61.0 — поиском и управлением всеми типами
источников, в 1.62.0 — preview-first AI-помощником, в 1.63.0 — полными
визуальными экспортами, а в 1.64.0 — расширенной работой и текстовыми форматами.
Ручные, сгенерированные и гибридные карты по-прежнему
используют один совместимый формат.

## 6. Карта знаний

### Полный документ через веб-интерфейс

Запустите `mem --dir "E:\temp\mem-test5" gui` и откройте **Граф знаний**.
Добавьте документ, дождитесь импорта, выберите его и нажмите
**Построить / дополнить весь документ**. **Открыть граф** открывает прежний редактор.

Сначала сохраняются документ, исходные текстовые фрагменты и ссылки на источник.
Затем модель добавляет темы, утверждения и связи. Каждый проверенный результат
сразу доступен в графе. Размер запросов выбирается автоматически, включая большие
фрагменты без абзацев. Полный исходный текст остаётся в графе; модель получает
ограниченные окна с перекрытием. Оборванные условия нельзя достраивать по догадке.

Неверная цитата, некорректный JSON, превышение лимита ответа или сбой модели
не останавливают весь документ. Такие места показаны в **Места, требующие
повторного разбора**. Нажмите **Построить / дополнить весь документ** ещё раз:
готовые фрагменты и успешно разобранные части сохранятся, повторятся незавершённые.
Старое остановленное задание можно **Продолжить**: его готовые пакеты сохраняются.
Без модели создаётся структура с исходным текстом. Для смыслового разбора
выберите в настройках модель ответов (например, уже настроенную gpt-oss:120b-cloud).
После изменения настроек создайте новое задание.

Вкладку можно закрыть, но `mem` должен работать. Запрос модели ограничен 60 секундами,
работа над одним исходным фрагментом — двумя минутами; при необходимости фрагмент
остаётся для продолжения. Два последовательных сбоя сервиса прекращают обращения
к нему в текущем запуске. Во время ожидания обновляется время запроса. Через два
часа задание можно продолжить; остановка и отмена сохраняют готовые результаты.

**Покрыто ссылками графа** включает исходный текст. **Смысловой разбор завершён**
означает, что модель обработала фрагмент, а не извлекла и проверила каждый факт.
Утверждения остаются черновиками; ошибка цитаты никогда не заменяется выдуманным
требованием. Ошибки диска, изменения источника и отмена всё ещё останавливают
операцию с сохранением уже опубликованной работы.

Тот же режим из PowerShell (подставьте document-id из `mem map coverage --json`;
для документов, импортированных из CLI, допустим полный исходный путь):

```powershell
mem --dir "E:\temp\mem-test5" map extract "Полный разбор документа" --document "<document-id>" --all-chunks
mem --dir "E:\temp\mem-test5" map coverage --document "<document-id>"
```

`--all-chunks` принимает один документ; `--dry-run` показывает число фрагментов.
Параметры `-batches`, `-context-chars`, `--pages`, `--tag` относятся к прежнему
порционному режиму и здесь не применяются.

Для импорта доступны Markdown, PDF, DjVu, DOCX и текст UTF-8 (TXT, CSV, TSV, JSON,
XML). TXT/CSV/JSON/XML сохраняются как текст без выдуманных номеров страниц.
В DOCX извлекаются абзацы, таблицы, сноски и колонтитулы. Изображения, диаграммы
и формулы Office могут потребовать экспорта в PDF и OCR; предупреждения доступны
в результате импорта. Повреждённые, зашифрованные и неподдерживаемые файлы не
считаются успешно прочитанными. Сохраняются пределы веб-загрузки 64 МиБ на файл,
20 файлов за раз, а также пределы базы этого веб-выпуска.
[Матрица CLI/web и оставшаяся работа](docs/WEB_PARITY_RU.md).

### Команды CLI

Открыть живую карту активной базы:

```powershell
mem map open
```

Программа выберет свободный loopback-порт, откроет браузер и будет обслуживать
страницу до нажатия `Ctrl+C` в PowerShell. Кнопка «ОБНОВИТЬ» заново читает граф
из SQLite, поэтому после `map build`, `map analyze`, approve или merge не требуется
повторный экспорт. Для фиксированного порта или ручного открытия:

```powershell
mem map open --port 8765 --title "Карта проекта"
mem map open --no-browser
```

В live-режиме визуальная раскладка сохраняется автоматически:

- перетащите узел — он останется закреплённым в выбранной позиции;
- дважды щёлкните узел — он снова станет свободным для force-layout;
- pan, zoom, кнопки `+`, `-` и `FIT` сохраняют viewport;
- индикатор в заголовке показывает «ИЗМЕНЕНО», «СОХРАНЕНИЕ…», «СОХРАНЕНО»
  или «ОШИБКА»;
- «СБРОСИТЬ ВИД» очищает раскладку, фильтры и фокус основного вида, но не узлы,
  связи и источники.

### Рабочие пространства live-карты

Начиная с версии 1.51.0 верхняя панель переключает не отдельные команды, а
четыре понятных рабочих режима:

- **КАРТА** — обзор графа и остальные представления, поиск, фильтры, кластеры,
  фокус, масштаб и навигация;
- **ПРОВЕРКА** — отдельная очередь draft, stale/missing, отклонённых либо уже
  подтверждённых объектов. Щелчок по строке открывает объект в инспекторе;
- **АНАЛИЗ** — вопрос, сводка, расширение по связям, детерминированный анализ и
  экспорт выбранной области;
- **ОБУЧЕНИЕ** — генерация кандидатов, учебный маршрут, повторение и история
  прогресса.

Правая панель является инспектором только одного активного объекта. Вкладки
«ОБЗОР», «ИСТОЧНИКИ», «ДЕЙСТВИЯ» и «ИСТОРИЯ» отделяют содержание и источники от
редактирования и технического журнала. Обычный щелчок меняет активный объект,
но не сбрасывает рабочую выбранную область.

Второстепенные команды находятся в меню «ЕЩЁ». Масштаб графа меняется кнопками
на самом холсте. Фильтры слева собраны в сворачиваемые группы; каталог
кластеров сначала показывает шесть элементов, а полный список раскрывается
кнопкой либо фильтруется строкой поиска. В режимах «ПРОВЕРКА», «АНАЛИЗ» и
«ОБУЧЕНИЕ» левая панель автоматически закрывается, чтобы освободить центр.

### Выбранная область: вопрос и сводка

Начиная с версии 1.44.0 живая карта умеет использовать визуальный выбор как
строго ограниченный контекст answer-модели:

1. Откройте нужный узел или связь обычным щелчком и нажмите в инспекторе
   «ДОБАВИТЬ В ВЫБРАННУЮ ОБЛАСТЬ». Быстрый вариант — `Ctrl+Click` по объекту.
2. Тем же способом добавьте остальные узлы/связи либо уберите лишние.
3. Нижняя панель «ВЫБРАНО: N» показывает размер и краткий состав области.
   Нажмите «АНАЛИЗ» или откройте одноимённый модуль сверху, чтобы увидеть полный
   список и статистику по документам, физическим страницам и evidence.
4. Введите вопрос и нажмите «СПРОСИТЬ ВЫБРАННОЕ» либо задайте акцент и нажмите
   «СДЕЛАТЬ СВОДКУ».
5. Под ответом программа покажет понятные источники: путь к документу,
   физическую страницу и номер блока.

Начиная с версии 1.45.0 над списком выбранных объектов есть навигационные
операции, которые не вызывают модель:

- выберите «ВСЕ НАПРАВЛЕНИЯ», «ИСХОДЯЩИЕ» или «ВХОДЯЩИЕ»;
- задайте глубину 1–3 и нажмите «РАСШИРИТЬ ПО СВЯЗЯМ»;
- чтобы найти кратчайшую цепочку, оставьте в выборе ровно два узла и нажмите
  «НАЙТИ ПУТЬ» (поиск ограничен 24 переходами);
- флажки типов связей в левой панели одновременно служат фильтром навигации.

Сервер сначала проверяет manifest исходного выбора, затем строит результат по
текущему графу и возвращает новый manifest. База и сами узлы не изменяются.
Если добавились stale/missing либо закрытые объекты, их можно изучать, но вопрос
и сводка остаются заблокированными до безопасного выбора.

Начиная с версии 1.46.0 нажмите «АНАЛИЗ ВЫБРАННОГО», чтобы получить отчёт без
вызова нейросети. В нём отдельно показаны:

- документы, физические страницы и число evidence;
- связи внутри выбора и связи с объектами за его пределами;
- явно сохранённые `compares`, `depends_on`/`prerequisite`/`constrains`,
  `contradicts` и `reveals_gap`;
- аналитические узлы, уже присутствующие в выборе.

Важно: ноль противоречий или пробелов означает только, что в текущем графе нет
соответствующих типизированных объектов/связей возле выбора. Это не доказывает,
что исходный документ полностью проверен и не содержит таких сведений.

Если все выбранные evidence актуальны и объекты не закрыты, внизу отчёта
доступна кнопка «СОХРАНИТЬ АНАЛИЗ В КАРТУ». Укажите понятное название и автора.
Программа атомарно создаст `draft`-заметку с точными источниками и
`derived_from`-связями ко всем выбранным узлам. Сохранённый результат не
становится подтверждённым фактом автоматически: откройте его на карте,
проверьте содержание и используйте обычный review-процесс. Если выбор, граф или
evidence изменились после построения отчёта, запись будет отклонена — заново
нажмите «АНАЛИЗ ВЫБРАННОГО».

Начиная с версии 1.47.0 закреплённый выбор можно скачать как самостоятельный
рабочий материал. Под кнопкой анализа:

1. При необходимости введите название материала.
2. Выберите один из форматов:
   - «ОТЧЁТ · MARKDOWN» — подробные объекты, содержание, связи и источники;
   - «ПЛАН · MARKDOWN» — упорядоченные шаги по сохранённым зависимостям;
   - «ЧЕК-ЛИСТ · MARKDOWN» — тот же порядок с полями выполнения;
   - «ТАБЛИЦА · CSV» — строки объектов для Excel/LibreOffice;
   - «ВЕТВЬ · JSON» — переносимый точный subgraph вместе с manifest и анализом.
3. Нажмите «ЭКСПОРТ» и выберите место сохранения средствами браузера.

Экспорт выполняется без нейросети и не изменяет базу. В Markdown и CSV указаны
имя файла, физическая страница, блок и фрагмент. План строится только по явно
сохранённым `prerequisite`, `depends_on`, `precedes` и `happens_before`; если
таких связей нет, программа использует стабильный алфавитный порядок, а при
цикле показывает предупреждение. Если выбор или evidence изменились после
открытия панели, операция будет отклонена — выберите объекты заново. В отличие
от вопроса модели экспорт разрешён и для stale/missing evidence, но обязательно
показывает предупреждения, чтобы неполные данные нельзя было принять за
проверенные.

### Учебные карточки и открытые вопросы

Начиная с версии 1.48.0 из закреплённой области можно подготовить учебные
материалы:

1. Выберите один или несколько узлов с актуальными источниками.
2. В поле учебного акцента при необходимости укажите, что проверить: например,
   «определения и формулы» или «порядок действий». Это не добавляет новые
   сведения, а только направляет формулировку заданий.
3. Выберите желаемое число кандидатов и нажмите «СОЗДАТЬ УЧЕБНЫЕ КАНДИДАТЫ».
4. Проверьте у каждого варианта вопрос, ожидаемый ответ, документ, физическую
   страницу, блок и фрагмент. Снимите флажки с неудачных вариантов.
5. Укажите автора и нажмите «СОХРАНИТЬ ВЫБРАННЫЕ КАК DRAFT».
6. Откройте созданные узлы на карте, сверьте их с источниками и выполните
   обычный review. До подтверждения они остаются предложениями модели.

Тип `card` подходит для одного факта, определения, формулы, сравнения или шага.
Тип `question` предназначен для развёрнутого ответа; ожидаемый ответ сохраняется
в описании узла. Модель получает только evidence выбранных объектов. Каждый
кандидат без точной ссылки на переданный источник отклоняется, а изменение
manifest или evidence между генерацией и сохранением требует создать кандидаты
заново. Повторное сохранение того же набора блокируется, и частичные узлы при
ошибке не остаются.

Начиная с версии 1.70.0 генерация выполняется в ограниченной фоновой очереди.
После запуска кнопка меняется на «ОТМЕНИТЬ ГЕНЕРАЦИЮ», а под ней отображаются
позиция в очереди, текущая фаза, процент, число evidence/кандидатов и прошедшее
время. На один `mem map open` работает один worker генерации и ожидают не более
четырёх задач; если очередь заполнена, дождитесь освобождения места.

Смена выбранной области отменяет связанную с ней незавершённую задачу. При
остановке live-сервера `Ctrl+C` отменяются все queued/running генерации.
Ожидающая задача удаляется сразу, активный вызов модели получает сигнал отмены
и завершает работу на безопасной границе. Если preview уже атомарно записан,
поздняя отмена не скрывает его: интерфейс показывает готовых кандидатов.
Завершённые preview доступны текущей live-сессии не более десяти минут.

Полоска прогресса не означает генерацию точного процента токенов моделью:
проценты соответствуют проверяемым этапам `validating`, `grounding`,
`generating`, `validating-response`, необязательному `correcting` и
`verifying`. Полный текст кандидатов не передаётся при каждом polling-запросе —
он загружается один раз после состояния `completed`.

Учебные кандидаты доступны только в защищённой live-карте `mem map open` и
требуют настроенной answer-модели. Автономный HTML остаётся read-only. В 1.48.0
ещё нет расписания повторений и автоматической оценки ответа: это следующий
этап, поэтому сохранённые draft-карточки нельзя путать с готовой учебной сессией.

Начиная с версии 1.49.0 подтверждённые материалы можно собрать в учебный
маршрут:

1. Выберите исходную тему/определение либо одну из карточек и откройте панель
   «ВЫБРАНО: N». Если открыт тематический кластер, кнопка «ДОБАВИТЬ ВЕСЬ
   КЛАСТЕР» одним нажатием выбирает все его объекты; повторное нажатие снимает
   их. Отдельные узлы можно по-прежнему добавлять и убирать вручную.
2. Нажмите «ПОСТРОИТЬ УЧЕБНЫЙ МАРШРУТ». Нейросеть для этого не вызывается.
3. Изучайте этапы сверху вниз. Щелчок по карточке маршрута открывает её обычную
   карточку сведений, где можно перейти к PDF на физической странице.
4. Исправьте объекты из раздела «НЕ ДОПУЩЕНО В МАРШРУТ»: подтвердите корректный
   draft обычным review либо обновите его источник. Отклонённые и закрытые
   объекты намеренно не допускаются.
5. Если показан цикл, исправьте направления связей `prerequisite`/`depends_on`.
   Пока цикл существует, маршрут помечается как требующий внимания.

`prerequisite` означает «сначала From, затем To». `depends_on` означает
«From зависит от To», поэтому To располагается раньше From. Учитываются только
связи `active` с актуальным evidence. Черновая связь не задаёт учебный порядок,
даже если обе карточки уже подтверждены. Если связей порядка нет, программа
покажет допущенные объекты вместе с предупреждением и не станет выдавать
алфавитную сортировку за доказанную последовательность.

Начиная с версии 1.50.0 маршрут можно проходить как учебную сессию:

1. Постройте маршрут и устраните циклы либо исключённые карточки.
2. Выберите предел карточек в одной сессии: 5, 10, 20 или 40.
3. Нажмите «НАЧАТЬ ПОВТОРЕНИЕ». Программа включит новые карточки и карточки с
   наступившим сроком; будущие повторения останутся отложенными.
4. Прочитайте вопрос и сформулируйте ответ самостоятельно. Только после этого
   нажмите «ПОКАЗАТЬ ОТВЕТ» и сравните свою формулировку с эталоном и источником.
5. Поставьте честную оценку:
   - «НЕ ПОМНЮ» — повтор через 10 минут, серия успешных ответов сбрасывается;
   - «ТРУДНО» — минимальный интервал один день, коэффициент лёгкости снижается;
   - «ПОМНЮ» — первый интервал один день, второй шесть дней, далее интервал
     умножается на коэффициент лёгкости;
   - «ЛЕГКО» — первый интервал четыре дня, коэффициент и дальнейшие интервалы
     увеличиваются быстрее.
6. Нажмите «УЧЕБНЫЙ ПРОГРЕСС», чтобы увидеть число попыток, текущий интервал,
   следующую дату и карточки, готовые к повторению.

В версии 1.53.0 повторение открывается в отдельном учебном экране без карты,
кандидатов и настроек маршрута. В нём остаются только один вопрос, точный
источник, раскрываемый ответ, четыре оценки и счётчик элементов сессии. Кнопка
«ВЕРНУТЬСЯ К МАРШРУТУ» ставит прохождение на паузу, а «ПРОДОЛЖИТЬ СЕССИЮ»
возвращает к тому же вопросу. Клавиатурные команды: `Пробел` — показать ответ,
`1`–`4` — выбрать оценку, `Esc` — вернуться к маршруту.

Рабочий выбор сохраняется при перезагрузке текущей live-страницы. Поэтому после
сохранения draft или review не нужно повторять прежний Ctrl+Click-выбор. Если
перейти в «ОБУЧЕНИЕ» с пустой рабочей областью, но с активным тематическим
кластером, программа автоматически добавит весь этот кластер. При необходимости
нажмите «ОЧИСТИТЬ» и соберите произвольный набор отдельных узлов.

Оценка является самооценкой: в 1.50.0 модель не решает за пользователя,
правильный ли ответ. Каждая попытка и состав сессии неизменяемы; редактируется
только вычисляемое текущее расписание. Если карточка, её ответ или evidence
изменились, открытая сессия не примет оценку, а после повторного подтверждения
обновлённая карточка будет предложена как новая. Так старый успех не переносится
на фактически другой материал.

Начиная с версии 1.55.0 готовый маршрут можно перенести во внешние материалы:

1. Постройте учебный маршрут и убедитесь, что он помечен как готовый.
2. Раскройте блок «ЭКСПОРТ УЧЕБНЫХ МАТЕРИАЛОВ».
3. При необходимости введите название материала или колоды.
4. Выберите формат:
   - «ANKI · UTF-8 TSV» — импортируемый Anki текст с полями Front, Back и Tags;
   - «СПРАВОЧНИК · MARKDOWN» — вопросы и ответы по этапам маршрута;
   - «РАСПИСАНИЕ · CSV» — полная таблица для Excel/LibreOffice.
5. Нажмите «ЭКСПОРТ» и сохраните файл средствами браузера.

В Anki выберите «Файл → Импорт», укажите полученный
`mem-learning-anki.txt` и проверьте сопоставление `Front → Front`,
`Back → Back`, `Tags → Tags`. Файл уже содержит UTF-8, табуляцию как разделитель,
HTML-режим, название колоды и колонку тегов. На обороте каждой карточки сохранены
ответ, физическая страница, блок/фрагмент источника, ID объекта и справочное
состояние расписания mem-tool. В начало Front добавлен невидимый стабильный ID:
он не показывается при повторении, но не даёт Anki склеить две разные карточки
с одинаковой формулировкой вопроса.

Важно: обычный текстовый импорт Anki переносит заметки, но не устанавливает
внутреннюю историю и интервалы планировщика Anki. После импорта Anki начинает
собственное расписание. Точные due date, interval, ease, repetitions, lapses,
последняя оценка и число попыток полностью сохраняются в CSV и Markdown, а в
Anki присутствуют как справочный текст. Для настоящего переноса native
scheduling нужен формат `.apkg`; версия 1.55.0 его не создаёт.

Перед формированием каждого файла сервер повторно проверяет selection manifest,
route digest, статусы карточек и актуальность evidence. Изменённый либо
устаревший маршрут отклоняется: постройте его заново. Экспорт не вызывает
нейросеть, не записывает попытки и не изменяет локальное расписание.

Кнопка «ВЫБРАНО: N» открывает модуль анализа. Крестик в нижней панели либо
«ОЧИСТИТЬ» в рабочем модуле снимает весь рабочий выбор. Обычный щелчок и `Esc`
не уничтожают выбранную область: первый открывает другой объект, второй
возвращает к карте или сбрасывает текущий фокус карты.

Это не новый семантический поиск. Сервер закрепляет точные evidence-anchors
выбранных объектов и передаёт модели только их. Если источник изменился,
устарел, исчез, не имеет evidence либо выбранный объект уже отклонён/закрыт,
кнопки блокируются. Если данные изменились между показом панели и отправкой
запроса, сервер отклонит устаревший manifest — обновите выбор или карту.

Операция доступна только через `mem map open`, пока в PowerShell работает её
локальный сервер. В экспортированном автономном HTML можно изучать и выделять
объекты, но нельзя вызывать модель. Для генерации должна быть корректно настроена
секция `answer` в `.mem/config.json`; embedding-модель `bge-m3` для этой операции
не используется как генератор ответа.

### Ширина панелей и цветовая тема

В версии 1.37.0 между левой панелью фильтров, картой и правой панелью сведений
есть узкие вертикальные разделители:

- потяните разделитель мышью влево или вправо, чтобы изменить ширину соседней
  панели;
- выделите разделитель клавишей `Tab` и нажимайте `←`/`→` для точной настройки;
- дважды щёлкните разделитель или нажмите `Home`, чтобы вернуть стандартные
  размеры 280 px слева и 360 px справа;
- центральная область защищена минимальной шириной, поэтому боковые панели не
  могут полностью закрыть карту.

Команда темы в меню «ЕЩЁ» показывает текущий вариант и переключает
«ТЁМНУЮ/СВЕТЛУЮ ТЕМУ».
Выбор темы и обе ширины запоминаются самим браузером и восстанавливаются при
следующем открытии карты. Эти параметры общие для интерфейса данного браузера,
не входят в именованный вид и не изменяют базу, граф или evidence. Если окно уже
1050 px, карта автоматически использует компактный режим: разделители скрыты,
а панели открываются командами «ФИЛЬТРЫ» и «СВЕДЕНИЯ» в меню «ЕЩЁ».

### Тематические кластеры и фокус

Карта автоматически назначает каждому узлу тематический кластер. Основой
кластера служит ближайший документ или связанная опорная тема; если в отдельной
компоненте их нет, используется наиболее связанный узел. Полностью изолированные
узлы собираются в диагностические группы по типу. Это детерминированная навигационная
группировка по уже сохранённому графу — она не создаёт новых фактов и не вызывает
модель.

- кнопка «КЛАСТЕРЫ: ВЫКЛ/ВКЛ» включает цветовые контуры и разносит группы;
- нажмите кластер в левой панели, чтобы показать только его узлы;
- выберите узел и используйте «ФОКУС 1», «ФОКУС 2» или «ФОКУС 3», чтобы оставить
  сам узел и окружение соответствующей глубины;
- «СВЕРНУТЬ ВЕТВЬ» скрывает исходящих потомков по структурным связям
  `contains`, `about`, `derived_from`, `asks`, `answers`, `prerequisite`;
- «ПОКАЗАТЬ ВСЁ» снимает фокус и все сворачивания; `Esc` быстро снимает фокус,
  но сохраняет осознанно свёрнутые ветви.

`FIT` учитывает только текущую видимую область. Поиск и фильтры применяются уже
внутри выбранного фокуса. В автономном HTML эти операции работают до закрытия
вкладки, но ничего не записывают на диск.

Начиная с версии 1.51.1 строка фокуса показывает отдельно количество видимых
узлов и связей: например, `узлов 14 из 1024 · связей 55 из 806`. Связи скрытых
узлов больше не остаются на холсте. Если граф плотный либо сильно уменьшен,
подписи автоматически скрываются: наведите указатель или выберите узел, чтобы
увидеть его сокращённое название; полное название доступно в подсказке и в
инспекторе справа. После выбора посторонние связи приглушаются, а
непосредственные соседи и связи выбранного узла остаются контрастными.

Начиная с версии 1.52.0 выбор тематического кластера автоматически переключает
его с общей force-раскладки на спокойную структуру из смысловых колонок «Тема и
источник», «Опорные знания» и «Аналитика и решения». Узлы сортируются стабильно,
получают рассчитанные интервалы и сразу показывают подписи. Пустой инспектор
закрывается, чтобы освободить холст; щелчок по узлу снова открывает сведения, а
узкая карта переходит в компактный режим и оставляет видимой подпись активного
узла. Кнопка «РАСКЛАДКА» в правом нижнем углу повторно выстраивает кластер после
ручного перемещения. При выходе из фокуса восстанавливаются исходные координаты
и масштаб общей карты: кластерная раскладка не перезаписывает глобальный вид.

Начиная с версии 1.54.0 под строкой поиска находятся два компактных
переключателя:

- «ДЕТАЛИЗАЦИЯ · АВТОМАТИЧЕСКИ» уменьшает визуальный шум по мере отдаления.
  Дальний уровень оставляет опорные узлы крупнейших кластеров, затем появляются
  темы, знания и полный набор деталей. Поиск, фокус, рабочий выбор и окружение
  активного узла не скрываются. Режим «ПОКАЗАТЬ ВСЕ УЗЛЫ» отключает это
  упрощение;
- «ЛИНЗА СВЯЗЕЙ · УМНАЯ» ограничивает число второстепенных рёбер на плотной
  карте и при выборе узла показывает его непосредственные отношения. Другие
  режимы оставляют все связи либо только структуру, логику, проблемы или
  рабочие отношения. Флажки в разделе «Типы связей» продолжают работать как
  точный дополнительный фильтр.

Под переключателями отображается фактический результат: текущий уровень,
сколько узлов и связей осталось на экране и какая линза включена. Навигационная
цепочка показывает `ВСЯ КАРТА → КЛАСТЕР → УЗЕЛ`; нажмите «ВСЯ КАРТА» для сброса
фокуса или название кластера для возврата от узла к кластеру. Эти две настройки
сохраняются вместе с именованным видом и не изменяют знания или evidence.

### Граф, дерево, причинная схема, процедуры, хронология, сравнение и findings

Переключатель представления в верхней панели меняет способ просмотра тех же
данных:

- «ГРАФ» показывает смысловые связи и force-layout;
- «ДЕРЕВО ДОКУМЕНТА» группирует узлы как
  `документ -> физическая страница -> узлы знаний`;
- «ПРИЧИНЫ И СЛЕДСТВИЯ» строит направленную схему по связям «вызывает»,
  «снижает риск», «ограничивает» и «зависит от»;
- «ПОСЛЕДОВАТЕЛЬНОСТЬ» собирает независимые процедуры по направленным связям
  «предшествует» (`precedes`) и раскладывает шаги по этапам сверху вниз;
- «ХРОНОЛОГИЯ» показывает source-узлы `event` по доказуемым временным связям
  «произошло раньше» (`happens_before`);
- «СРАВНЕНИЕ ДОКУМЕНТОВ» строит таблицу по analytics-узлам `comparison`,
  связям `compares` и сохранённым evidence каждого исходного документа;
- «ПРОТИВОРЕЧИЯ И ПРОБЕЛЫ» разделяет findings `contradiction` и `gap`, показывает
  их review-статус, актуальность, охват документами, исходные claims и страницы;
- документ и страницу можно свернуть или развернуть нажатием на их заголовок;
- нажатие на узел дерева открывает справа его описание, все выдержки и кнопку
  перехода к соответствующей странице PDF;
- если один узел подтверждается несколькими страницами или документами, он
  появляется в каждой соответствующей ветви, но остаётся одним объектом графа;
- узлы без сохранённых координат источника явно помещаются в диагностическую
  ветвь «Без привязанного источника».

Поиск работает также по путям документов, номерам страниц и тексту evidence.
Обычные фильтры, фокус и свёрнутые смысловые ветви действуют во всех режимах.
Масштаб, `FIT`, перемещение узлов и кластеры отключены в дереве, причинной схеме
и последовательностях, потому что там используется прокрутка и
детерминированная раскладка, а не координаты force-графа. Если подходящих
направленных связей нет, специализированный режим явно сообщает об этом и не
выдаёт обычную близость узлов за причинность или порядок действий.

В последовательности несколько карточек на одном этапе означают параллельные
или разветвляющиеся шаги; точный переход показан кнопкой вида `2 → 4`. Нажмите
карточку шага либо переход, чтобы справа проверить выдержку, документ и
физическую страницу. Предупреждение о цикле означает, что сохранённые связи
`precedes` замыкаются и порядок последнего этапа нужно проверить по источникам.

Хронология не использует дату импорта записи, номер страницы или порядок чанков
как время события. Независимые цепочки показаны раздельно, события одного
временного уровня не получают вымышленного взаимного порядка, а элементы без
`happens_before` вынесены в блок «События без установленного порядка». Нажатие на
событие или временной переход открывает его evidence. Предупреждение о цикле
означает противоречивые временные связи, которые нужно проверить по источникам.

В матрице сравнения каждая строка — сохранённый аспект сравнения, каждый столбец
— реальный документ из evidence, а заполненная ячейка показывает подтверждённый
аспект или сравниваемый объект, количество связанных объектов и страницы.
Нажмите ячейку, чтобы справа открыть выдержки и точные координаты. Пустая ячейка
означает только отсутствие сохранённого evidence для этого документа и не
доказывает отсутствие свойства. Надпись «междокументный вывод неполон» означает,
что сам аспект подтверждён anchors меньше чем двух документов; его нельзя
считать полноценным сравнением корпуса без дополнительного извлечения.

В режиме «ПРОТИВОРЕЧИЯ И ПРОБЕЛЫ» `draft` означает предложение модели, которое
ещё не проверил человек. `active` означает подтверждённый review-переход, а
`resolved` — закрытый вывод. Нажмите заголовок карточки, чтобы увидеть evidence
самого finding, либо исходное утверждение с именем файла и страницами, чтобы
проверить конкретный фрагмент. Предупреждение о неполном междокументном evidence
означает, что сохранённые anchors сейчас охватывают меньше двух документов.

Чтобы наполнить этот экран, сначала подтвердите исходные claims, затем запустите:

```powershell
mem map analyze "тема для проверки"
mem map open
```

Пустой экран не доказывает, что в корпусе нет противоречий: анализ зависит от
темы, доступных active claims, batch-покрытия и качества извлечения.

В live-режиме выбранное представление сохраняется вместе с основным или
именованным видом. Поэтому можно, например, создать отдельный вид «Документ по
страницам». Переключение в дерево не изменяет сохранённое расположение узлов
графа. В автономном HTML режим можно переключать до закрытия вкладки без записи
в базу.

### Именованные представления

В live-карте «СОХРАНИТЬ КАК» создаёт отдельный вид с текущими координатами,
viewport, фильтрами, кластерным режимом, фокусом, свёрнутыми ветвями и выбранным
режимом «граф/дерево/причинная схема/последовательность/хронология/сравнение».
Список в
верхней панели переключает виды. У именованного вида кнопка «УДАЛИТЬ ВИД» удаляет
только это визуальное представление и возвращает основной вид. Последний выбор
запоминается в браузере и восстанавливается при следующем `mem map open`.

Названия могут быть человекочитаемыми, например «Композиция — определения» или
«Противоречия главы 3». Не включайте в название секреты: оно хранится в активной
локальной SQLite-базе. Создание, перезапись и удаление вида защищены тем же
одноразовым session token и same-origin-проверкой, что и остальные live-действия.

### Семантические слои и связи

Начиная с 1.35.0 узлы карты разделены на понятные слои, а в 1.36.0 рабочий слой
расширен:

- источник: документ, раздел, тема, определение, утверждение, формула, пример,
  процедура, событие;
- аналитика: сравнение, противоречие, пробел, зависимость, причина, следствие,
  риск, ограничение;
- рабочий слой: заметка, вопрос, карточка, гипотеза, решение и задача.

`mem map build` и `mem map extract` создают только source- и analytics-объекты.
Все рабочие объекты появляются исключительно после вашего действия в live-карте,
поэтому текст модели не смешивается с пользовательской работой. Для связей
доступны, в частности, понятные направления «определяет», «иллюстрирует
примером», «зависит от», «вызывает», «снижает риск», «ограничивает» и
«предшествует».

В фильтрах слева типы и связи показаны по-русски. При выборе узла справа отдельно
видны четыре независимых признака: уверенность извлечения, покрытие источниками,
актуальность evidence и состояние проверки. Ни один из них сам по себе не
означает, что утверждение истинно; окончательное подтверждение остаётся за вами.

Старые сохранённые виды v1/v2/v3 открываются автоматически. Новые типы при первом
открытии старого вида включены, чтобы ранее сохранённый фильтр не скрыл свежие
результаты. Следующее сохранение записывает совместимый формат v4.

### Ручные рабочие объекты

В `mem map open` выберите исходный узел. Если его evidence актуален, справа
появится блок «РАБОЧИЙ СЛОЙ»:

1. выберите «Заметка», «Вопрос», «Карточка», «Гипотеза», «Решение» или «Задача»;
2. введите понятное название или формулировку;
3. при необходимости добавьте подробный текст и комментарий;
4. укажите автора и нажмите «СОЗДАТЬ И ПРИВЯЗАТЬ».

После обновления появится новый ручной узел. Тип связи выбирается автоматически:

- заметка или карточка — `derived_from` («получено из»);
- вопрос — `asks` («задаёт вопрос к»);
- гипотеза — `hypothesizes_about` («выдвигает гипотезу о»);
- решение — `based_on` («решение основано на»);
- задача — `acts_on` («задача относится к»).

Все объекты создаются со статусом `draft`: это рабочая мысль пользователя, а не
автоматически подтверждённый факт. Её можно проверить обычным блоком
«ПРОВЕРКА ОБЪЕКТА».

Программа автоматически копирует точные evidence-anchors выбранного узла, то
есть путь документа, физическую страницу, блок, чанк, ревизию и выдержку. Эти
данные не требуется вводить или копировать вручную. Если источник либо сам узел
изменился после открытия формы, запись не выполняется; обновите карту, заново
проверьте источник и повторите действие.

У созданного объекта правая панель показывает автора, время, комментарий и
понятное название исходного узла. Технические ID и digests находятся только в
сворачиваемой диагностической секции. История создания append-only: приложение
не переписывает и не удаляет её задним числом. Автономный `map export-html`
показывает уже созданные рабочие объекты, но не позволяет создавать новые.

Чтобы проверить источник, выберите узел или связь и найдите нужный evidence-блок
в правой панели. Для актуального PDF с известной страницей появится кнопка
«ОТКРЫТЬ PDF · СТР. N». Она открывает новую вкладку на соответствующей физической
странице. Если evidence устарел или отсутствует, переход блокируется: сначала
повторно импортируйте изменившийся документ и обновите карту. Для форматов без
физической PDF-страницы кнопка не показывается.

Чтобы принять решение по найденному знанию, выберите узел или связь. При актуальном
evidence блок «ПРОВЕРКА ОБЪЕКТА» показывает имя проверяющего, комментарий/причину
и доступные для текущего состояния кнопки:

- `draft` → «ПОДТВЕРДИТЬ» или «ОТКЛОНИТЬ»;
- `rejected` → «ВЕРНУТЬ В РАБОТУ»;
- `active` → «ОТМЕНИТЬ ПОДТВЕРЖДЕНИЕ», если оно остаётся последним решением;
- `draft` после возврата → «ОТМЕНИТЬ ВОЗВРАТ».

Причина отклонения обязательна. Внутренний ID, digest и номер audit-записи
копировать не нужно: карта закрепляет их автоматически. Для подтверждения связи
сначала подтвердите оба связанных узла. Подтверждение узла нельзя отменить, пока
от него идут активные связи — сначала отмените подтверждение этих связей. Статус
`resolved` означает закрытие другой операцией (например, merge), а не отклонение.
Имя проверяющего запоминается только локально в браузере; оно является заявленной
подписью, а не проверенной учётной записью.

Если проверяемая редакция объекта или evidence изменились после открытия
страницы, решение отклоняется без частичной записи. Для undo дополнительно
проверяется последняя запись audit-истории. Нажмите «ОБНОВИТЬ», снова изучите
выдержки и повторите действие. Отклонение, возврат и undo добавляют новые
append-only записи, не переписывая прежние. Полную историю показывает
`mem map reviews`.

Чтобы исправить формулировку, в том же окне выберите блок «РЕДАКТИРОВАНИЕ»:

- для узла доступны название и описание;
- для связи доступно название (отдельного описания у связи нет);
- укажите автора правки и при необходимости комментарий;
- нажмите «СОХРАНИТЬ ПРАВКУ»;
- «ОТМЕНИТЬ ПОСЛЕДНЮЮ ПРАВКУ» вернёт предыдущий текст и статус, если объект,
  история и evidence с момента сохранения не изменились.

Правка `active` или `rejected` всегда переводит объект в `draft`, чтобы новое
содержание прошло проверку заново. Активный узел с active-связями изменить нельзя:
сначала отмените подтверждение соответствующих связей. Внутренние ID и digest
интерфейс подставляет сам. Повторное generated-извлечение не перезапишет активную
ручную правку; после явной отмены будущая генерация снова сможет обновлять текст.
Полный журнал доступен командой `mem map edits`.

Представления хранятся в активной локальной базе и восстанавливаются при следующем
`map open`. Live-сервер доступен только через `127.0.0.1`; сохранение вида и
review-действия защищены одноразовым токеном текущего запуска,
same-origin/Origin-проверкой, evidence/review pins и ограниченными JSON-контрактами.
Редактирование названий и описаний защищено теми же условиями и дополнительными
content/status/edit pins. Исходный текст документа и импортированные chunks этим
интерфейсом не изменяются. Запускайте `map open` из PowerShell: TUI сообщает об
этом явно, поскольку сервер должен владеть терминальной сессией до `Ctrl+C`.

Live-сервер никогда не принимает путь из браузера. Он разрешает citation ID через
актуальный граф и отдаёт только привязанный к нему PDF. Сессионная cookie имеет
`HttpOnly` и `SameSite=Strict` и перестаёт действовать после закрытия процесса.
В автономном `export-html` локальные PDF намеренно не открываются.

Построить начальный граф по найденным фрагментам:

```powershell
mem map build "архитектура импорта" -limit 10
```

Проверить, насколько карта покрывает сохранённый исходный материал:

```powershell
mem map coverage
mem map coverage --document "D:\Books\manual.pdf"
mem map coverage --document "D:\Books\manual.pdf" --pages 20-45
mem map coverage --tag "Радиотехника"
mem map coverage --json
```

Команда ничего не отправляет модели и не изменяет базу. Graph coverage считает
текущие versioned chunks и засчитывает chunk, если текущий узел или связь карты
ссылается на его точную ревизию. Import coverage отдельно использует манифест
1.30.0+ и считает все его физические страницы, включая пустые и не создавшие
chunk. Поэтому запрос диапазона из одной пустой страницы теперь возвращает
документ, статус страницы и причину, а не нулевой «исчезнувший» результат.

В отчёте также указаны полностью, частично и совсем не покрытые текстовые
страницы, слабый OCR, предупреждения, объекты `draft/active/rejected/resolved` и
устаревшие/исчезнувшие evidence. Для старых ревизий без манифеста выводится явное
ограничение и рекомендация повторного импорта. JSON содержит стабильный
`snapshot_digest`, учитывающий и выбранные chunks, и статусы физических страниц.

Зафиксировать воспроизводимый quality gate для этого отчёта можно строгим
JSON-манифестом. Например, `quality-baseline.json`:

```json
{
  "schema_version": 1,
  "name": "SP10 — базовая проверка",
  "scope": {
    "document": "E:\\temp\\mem-test4\\SP10.pdf",
    "page_from": 1,
    "page_to": 129,
    "low_confidence_threshold": 65
  },
  "requirements": {
    "min_import_coverage_percent": 100,
    "min_processing_percent": 100,
    "min_knowledge_coverage_percent": 80,
    "max_unprocessed_chunks": 0,
    "max_uncovered_chunks": 30,
    "max_low_confidence_ocr_chunks": 5,
    "max_warning_chunks": 5,
    "min_extracted_nodes": 20,
    "min_extracted_relations": 10,
    "max_draft_objects": 100,
    "max_stale_evidence_objects": 0,
    "max_missing_evidence_objects": 0
  }
}
```

Запуск:

```powershell
mem map eval .\quality-baseline.json
mem map eval .\quality-baseline.json --json
```

Каждое поле `requirements` необязательно, но должен присутствовать хотя бы один
порог. Проценты находятся в диапазоне 0–100, счётчики не могут быть
отрицательными. Значение `0` является настоящим строгим порогом, а не
«отключением». Если проверка не пройдена, mem показывает все `[OK]`/`[FAIL]`,
возвращает код процесса 1 и не меняет базу. JSON также печатается полностью до
ненулевого завершения, поэтому отчёт можно сохранить и разобрать автоматически.
`manifest_digest` закрепляет нормализованные правила, `snapshot_digest` —
фактический coverage-снимок. Сравнивать результаты нужно только при совпадающем
manifest digest.

### Размеченная оценка precision/recall

Coverage отвечает на вопрос «сколько материала обработано», но не доказывает,
что claims извлечены правильно и что найденные противоречия действительно
существуют. Для проверки качества на небольшом вручную размеченном наборе
используйте отдельный manifest, например `labeled-benchmark.json`:

```json
{
  "schema_version": 1,
  "name": "SP10 — давление и температура",
  "scope": {
    "document": "E:\\temp\\mem-test4\\SP10.pdf",
    "page_from": 10,
    "page_to": 30,
    "tag": "АУП"
  },
  "matching": {
    "claim_similarity_threshold": 0.8,
    "statuses": ["active", "draft"]
  },
  "claims": [
    {
      "id": "working-pressure",
      "text": "Рабочее давление установки равно 10 бар",
      "aliases": ["Рабочее давление составляет 10 бар"]
    },
    {
      "id": "pressure-limit",
      "text": "Рабочее давление не должно превышать 8 бар",
      "node_id": "claim-pressure-limit",
      "accepted_citation_ids": [
        "cite-0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef-p22-b3-c1"
      ]
    },
    {
      "id": "temperature-limit",
      "text": "Расчётная температура равна 40 градусам"
    }
  ],
  "contradictions": [
    {
      "id": "pressure-conflict",
      "left_claim_id": "working-pressure",
      "right_claim_id": "pressure-limit"
    }
  ],
  "requirements": {
    "min_claim_precision": 90,
    "min_claim_recall": 85,
    "min_claim_f1": 87,
    "min_contradiction_precision": 100,
    "min_contradiction_recall": 90,
    "min_contradiction_f1": 94,
    "max_false_positive_claims": 2,
    "max_false_negative_claims": 3,
    "max_false_positive_contradictions": 0,
    "max_false_negative_contradictions": 1
  }
}
```

`node_id` и `accepted_citation_ids` необязательны. Добавляйте их, когда эталон
должен проверять конкретный объект либо конкретный фрагмент источника. Реальные
значения можно взять из `mem map export` или JSON-отчёта карты. Не копируйте
примерные значения из документации: они служат только для показа формата.

Запуск:

```powershell
mem map eval-labeled .\labeled-benchmark.json
mem map eval-labeled .\labeled-benchmark.json --json
```

Как работает сопоставление claims:

1. В выбранной области берутся только узлы `claim` с перечисленными статусами и
   хотя бы одним current evidence. По умолчанию статусы — `active` и `draft`.
2. Текст эталона и aliases сравниваются с label, body и их объединением у узла.
   Алгоритм — регистронезависимый token Dice по буквенно-цифровым словам. Он
   детерминирован, не вызывает embeddings и не зависит от выбранной AI-модели.
3. Порог по умолчанию равен `0.8`. Для разных формулировок лучше добавить
   проверенный alias, а не чрезмерно снижать порог.
4. Один узел может закрыть только один эталонный claim, и наоборот. Если задан
   `node_id`, подходит только этот узел. Если заданы `accepted_citation_ids`, у
   узла должен быть хотя бы один такой current источник в выбранной области.

Связь `contradicts` считается true positive только тогда, когда оба её конца уже
сопоставлены с указанной парой эталонных claims. Направление пары не важно.
Повторная связь для уже закрытой пары является false positive. Analytics-узел
`contradiction` сам по себе не засчитывается: метрика проверяет именно явное
отношение между claims.

Отчёт показывает:

- `TP` — правильно найденные объекты;
- `FP` — лишние claims или противоречия;
- `FN` — пропущенные элементы эталона;
- `precision = TP / (TP + FP)` — долю правильных среди найденных;
- `recall = TP / (TP + FN)` — долю найденных среди ожидаемых;
- `F1` — гармоническое среднее precision и recall.

Если предсказаний нет, precision принимается равной 100% (нет FP); если в
эталоне нет объектов, recall принимается равной 100% (нет FN). При пропущенном
непустом эталоне recall и F1 всё равно становятся нулевыми. Human-отчёт
перечисляет FP/FN и для найденных объектов показывает файл и страницу. JSON
дополнительно содержит matches, текущие evidence, `manifest_digest`, `graph_digest`,
`evidence_state_digest` и `snapshot_digest`.

Manifest ограничен 8 MiB и 2000 claims / 5000 contradictions. Неизвестные поля,
дубли ID и пар, неизвестные ссылки, неверные citation ID, лишний JSON и
некорректные пороги отклоняются до оценки. Команда read-only, не вызывает модель
и не изменяет статусы карты. Непройденный gate печатает полный отчёт, затем
возвращает код процесса 1 — это подходит для PowerShell и CI.

### Профиль SQLite и генерации live-карты

Чтобы измерить, где именно тратится время при открытии большой knowledge map,
выполните:

```powershell
mem map profile
mem map profile -iterations 5
mem map profile -iterations 5 --view "основной" --json
```

По умолчанию выполняются три итерации, допустимо от 1 до 20. `--view` выбирает
сохранённое представление; без него измеряется основной вид. Команда последовательно
профилирует четыре стадии:

- `sqlite_graph_load` — чтение узлов, связей и их evidence из SQLite;
- `pinned_evidence_snapshot` — повторное чтение графа и разрешение каждого
  evidence как current/stale/missing;
- `live_view_assembly` — сборка полного payload живой карты: review, edits,
  revision diff, layout, выбранный view и portable-export pin;
- `html_serialization` — JSON-сериализация payload и запись встроенных HTML/CSS/JS
  без запуска браузера.

Human-отчёт показывает median и p95, а также min/max. JSON содержит исходные
`samples_ns` и mean для собственного анализа. Дополнительно фиксируются:

- абсолютный путь и размеры `store.db`, `store.db-wal`, `store.db-shm`;
- SQLite page count, page size, freelist, journal mode и `data_version`;
- число entries, документов, узлов, связей и current/stale/missing evidence;
- размер и digest полученного HTML;
- GOOS, GOARCH, версия Go и число логических CPU;
- graph, evidence-state и нормализованный view digest.

Перед измерением mem строит content/state pin. Каждая итерация сверяется с ним,
а view дополнительно сравнивается без полей текущего времени. Если другой процесс
изменил граф, evidence, review или layout во время серии, команда завершится
ошибкой `knowledge map changed during profile`, а смешанные timings не будут
выданы как корректный результат. База остаётся неизменной, модель не вызывается.

Это профиль **прогретого host-side пути**: предварительный pin уже прочитал
часть страниц SQLite. Команда не измеряет запуск процесса, браузерный JavaScript,
layout, paint, GPU, FPS и задержку кликов. Поэтому сравнивайте результаты только:

1. на одном компьютере и накопителе;
2. с одинаковым числом итераций и view;
3. при совпадающих graph/evidence/view digests;
4. без тяжёлой параллельной нагрузки.

На пустой базе очень быстрая стадия может получить sample `0 ns`: это означает,
что операция оказалась быстрее разрешения monotonic timer ОС, а не то, что работа
не выполнялась. Оценивать производительность следует на содержательной карте и
по серии итераций, а пустую базу использовать только как smoke-test команды.

Сначала снимите baseline, затем повторите ту же команду после оптимизации. Если
`sqlite_graph_load` мал, но `live_view_assembly` велик, оптимизировать нужно
агрегацию review/diff/layout, а не SQLite. Если велик `html_serialization`,
смотрите объём payload и `html_bytes`. Медленный браузер при быстрых четырёх
стадиях означает отдельную проблему client-side layout/paint, которую этот
отчёт честно не покрывает.

Начиная с 1.68.1 загрузка графа использует постоянные четыре SQL-запроса:
узлы, связи, evidence узлов и evidence связей. Разрешение источников объединяет
одинаковые document/page/block/chunk coordinates и читает уникальные позиции
пакетами до 200. Review и live-view используют один закреплённый SQLite-снимок,
поэтому повторяющиеся ссылки на один chunk больше не создают тысячи одинаковых
обращений к базе. Для проверки эффекта сравнивайте собственные отчёты 1.68.0 и
1.68.1 с одинаковыми `iterations`, `view`, graph digest и evidence-state digest;
чужие миллисекунды не являются гарантией для другого компьютера или корпуса.

Сравнить сохранённые выдержки карты с текущей ревизией базы:

```powershell
mem map diff
mem map diff --document "D:\Books\manual.pdf"
mem map diff --document "D:\Books\manual.pdf" --json
```

Команда не вызывает модель и не меняет базу. Она показывает документы, в которых
точные coordinates evidence остались актуальными, изменились (`stale`) либо
исчезли (`missing`), а также перечисляет затронутые узлы и связи. В `mem map open`
тот же отчёт находится на отдельной вкладке «ИЗМЕНЕНИЯ»: раскройте документ,
чтобы увидеть прежнюю выдержку рядом с текущим chunk, затем нажмите название
объекта для открытия полного инспектора.

Начиная с 1.57.0 перед заменой ревизии mem атомарно сохраняет полный неизменяемый
снимок прежних chunks и одновременный снимок карты. Поэтому после первого
повторного импорта изменённого документа `mem map diff` дополняется полными
счётчиками корпуса. До этого момента он честно остаётся evidence-diff.

Посмотреть накопленные снимки:

```powershell
mem map snapshots
mem map snapshots --document "D:\Books\manual.pdf"
mem map snapshots --json
```

Сравнить весь старый набор chunks с текущей или другой сохранённой ревизией:

```powershell
mem map corpus-diff --document "D:\Books\manual.pdf"
mem map corpus-diff --document "D:\Books\manual.pdf" --from "dhs-..." --to current
mem map corpus-diff --document "D:\Books\manual.pdf" --json
```

Каждый снимок имеет собственный ID вида `dhs-...`; его печатает `map snapshots`.
Снимок создаётся при фактической смене полного состояния документа, в том числе
когда `document_revision` совпадает, но изменились границы chunks. Идентичный
повторный импорт место не расходует. Пустой после переиндексации документ тоже
сохраняется как точное empty-состояние и может быть восстановлен. История
содержит полный текст и векторы, поэтому размер `store.db` закономерно растёт на
объём заменённых состояний. Таблицы защищены от UPDATE/DELETE. Для точного diff
и восстановления используйте `dhs-...`. Старый selector `sha256:...` оставлен
для совместимости и выбирает самый новый снимок с этой content-revision.

Восстановление выполняется только через обязательный preview и отдельное
подтверждение точного состояния.

Предварительно посмотреть восстановление старой ревизии:

```powershell
mem map restore --document "D:\Books\manual.pdf" --revision "dhs-..."
```

Эта команда ничего не меняет. Она показывает, сколько chunks, узлов и связей
будет заменено, и печатает готовую команду с `--confirm sha256:...`. Восстановление
касается выбранного документа и **всей карты**, зафиксированной одновременно с
этой ревизией. Поэтому обязательно проверьте числа карты и предупреждение.

Если состояние не изменилось после preview, примените напечатанную команду:

```powershell
mem map restore --document "D:\Books\manual.pdf" `
  --revision "dhs-..." `
  --confirm "sha256:..."
```

Нельзя подставлять произвольный digest или использовать старый preview после
редактирования карты/повторного импорта: mem отклонит операцию. Восстановление
выполняется одной SQLite-транзакцией и перед изменением создаёт recovery point.

После успеха программа напечатает ID вида `restore-run-...`. Для отката также
обязательны два шага:

```powershell
mem map restore --rollback "restore-run-..."
mem map restore --rollback "restore-run-..." --confirm "sha256:..."
```

Первый вызов — только preview; второй использует digest именно этого preview.
Посмотреть append-only журнал операций:

```powershell
mem map restore-runs
mem map restore-runs --json -limit 50
```

Восстанавливаются exact chunks с текстом, векторами и provenance, а также exact
knowledge graph. Журналы review/edit/learning/import и визуальные виды не
удаляются. Модель и embedding API при preview, restore и rollback не вызываются.

Запланировать полный контролируемый разбор без запуска модели:

```powershell
mem map extract "полный разбор документа" --document "D:\Books\manual.pdf" --dry-run
```

Запустить ограниченную порцию пакетов:

```powershell
mem map extract "полный разбор документа" --document "D:\Books\manual.pdf" -batches 16
```

Команда обходит chunks в стабильном порядке document/page/block/chunk и передаёт
модели каждый chunk целиком. Если полный chunk не помещается, команда завершается
с предложением увеличить `-context-chars` или переимпортировать документ с меньшим
размером chunk; скрытого усечения нет. Job-prompt требует просмотреть каждый
evidence-фрагмент, а не выбирать только наиболее похожие на фокус.

Каждый валидный пакет немедленно становится checkpoint. При ошибке скопируйте
напечатанный `ker-...` и продолжите задание; исходные параметры можно не повторять,
но фокус должен совпадать:

```powershell
mem map extract "полный разбор документа" -resume ker-0123456789abcdef0123456789abcdef
mem map extract-runs
mem map extract-run ker-0123456789abcdef0123456789abcdef
```

Если модель остановила строгий JSON ровно на output-limit, версия 1.43.1 сама
повторит только текущий пакет: сначала с 8192, затем при необходимости с 16384
токенами. В журнале появится строка `повтор ... с компактным JSON`. Значение
`answer.max_tokens` в `config.json` при этом не меняется, а уже готовые пакеты не
обрабатываются заново. Если обе попытки исчерпаны, run остаётся доступным для
`-resume`; частичный JSON в карту не записывается.

Версия 1.43.2 также повторяет текущий пакет, если JSON завершён, но логически
некорректен — например, edge содержит `from`/`to`, которого нет среди node refs.
В журнале это обозначается как `JSON отклонён строгой проверкой` и
`исправляющий повтор 1/2`.

Начиная с 1.43.3, после двух неудачных исправлений пакет из нескольких фрагментов
не останавливает весь run: он автоматически делится пополам. Если меньший пакет
снова нестабилен, деление продолжается вплоть до одного evidence fragment. В
журнале появляются строки `делю на подпакеты`, `подпакет ...` и `подпакеты
объединены`. Каждый подпакет проверяется fail-closed; неверные refs, citations,
типы или provenance не принимаются, а уже готовые checkpoints не пересчитываются.
Если строгую схему не смог пройти даже одиночный фрагмент, run сохраняется для
следующего `-resume` и сообщает точную ошибку.

Карта обновляется только после завершения всех пакетов текущего run. Результаты
имеют статус `draft`. Затем ledger отмечает точные ревизии chunks как обработанные.
Повтор исходной команды берёт следующий остаток, если `-batches` ограничил первый
запуск. Изменённые после переимпорта chunks получают новую identity и обрабатываются
заново. `map coverage` показывает две разные величины:

- «обработано заданием» — chunk полностью предъявлялся модели;
- «покрыто картой» — хотя бы один текущий узел или связь реально цитирует chunk.

Обработанный, но не процитированный chunk не объявляется содержательно покрытым.
Такой результат означает только завершённый проход модели, а не доказательство,
что из фрагмента извлечён каждый возможный факт.

Найти противоречия и пробелы при помощи локальной answer-модели:

```powershell
mem map analyze "требования к рабочему давлению" -batches 8
mem map runs
mem map status
```

Продолжить незавершённый запуск:

```powershell
mem map analyze "требования к рабочему давлению" -batches 8 -resume <run-id>
```

Сгенерированные узлы сначала имеют статус `draft`. Перед подтверждением изучите
формулировку и evidence. В `map status --json` поле `evidence_digest` фиксирует
цитаты, а `review_digest` — проверяемую редакцию самого объекта, включая тип и
концы связи. Чтобы подтвердить именно просмотренный вариант, передайте оба:

```powershell
mem map status --json
mem map approve node <node-id> --reviewer "Руслан" --evidence-digest <evidence_digest> --review-digest <review_digest>
mem map reviews
mem map edits
```

Если объект изменён после просмотра, старый `review_digest` не подходит:
повторно откройте состояние, проверьте текст и только затем подтвердите его.
Веб-интерфейс передаёт эту привязку автоматически. Старую открытую страницу
редактора после обновления программы нужно перезагрузить.
Повторная генерация с изменившейся формулировкой или структурой также возвращает
ранее проверенный объект в черновик. Действующие ручные правки сохраняются;
неизменившийся результат не теряет подтверждения.

Одиночная CLI-команда без `--review-digest` остаётся прямым подтверждением
текущей редакции по ID; она не удостоверяет совпадение с ранее просмотренным
снимком. Для отложенной проверки используйте явный digest.

В JSON для `mem map approve-batch` каждый объект теперь должен содержать
`expected_evidence_digest` и `expected_review_digest`, взятые из проверенного
`map status --json`. Старые batch-планы без привязки к формулировке отклоняются:
получите новый статус и сформируйте план повторно. В новых записях `map reviews`
сохраняется `review_digest`; отсутствие этого поля у исторической записи
означает, что она была сделана без новой гарантии.

Поиск семантических дублей ничего не объединяет автоматически:

```powershell
mem map duplicates --json -kind claim -threshold 0.92
mem map merge-node .\merge-node.json
mem map merges
```

Экспортировать **всю расширенную карту знаний** в переносимый файл:

```powershell
mem map export --format markdown --output .\knowledge-map.md --title "Карта проекта"
mem map export --format outline --output .\knowledge-map.txt
mem map export --format opml --output .\knowledge-map.opml
mem map export --format graphml --output .\knowledge-map.graphml
mem map export --format gexf --output .\knowledge-map.gexf
mem map export --format mermaid --output .\knowledge-map.mmd
mem map export --format obsidian --output .\knowledge-map.obsidian.md
```

Назначение форматов:

- `markdown` — полный читаемый справочник по слоям с текстами, связями и
  координатами источников;
- `outline` — простой UTF-8 план для чтения и обработки скриптами;
- `opml` — переносимый список узлов и связей для outline-приложений;
- `graphml` — полноценный направленный граф для yEd, Gephi и библиотек;
- `gexf` — полноценный направленный граф для Gephi и сетевого анализа;
- `mermaid` — `flowchart LR` для Markdown-документации;
- `obsidian` — одна заметка с front matter, Mermaid-схемой, секциями узлов,
  block ID и читаемыми источниками.

Каждый формат содержит полный canonical provenance: узлы, связи, исходные
anchors и вычисленное состояние `current/stale/missing`. Экспортируется весь
граф независимо от фильтров, свёрнутых кластеров и текущего выбора. Изменение
графа или источника между открытием live-страницы и скачиванием блокирует
операцию: обновите страницу и повторите её. `stale`/`missing` источники
сохраняются в файле как предупреждение, но не считаются актуальным
подтверждением.

Безопасные пределы одного полного экспорта: до 10 000 узлов, 100 000 связей
и 128 MiB готового файла. При превышении операция завершается ошибкой до записи
назначения; существующий файл остаётся нетронутым. Для более крупного корпуса
разделите карту по документам или тематическим областям и экспортируйте части
отдельно.

По умолчанию существующий файл не меняется. Для осознанной атомарной замены:

```powershell
mem map export --format graphml --output .\knowledge-map.graphml --force
```

Старое `mem map export` без дополнительных флагов совместимо с прежними
скриптами и выводит сырой JSON графа в stdout. В live-интерфейсе полный экспорт
находится в `ЕЩЁ → ЭКСПОРТ КАРТЫ`. Экспорт только выбранной области остаётся в
рабочем пространстве `АНАЛИЗ` и создаёт отчёт, план, checklist, CSV или
переносимую JSON-ветвь.

Начиная с 1.69.0 live-экспорт выполняется как ограниченная фоновая job. После
кнопки `СОЗДАТЬ ФАЙЛ` диалог показывает позицию в очереди, фазу, процент и
статистику проверки источников; когда файл готов, браузер автоматически
предлагает его сохранить. На один `mem map open` работает один worker и ждут не
более четырёх заданий. Если очередь заполнена, дождитесь текущего экспорта —
программа не создаёт неограниченную параллельную нагрузку.

Во время работы кнопка меняется на `ОТМЕНИТЬ`. Ожидающее задание удаляется из
очереди сразу; активное останавливается на ближайшей безопасной границе фазы.
Закрыть диалог, не решив судьбу активной job, нельзя: это защищает от незаметно
оставленной тяжёлой операции. `Ctrl+C` в терминале останавливает live-server и
отменяет все его незавершённые экспорты. Частичные файлы не скачиваются.

Готовый файл хранится в памяти только до успешной передачи браузеру; забытый
результат удаляется через 10 минут. Общий лимит удерживаемых артефактов —
128 MiB. Job и скачивание защищены тем же loopback/same-origin/session-token
контрактом, а content/state digest повторно проверяются внутри worker. Поэтому
обновившуюся карту нужно сначала перезагрузить, затем запустить экспорт заново.
CLI-команды экспорта остаются синхронными и работают как прежде.

Создать автономную интерактивную карту:

```powershell
mem map export-html .\knowledge-map.html --title "Карта проекта"
```

Откройте HTML обычным браузером. Доступны поиск, фильтры, pan, zoom, `FIT`,
перетаскивание узлов и карточки точных источников. В файл включается последняя
сохранённая раскладка, но сам файл является read-only
снимком; после approve, merge или нового анализа экспортируйте его повторно с
`--force`. HTML содержит выдержки и локальные пути, поэтому может быть
чувствительным.

После обновления mem-tool старый HTML не получает исправления автоматически:
пересоздайте его командой `map export-html ... --force`. Обычный клик по узлу
или связи открывает справа описание и evidence; drag продолжает перемещать узел.

## 7. Семантический каталог файлов

`mem-index` хранит отдельную базу `.fileindex` и индексирует имена, пути и
аннотации файлов, а не записи `.mem`. Сначала один раз выполните `init`; остальные
команды требуют уже полностью инициализированные обычные файлы
`.fileindex/config.json`, `.fileindex/meta.json` и `.fileindex/store.db` и не
создают пустую БД из частичного состояния:

```powershell
mem-index init D:\Books
mem-index enrich D:\Books
mem-index find "книга про роботов" -limit 10
mem-index list -limit 20
mem-index show 42
mem-index stats
```

После добавления, удаления, перемещения файлов или смены embedding-модели:

```powershell
mem-index scan D:\Books -enrich
```

Обычный `scan` при изменении файла убирает прежний вектор из поиска и сохраняет
необходимость обновления аннотации. `scan -embed` затем повторно извлечёт
устаревшую аннотацию и построит вектор; этот признак сохраняется между запусками.
После ошибки извлечения/embedding исправьте её причину и повторите `scan -embed`.

Для полного обновления аннотаций и векторов, включая записи, затронутые ошибкой
версии 1.70.3, явно включите оба флага:

```powershell
mem-index scan D:\Books -enrich -embed
```

## 8. Telegram-бот

Команда бота `/import` показывает способ импорта через локальный CLI.
Приём и индексация файлов, присланных в Telegram, пока не реализованы.

Боту нужны токен, каталог данных и явный список разрешённых Telegram user ID:

```powershell
$env:TELEGRAM_BOT_TOKEN = "токен от BotFather"
$env:MEM_BOT_DATA_DIR = "$env:USERPROFILE\mem-bot-data"
$env:MEM_BOT_ALLOWED_USER_IDS = "123456789"
mem-bot
```

Пустой allowlist по умолчанию блокирует запуск. Публичный режим допустим только
для личных чатов и включается явно через `MEM_BOT_ALLOW_PUBLIC=true`; одновременно
должны быть положительными `MEM_BOT_RATE_LIMIT_PER_MINUTE`,
`MEM_BOT_GLOBAL_RATE_LIMIT_PER_MINUTE`, `MEM_BOT_MAX_ENTRIES_PER_USER` и
`MEM_BOT_MAX_USERS`. Их безопасные значения по умолчанию: 30, 120, 10000 и 100.
Allowlist и публичный режим одновременно не используются.

Бот одновременно допускает не более двух долгих embedding-запросов и не более
одного такого запроса от одного пользователя. При насыщении он сразу просит
повторить позже, оставляя workers для `/start`, `/help`, `/recent` и `/stats`.
Если личная база уже открывается либо занята другая операция создания базы,
ожидание также не занимает worker: пользователь получает просьбу повторить
запрос. Квота записей читается непосредственно из SQLite; при ошибке чтения
новая запись не выполняется.
Ответ без Markdown повторяется только если Telegram явно вернул HTTP 400 с
ошибкой разбора entities; 429, отмена, тайм-аут и сетевые ошибки автоматически
не дублируются.

Не записывайте токен в Git. В репозитории есть безопасный пример
`.env.local.example` и локальный launcher `run-bot.ps1`.

### Веб-редактор карт — 1.71.0-alpha.17

Запуск остаётся прежним: `mem --dir <папка-базы> gui`. В разделе «Карты»
выберите карту, затем узел и откройте панель текста.

- «Переместить ветвь»: выберите нового родителя и позицию; пустая позиция — в конец.
- «Удалить узел»: удалить всю ветвь либо оставить детей и поднять их к родителю.
- «Свойства узла»: тип и защита от правок. Защиту можно снять в той же форме.
- «Источники узла»: фрагменты документов без вызова модели, веб-ссылки,
  сохранённые цитаты, порядок и удаление привязок. Статус ссылки не означает,
  что сайт скачан или проверен. Локальные файлы пока открываются в прежнем редакторе.
- «О карте»: название, описание, готовность/архив. Архив не удаляет карту.
- «Снимки»: именованные состояния карты внутри базы. Это не копия оригиналов.
- «Скачать»: полная карта во всех восьми форматах CLI, включая свёрнутые узлы.

Правки можно отменить/вернуть через историю. При сбое связи повторите ту же
отправку; при конфликте обновите карту и откройте форму заново. Пределы редактора
сохраняются: 1000 узлов, 2000 источников, глубина 256, 4 МиБ данных карты,
64 МиБ истории, 64 МиБ снимков. С 1.72.0-alpha.1 предел квитанций редактирования
составляет 100000 записей и 16 МиБ; прежние ключи повторных запросов сохраняются.

Настройка будущего VDS, остановленное резервное копирование и проверка восстановления
описаны в [deploy/WEB_SERVER_RU.md](deploy/WEB_SERVER_RU.md). Скрипты не устанавливают
сервис автоматически и не переносят локальные пути на другую ОС.


### Работа с ветвью и пересчёт векторов — alpha.18

В общем редакторе выберите узел и нажмите «Изучить ветвь / Задать вопрос».
Карточки используют текст узлов и названия подтем. Можно показать ответ,
перейти к узлу и скачать весь набор в Markdown. С 1.72.0-alpha.1 учебные попытки,
самооценки и расписание сохраняются в базе; подробности в начале инструкции.
Вопрос по ветви
использует актуальные фрагменты прикреплённых документов; сначала
добавьте их через «Источники узла». Веб-ссылки сами по себе контекстом не служат.
Кнопка «Сравнить» показывает различия с другой картой той же базы.

В «Настройках базы → Проверка настроек» можно проверить сохранённую модель
или вставить пример текста для предпросмотра разбиения. Проверка модели делает
короткий запрос к настроенному подключению; документы в него не включаются.

Для пересчёта векторов сохраните нужную модель поиска и нажмите
«Подготовить новые векторы». Старые векторы работают до применения нового
поколения. После готовности нажмите «Применить готовые векторы».
«Вернуть прежние векторы» доступно, пока после применения записи базы
не изменялись. Возврат не переключает модель в настройках. Новый запуск
заменяет сохранённое предыдущее поколение. Не меняйте документы и настройки
во время подготовки: такое изменение делает результат неприменимым.

Пересчёт не меняет границы фрагментов. Для нового разбиения загрузите новую
редакцию документа. Лимиты поколения: 20 000 записей, 64 МиБ исходного текста
с векторами и 64 МиБ новых векторов. На один ответ embedding-модели отводится
100 секунд. Программа mem должна работать; вкладку можно закрыть.


### Предложения AI и копии карт — alpha.19

Выберите узел карты → «Предложения AI». Укажите действие и задачу.
Для обоснованного предложения используйте актуальные источники ветви или
«Выбрать дополнительные фрагменты». Общий предел — 30 источников и 60 000
символов. Идеи без источников разрешаются отдельным флажком и помечаются
в предпросмотре. Модель и подключение берутся из сохранённых настроек базы.

Нажмите «Подготовить предложение». Карта пока не меняется. В списке заданий
откройте готовое предложение, проверьте текст/источники и отметьте нужные
изменения. Выбор ребёнка включает родителя; снятие родителя снимает детей.
«Применить выбранное к карте» сохраняет изменения общей транзакцией с историей.
Если карта или источник изменились, подготовьте новое предложение.

Вкладку можно закрыть: генерация работает в процессе mem. После остановки
программы незапущенные задания продолжаются, а прерванная генерация получает
понятный статус; используйте «Заполнить задачу заново» и проверьте источники.
Повтор запроса после сбоя сети использует прежнюю квитанцию и не дублирует
применённые изменения. Отмена задания доступна до применения.

Для эксперимента нажмите «Сделать копию» и задайте название. Узлы и история копии
независимы; привязки ссылаются на те же документы базы. Изменение оригиналов
документов влияет на актуальность источников обеих карт.

### История обработки в веб-интерфейсе

В разделе **Обработка** нажмите **История обработки** у нужного файла.
Выберите **Страницы попытки N**, чтобы увидеть результат именно этой попытки,
включая пустые и пропущенные страницы, текстовый слой/OCR и число фрагментов.
Длинные отчёты выводятся по 50 страниц. Кнопка обновления показывает завершившуюся
попытку. У обычного Markdown физических страниц может не быть — показывается
итоговое число фрагментов. Текст с ошибками внешних инструментов остаётся
в локальном журнале импорта; в браузере показано наличие ошибки/предупреждения.

### Автоматическая карта по источникам — как в NotebookLM

1. Запустите `mem gui`, выберите базу и дождитесь обработки нужных документов.
2. Откройте **Ментальные карты → Карта по источникам**.
3. Отметьте документы. Название и акцент необязательны; выберите подробность.
4. Нажмите **Создать карту по источникам**. Над картой появится спиннер с текущим этапом, номером обрабатываемой части и прошедшим временем. Генерация работает в фоне; её можно отменить. После повторного открытия карты отсчёт продолжается от запуска задания.
5. Готовая карта откроется с главными темами. Кнопки **+ / −** раскрывают ветви;
   **Основные темы** и **Показать 1 / 2 / 3 уровня** возвращают нужную глубину.
6. Выберите узел: **Источники узла** показывают подтверждения, а
   **Изучить ветвь / Задать вопрос** позволяет задать вопрос по материалам темы.

Все фрагменты выбранных документов участвуют в генерации. Предел одной карты:
20 документов / 512 фрагментов / 600 000 символов. Если предел превышен,
выберите меньше документов; программа не подменяет полный охват случайной выборкой.
Используется сохранённая модель ответов. Начиная с alpha.25 время задания зависит
от числа частей: минимум 15 минут, максимум 2 часа; платный провайдер
может тарифицировать запросы. Сгенерированная структура остаётся редактируемой;
применение AI можно отменить через историю. **Создать вручную** сохраняет
пустую карту и шаблоны без вызова модели. Этот режим не требует аккаунта Google.


### Ширина текста узла и удаление карты

Наведите указатель на вертикальный разделитель слева от панели **Текст узла**
и перетащите его влево для расширения или вправо для сужения. Можно также
выбрать разделитель клавишей Tab и нажимать стрелки ← / → (с Shift — крупнее),
Home / End — минимальная / максимальная ширина. Двойной щелчок возвращает
стандартные 360 px. Браузер запоминает выбранную ширину.

Чтобы удалить карту, нажмите **Удалить** напротив неё в библиотеке либо
**Удалить карту** в открытом редакторе. Проверьте название в диалоге и нажмите
**Подтвердить удаление карты**. Кнопка **Оставить карту** отменяет действие.
Карта исчезнет из библиотеки, включая архивный список, её задания AI остановятся.
Документы останутся в базе. История и содержимое логически удалённой карты
сохраняются внутри SQLite; восстановление через интерфейс и очистка этих данных
пока не предусмотрены. Для временного скрытия используйте **О карте → В архиве**.


### Сопоставление узла с исходным документом

Выберите узел и нажмите **Сверить с документом** в панели **Текст узла**.
Слева показан текст узла, справа — текст страницы, сохранённый при импорте.
Связанный фрагмент выделен и автоматически прокручивается в область просмотра.
Если подтверждений несколько, переключайте их списком **Источник узла**.
Обе области прокручиваются отдельно; на телефоне они располагаются друг под другом.

**Открыть оригинал PDF — страница N** открывает PDF в новой вкладке на той же
физической странице. Её номер может отличаться от напечатанного на странице.
Выделение пункта доступно в текстовом сравнении; исходный PDF открывается без
добавленной разметки. Переход к странице зависит от поддержки просмотрщиком PDF.
Текст узла остаётся в открытом окне сравнения.

Для документов без нумерации показан фрагмент и до двух соседних блоков с каждой
стороны. Если источник изменён или удалён из базы, показывается сохранённая цитата
с предупреждением. Если исходный PDF отсутствует, изменён или для него не сохранён
отпечаток, оригинал недоступен: повторите импорт и обновите привязку к источнику.
В серверном режиме оригинал должен находиться внутри каталога этой базы.
Оригиналы крупнее 64 МиБ не выдаются через этот просмотр; текст страницы ограничен
500 фрагментами и 2 МиБ, при превышении остаётся связанная цитата.
Узлам без источников сначала прикрепите подтверждение через **Источники узла**.

### Если создание большой карты остановилось по времени

С версии 1.72.0-alpha.12 у карт по источникам нет общего срока 15–120 минут.
Отдельный web-запрос модели ограничен 90 секундами. При его неудаче готовые
части остаются в базе: используйте **Продолжить с сохранённого места**.
После перезапуска mem незавершённая работа возобновляется автоматически;
пользовательская отмена автоматически не снимается. Вкладку можно закрыть.
Обычные предложения AI для существующего узла по-прежнему ограничены 3 минутами.

### Если создание карты остановилось из-за лимита токенов

В alpha.23 исправлено игнорирование повышенного лимита в веб-картах.
Первый запрос использует 4096 токенов. Если ответ обрывается, повтор той же
части может увеличить бюджет до значения **Настройки базы → Максимум токенов ответа**,
не выше 16384; значения ниже 4096 для карт повышаются до 4096. Повторные запросы
модели могут расходовать дополнительные токены. Произвольные ошибки сети и модели
не вызывают такого увеличения бюджета.

Если исчерпан и этот предел, пакет из нескольких фрагментов автоматически
делится на меньшие порции. Их готовые результаты сохраняются независимо.
Это также применяется при распознанной ошибке контекста модели.
Слишком длинный исходный фрагмент до генерации делится по доступному бюджету
символов без отбрасывания окончания; повторный импорт документа не требуется.
Начиная с 1.72.0-alpha.13, по фактическому отказу модели делится и одиночная
порция. Сохраняются все части входного текста и ссылки на исходный документ.
Готовые части не отправляются повторно при продолжении. Деление прекращается,
когда текст меньше 256 символов или невозможно получить две непустые части:
если модель отвергает и такую порцию, задание сохраняет прогресс и причину остановки.
Автоматическое определение токенизатора и ёмкости модели ещё предстоит.

### Если модель временно недоступна

Для HTTP 408, 429, 502, 503, 504 и типизированного сетевого сбоя программа
повторяет запрос до двух раз: обычно через 1 и 2 секунды. Если сервер передал
Retry-After до 30 секунд, пауза не будет короче указанного им срока. При более
долгой паузе задание сохраняет ошибку для явного продолжения позже.
Нажатие отмены прерывает ожидание. Ошибки доступа, неизвестной модели,
неверного ответа и превышение времени запроса не запускают эти повторы.
Если попытки исчерпаны, используйте **Продолжить с сохранённого места**,
когда модель снова станет доступна. Повторы могут расходовать токены провайдера.


## Сверка графа с документом (alpha.28)

Откройте расширенный граф, выберите узел или связь, затем вкладку «Источники»
и кнопку «СВЕРИТЬ С ИСТОЧНИКОМ». В широком окне слева находится формулировка,
справа — полный импортированный фрагмент с выделенной выдержкой. PDF можно
открыть отдельно на физической странице. Внизу доступны обратные переходы
к узлам и связям из того же фрагмента. Esc закрывает окно; на узком экране
колонки располагаются друг под другом. В статическом HTML доступна сохранённая
выдержка; загрузка контекста требует работающего сервера.

Новые требования могут содержать подписанные части «Требование», «Условие»,
«Исключение», «Ограничение». Каждая часть проверяется на дословное присутствие
в процитированном фрагменте. Отсутствующая часть означает «не извлечено»,
а не «условий/исключений нет». Новые узлы остаются черновиками.

В эталоне для `mem map eval-labeled` можно задавать `required_fragments` —
список обязательных формулировок. Например: `"required_fragments":["не менее 10 с"]`.
Они должны присутствовать в основном тексте узла (или заголовке, если текста нет).
Допустимые перефразирования основного утверждения задаются через `aliases`;
обязательные фрагменты остаются буквальными. Регистр и пробелы нормализуются.
См. [подробности и границы проверки](docs/GRAPH_QUALITY_RU.md).


### Оценка требований разных типов (alpha.29)

В JSON-эталоне для `mem map eval-labeled` и проверки качества в веб-интерфейсе
можно включить ограничения и процедуры:

```json
"matching": {
  "claim_kinds": ["claim", "constraint", "procedure"]
}
```

Без `claim_kinds` оцениваются только утверждения, как раньше. Пустой список,
повторы и другие типы отклоняются. В отчёте у каждого найденного объекта есть
его `kind`; числовые показатели `claims` относятся к выбранным типам.
Проверка использует весь текст узла, а не первые 4096 символов.
Дословное повторение ограничения в отдельном поле не снижает сходство с
эталоном, если оно уже входит в текст требования. Новые условия и исключения
продолжают участвовать в проверке по полному тексту.

При извлечении требований различия PDF-цитаты только в пробелах, табуляции
или переносах строк больше не приводят к отказу, если место однозначно найдено.
Сохраняются исходная выдержка и её хеш. Изменения букв, пунктуации, чисел и единиц
не исправляются автоматически. Это не проверка полноты требований.

Протокол ограниченного прогона на реальной модели:
[GRAPH_QUALITY_STAGE2_RU.md](docs/GRAPH_QUALITY_STAGE2_RU.md).
