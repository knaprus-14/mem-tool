# Проверка веб-интерфейса 1.71.0-alpha.1

Дата: 9 сентября 2026 года. Проверен первый этап из
[плана реализации](WEB_ROADMAP_RU.md). Полный паритет с CLI пока не реализован.

## Автоматические проверки

- `go test ./... -count=1 -timeout=300s` — успешно после финальных изменений.
- `go vet ./...` — успешно.
- `node --check internal/webapp/assets/app.js` — успешно.
- `git diff --check` — без ошибок форматирования; Git предупреждает о нормализации
  окончаний строк в части ранее изменённых файлов.
- Проверены read-only SQLite, отсутствие создания отсутствующей БД при чтении,
  сохранение каталога, владение базами и отсутствие изменения текущей директории.
- HTTP-тесты покрывают два пользовательских контекста, запрет доступа к чужим
  данным, Host/Origin/CSRF, cookie, выход, ограничение попыток входа и отказ
  невалидной серверной конфигурации до создания данных.

В ограниченной Windows-среде Go выдавал предупреждения о недоступной записи
телеметрии/кэша модулей. Проверки завершились с кодом 0; использовался доступный
временный `GOCACHE`, `GOPROXY=off` и `GOTOOLCHAIN=local`.

## Браузерные сценарии

На отдельных временных данных, без обращения к моделям и реальным документам:

- `mem gui`: первый запуск, создание базы, сохранение списка после перезапуска.
- Просмотр одного тестового документа с тремя фрагментами по порядку страниц;
  открытие полного текста и отображение имени документа.
- Просмотр 35 заметок: страницы по 30 записей, переход на последнюю страницу.
- HTML-теги в тексте заметки отображаются буквально.
- Просмотр настроек; при ширине окна 390 px горизонтального переполнения нет.
- Изменения тестовой БД извне видны после кнопки «Обновить».
- SHA-256 тестового `store.db` после просмотра и перезапуска не изменился.
- `mem serve`: форма входа, вход проверочного пользователя, создание его базы,
  отсутствие выбора серверного пути в форме, выход с возвратом на страницу входа.

Браузерная проверка server mode выполнялась на Windows через HTTP loopback.
Linux runtime, реальный reverse proxy и HTTPS на VDS ещё не проверены.

## Артефакты и установка

Собраны `mem.exe`, `mem-index.exe`, `mem-bot.exe` для Windows/amd64; версии всех
трёх — `1.71.0-alpha.1`. Проверочные файлы размещены в
`build/web-alpha/windows-amd64`; SHA-256 совпали с временными сборками.
Версии и хэши записаны рядом в `verification.json`.

Также собран Linux/amd64 `mem` с `CGO_ENABLED=0` в
`build/web-alpha/linux-amd64/mem`. Проверен ELF-заголовок, выполнение на Linux
не проводилось.

Установленная версия в `C:\Users\ZMII\bin` осталась **1.70.4**: проверка записи
`deploy/windows.ps1` получила `Access denied` до тестов и сборки. При отдельной
проверке со staging-целью общие тесты и сборка прошли, после чего скрипт остановился
из-за уже работающего пользовательского `mem`; этот процесс не останавливали.
Три артефакта скопированы только в отдельную папку внутри репозитория.

Для обычной установки после закрытия работающих экземпляров `mem` следует
запустить `deploy/windows.ps1` в PowerShell с доступом к каталогу установки.
На VDS ничего не установлено; серверные файлы в `deploy/` являются шаблонами.
