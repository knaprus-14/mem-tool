# Проверка 1.71.0-alpha.25 — общий тайм-аут большой карты

Дата: 10 сентября 2026 года.

## Диагноз

База `E:\temp\mem-test4\.mem\store.db` открывалась только через SQLite mode=ro.
Карта «Обзор документа СП485», id `mm-3f8f4b96385a62963b0603e72ccedd2d`.
Задание `efc10ec6b6214d69aee875f527702642`, run
`mmg-26b8dffa9a84849a5abff2c0ed8cb58e`. Выбран 1 документ, 372 фрагмента,
план — 64 части. Модель gpt-oss:120b-cloud; сохранённые настройки ответа:
timeout_seconds=60, max_tokens=32000, context_chars=12000.

Run начался 06:49:21.7603764 UTC, завершился 07:04:21.5770599 UTC — примерно
15 минут. 57 частей completed, 58-я failed, 6 pending. Часть 57 завершилась
07:04:14.7708757, часть 58 прервана спустя около 6,8 секунды с
`ollama answer cancelled or timed out: context deadline exceeded`.

Причина — фиксированный 15-минутный context всего задания в веб-воркере.
Модель продолжала успешно обрабатывать документ, тайм-аут последнего отдельного
HTTP-ответа ещё не истёк. Повышение max_tokens эту причину не устраняет.
Карта осталась на ревизии 1 с корнем. Установленный mem сообщает alpha.23.

## Исправление

Подготовка входов ограничена 3 минутами, затем для source overview создаётся
отдельный контекст на основе того же детерминированного плана, что использует
генерация. Бюджет: число частей × 2 × окно ответа + 2 минуты запаса, минимум
15 минут, максимум 120 минут. Для 64 частей — 120 минут.

Окно HTTP-ответа остаётся 90 секунд; количество повторов и токены не менялись.
Это верхний предел времени, а не обязательная задержка и не дополнительные
запросы модели. Предложения AI для существующей карты остаются ограничены
3 минутами. Ошибки общего бюджета и одного ответа теперь различаются.
Отмена пользователем и остановка сервера по-прежнему доходят до провайдера.

Прежний failed run не менялся, его части не перепубликовывались. Для новой
попытки после обновления используется «Выбрать источники и повторить»; она
начинает обработку сначала. Возобновление с части 58 в этом исправлении
не добавлялось. Реальная облачная генерация СП485 повторно не запускалась.

## Проверка

Регрессионный тест с testing/synctest выполняет настоящий веб-воркер на временной
базе с 64 частями. Тестовая модель тратит по 16 секунд виртуального времени:
64 ответа, 17 минут 4 секунды, затем автоматическая публикация 65 узлов и
ревизии 2. Старый предел остановил бы этот сценарий до получения всех ответов.
В реальном времени тест занимает секунды и не обращается к модели или сети.

Отдельно проверены расчёт минимального/максимального бюджета, классификация
ошибок без раскрытия приватных деталей, отмена пользователем и остановка сервиса.
Все тесты TestWebSourceMap/TestWebMapAI, go vet и 6 JS-сценариев индикатора
прогресса прошли. git diff --check не обнаружил ошибок форматирования.

Полный `go test ./... -count=1 -timeout=300s` в штатном скрипте сборки также
прошёл. Новые тесты использовали изолированные временные базы; браузерная
проверка не повторялась, так как DOM/CSS/JS и контракт HTTP не менялись.

Все три Windows/amd64 бинарника собраны deploy/windows.ps1 и прошли version
smoke: 1.71.0-alpha.25. Проверенные артефакты и SHA256.json сохранены в
`build/web-alpha/alpha25/windows-amd64`; SHA-256 совпадает с исходным stage.

Установка в `C:\Users\ZMII\bin` заблокирована на preflight:
Access denied для `.mem-deploy-probe-ac12b91b30b146568bc5cab451d3d873`.
Выполнение со сборочной целью внутри проекта прошло тесты и компиляцию,
но штатное копирование остановлено из-за пользовательского процесса mem:15300.
Он не останавливался. В незанятый каталог артефактов скопированы только три
именованных exe из сохранённого stage, с повторной проверкой версий и хешей.
Это подготовленная сборка; установленные программы по-прежнему alpha.23.
