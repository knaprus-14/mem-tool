# Проверка 1.71.0-alpha.26 — единое логирование

Дата: 10 сентября 2026 года.

## Реализовано

Общий `internal/applog` подключён к точкам запуска всех трёх команд.
`mem-tool.log` закреплён за исходным cwd до --dir/--global/TUI-переходов.
JSONL содержит время, процесс, версию, идентификаторы запуска/операций,
длительность, технические результаты. Добавлено 295 вызовов Track/TrackCode
на границах операций, а также отдельные события стадий и HTTP.

Охват: CLI/TUI/REPL, Telegram, web app и оба прежних редактора карт,
SQLite/workspaces, настройки, импорт/конвертеры/OCR, индекс файлов,
эмбеддинги/поиск/ответы, графы и классические карты, история/экспорт/учебные
материалы, фоновые задания. Поля task/run ID, прогресс, сроки и повторы модели
сохраняются отдельно. Клиентские ошибки принимаются только после авторизации
и CSRF-проверки, с ограниченным набором полей и частотой.

Логгер не копирует документы, запросы/ответы моделей, параметры SQL, токены,
произвольные сообщения ошибок и полный stdout/stderr. Вместо приватных ошибок
сохраняются типы, категории, коды, хеши; для валидации AI — безопасная категория.
Прежний log.Printf продолжает печататься в консоль, в журнале сохраняется
обезличенный legacy.log. Область действия и ограничения описаны в LOGGING_RU.md.

Ротация — 10 МиБ с сохранением всех архивов; межпроцессная блокировка защищает
строки и переименование. При запрете ротации запись продолжается в текущий файл.
Ошибка открытия/записи не подменяет результат операции. Файлы журналов и lock
исключены из автоматического файлового индекса и Git. Шаблон systemd для бота
перенесён в writable cwd /opt/mem-bot/data с абсолютным путём к данным.

## Автоматическая проверка

- Полный `go test ./... -count=1 -timeout=300s` прошёл на финальном исходном коде.
- Полный `go vet ./...` прошёл; после последней локальной поправки обработки
  паники TrackCode пакет internal/applog проверен повторно.
- 26 JS-сценариев навигации, удаления, сравнения, ширины панели и прогресса прошли;
  синтаксис изменённого app.js проверен Node.
- 8 горутин и отдельные процессы одновременно пишут/ротируют один журнал:
  строки остаются валидным JSON, ожидаемые события сохранены.
- Проверены неизменность cwd журнала после chdir, коды выхода, скрытие приватных
  маркеров, запись/повторное возбуждение паник, отказ открытия лога без остановки
  команды, продолжение записи при отказе ротации и восстановление архивирования.
- HTTP: статус/тело/Flush сохранены, входящие query/body/headers и исходящие
  credential-bearing URL/Authorization/тексты не попадают в файл.
- Клиентские события: 401/403 без сессии/CSRF, 400 для лишних/опасных полей,
  200 для валидного события, 429 при повторе раньше секунды.
- Интеграция worker: source map, повтор после токенного обрыва, публикация;
  журнал содержит task ID, план, бюджет, попытки и завершение, без содержимого.
- Собственные журналы/архивы/lock не индексируются; обычный application.log
  и пользовательский notes.txt остаются доступными файловому индексу.

## Исполняемые файлы и браузер

Все три exe запускаются из отдельной smoke-папки. Проверены version, ошибка
арности с кодом 1 и четыре process.exit. `mem --dir ../fixture version` оставляет
журнал в smoke-папке. Синтетический секретный аргумент в файл не попал.

Итоговый mem.exe запущен на localhost:18796 с изолированной копией тестовой базы.
Библиотека и карты открываются; через браузер создана ручная карта с приватными
тестовыми маркерами в названии/описании. В журнале есть web.request/response и
CreateWebMapIn.start/finish, маркеры отсутствуют. На контрольном срезе — 1201
валидная строка JSONL, 56 HTTP-ответов, 334533 байта; создание вернуло HTTP 200.
В журнале браузера и stderr сервера ошибок нет; SQLite integrity_check — ok.
Тестовая вкладка и сервер закрыты. Пользовательская база и процесс не менялись.
Облачные модели и Telegram в живом окружении не вызывались, Linux/VDS не развёртывался.
