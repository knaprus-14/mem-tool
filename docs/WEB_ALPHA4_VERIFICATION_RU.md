# Проверка поиска и ответов 1.71.0-alpha.4

Дата: 9 сентября 2026 года. Первая часть этапа 3: поиск и ответы в общей
веб-оболочке, с отдельным сервисом чтения и прежними моделями из настроек базы.

## Что подключено

- Гибридный, векторный и лексический поиск, общие алгоритмы и ранжирование CLI.
- Фильтры тегов, важности, даты и физических страниц; поиск во всей базе или
  одном документе; ограничение выдачи 1–50 фрагментами и порог оценки.
- Раздельные действия «Найти фрагменты» / «Получить ответ», отмена запроса,
  сохранение найденных фрагментов при недоступной модели ответов.
- Нумерованные источники, отклонение ответов с отсутствующими/неизвестными ссылками,
  явные состояния недостаточных данных и изменившихся источников.
- Контрольная сумма состояния фрагмента при открытии; повторная согласованная
  проверка использованных источников после генерации.
- Ограничения времени, параллельности и размера снимка для серверного режима.

## Автоматическая проверка

Успешно выполнены:

- `go test ./... -count=1 -timeout=300s` через `deploy/windows.ps1`;
- `go vet ./...`;
- `node --check internal/webapp/assets/app.js`;
- `git diff --check` (есть предупреждения Git о нормализации окончаний строк).

Новые тесты выполняются на временных базах и локальном тестовом HTTP-провайдере.
Проверены чтение без изменения store.db, поколения FTS и статуса постороннего
импорта; поиск по словам при недоступной модели; фильтры, идентичность пространства
векторов и совпадение ранжирования с CLI при актуальном FTS. Устаревший FTS не
перестраивается запросом: используется общий лексический fallback.

Проверены корректный ответ, отсутствие ссылок, неизвестная ссылка, недостаточные
данные и изменение метаданных источника во время генерации. Изменённый фрагмент
не открывается по старой контрольной сумме. Невалидные запросы отклоняются до
вызовов модели; ограничение размера корпуса проверяется до его загрузки в память.
Отмена контекста прерывает активный запрос векторизации.

HTTP-тесты проверяют поиск → ответ → открытие источника, CSRF (403), отказ чужому
владельцу (404), анонимному пользователю (401), неподдерживаемому методу (405),
лимитам параллельности (429). Клиент не может подставить URL модели. Серверные пути,
параметры векторов и внутренние ошибки провайдера не попадают в ответы API.

## Проверка в браузере

Использовались отдельная база `build/web-alpha/alpha4/smoke-state`, две искусственные
заметки и тестовый HTTP-провайдер ответов на loopback. Заметки созданы непосредственно
как тестовые записи SQLite; импорт и загрузка файлов в этой проверке не участвовали.
Реальные документы, установленные модели и внешние API не использовались.

Подтверждены:

1. Создание базы, открытие раздела поиска и отображение выбранных моделей.
2. Поиск «клапан» в режиме «По словам» возвращает одну подходящую заметку.
3. Ответ тестовой модели содержит `[1]`, а ниже показан использованный источник.
4. Кнопка источника открывает сохранённый текст заметки.
5. После изменения тестовых тегов старая ссылка сообщает об изменении источника.
6. При тестовой задержке видны ожидание и кнопка отмены; отмена возвращает форму
   в рабочее состояние. Поздний ответ не появляется вместо сообщения об отмене.
7. При viewport 390 px и раскрытых фильтрах scrollWidth раздела равен clientWidth
   (335 px). Горизонтального переполнения нет. Журнал ошибок JavaScript пуст.

Тестовая вкладка закрыта, размер окна сброшен, оба временных процесса остановлены.
Запущенный пользовательский `mem` не останавливали. Чтение сведений через CIM было
недоступно; тестовый helper завершён по ранее полученному PID после проверки его
пути через Get-Process. Это не повлияло на результат проверки приложения.

`C:\Users\ZMII\bin` возвращает `Access denied` до тестов и сборки.

## Границы этапа

Снимок веб-поиска ограничен 20 000 записями и 64 МиБ содержимого с векторами;
это не жёсткая граница полного потребления RAM. Лимит возвращает явный отказ,
а не поиск по молча усечённому корпусу. На процесс разрешены два запроса и один
на пользователя, до 100 секунд; настройки ответа ограничены сверху 48 000 символов
контекста и 4096 токенами. При лексическом fallback порядок может отличаться от
актуального FTS, хотя алгоритмы обоих режимов общие с CLI.

Открывается текст фрагмента из базы, не оригинальный PDF. Проверка актуальности
сравнивает состояние записей базы, а не хэш физического файла на диске.
Проверка ссылок не доказывает семантическую истинность ответа; качество реальной
модели в этом этапе не оценивалось. Выбор моделей, редактирование настроек/заметок,
полная переносимость баз и карты в общей оболочке остаются последующими этапами.
