# Проверка 1.71.0-alpha.23 — остановка создания карты АУП-1

Дата: 9 сентября 2026 года.

## Установленная причина

Исходная база E:\Video\Takir\АУП-1\.mem\store.db открывалась только с mode=ro.
Задание ff962d5335c04a5293e0304f634cf645, карта
mm-418c8c8b81d7ef097fe27d4ae3b33a0c — «порядок применения неметаллических труб
при проектировании АУП». Выбрано 3 документа, 290 фрагментов. Превышения общего
предела документов/фрагментов нет.

Run mmg-2a3b0da6ab4d5e9c37383af58b908bbd:
- Модель gpt-oss:120b-cloud.
- Начало 20:22:44 UTC, остановка 20:26:54 UTC — около 4 минут 10 секунд.
- Фаза generate, часть 41 из 61.
- Сохранённая причина: `classic mind map AI batch 41: web AI token budget exhausted`.
- 24 части completed, 16 insufficient, 1 failed, 20 pending.
- Карта осталась на ревизии 1 с одним корнем. Готовые части сохранены в журнале;
  итоговая структура не опубликована. Восстановление с части 41 не выполнялось.

В настройках базы answer.max_tokens=8128, context_chars=12000,
answer.timeout_seconds=60. Веб-адаптер обрезал выходной бюджет до 4096 и запрещал
любой больший запрос. После типизированной ошибки обрыва по токенам общий механизм
удваивал бюджет до 8192, но адаптер отклонял его до обращения к модели, заменяя
первоначальную причину общей ошибкой. Это конфликт политик бюджета, а не истечение
времени всего задания. Общая ошибка в интерфейсе не объясняла причину.

## Исправление

Начальный бюджет веб-карты — 4096. Настроенное значение теперь задаёт потолок
повторов: минимум 4096, максимум 16384. Для пользовательского значения 8128
получается последовательность 4096 → 8128. Общий механизм учитывает потолок
адаптера и не отправляет запрещённый запрос. Терминальные провайдеры без
специального ограничения сохраняют прежние повторы до 16384.

При исчерпании допустимого бюджета исходная AnswerTokenLimitError сохраняется,
веб-сообщение содержит номер части, лимит и доступные действия. Тайм-аут имеет
отдельное сообщение. Произвольные сырые ошибки модели и приватные пути в
веб-сообщение не включаются. Существующие завершившиеся ошибкой задания
не перезапускаются; повтор из интерфейса создаёт новое задание с начала.

## Проверки

- Целевые TestWebMapAI*, TestWebSourceMap* и тесты token retry — успешно.
- Регрессия 4096 → 8128 с публикацией карты по источникам — успешно.
- Верхний предел 16384 при настройке 32768; последовательность
  4096 → 8192 → 16384 и публикация — успешно.
- Повторный обрыв на 8128: ровно два запроса, failed с конкретным лимитом,
  исходная карта не изменена.
- Порог по умолчанию 4096 не обходится; приватные ошибки не раскрываются,
  ошибка тайм-аута распознаётся по errors.Is.
- HTTP-интеграция: тестовый Ollama /api/chat сначала возвращает done_reason=length;
  второй HTTP-запрос содержит num_predict=8128 и создаёт карту.
- Полный go test ./... -count=1 -timeout=300s и go vet ./... — успешно.
- git diff --check — без ошибок; остаются предупреждения нормализации LF/CRLF.

В браузере использована только изолированная тестовая база, localhost:18793 и
тестовая модель localhost:18923. Создание после искусственного обрыва завершилось
«Карта готова», 2 узла. Второй сценарий исчерпал оба бюджета и показал:
«Часть 1 из 1: модели не хватило лимита 8128 токенов…». Журнал браузера пуст,
SQLite integrity_check — ok. HTML из итогового бинарника совпадает с исходником.
Тестовые вкладка и процессы закрыты. Запросы к облачной модели не выполнялись,
пользовательская база не изменялась. Полная повторная генерация 290 реальных
фрагментов и её конечное качество этим прогоном не проверялись.
