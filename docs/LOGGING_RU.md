# Системный журнал mem-tool

Начиная с alpha.26, `mem`, `mem-index` и `mem-bot` автоматически создают
**mem-tool.log в текущей папке запуска**. Ничего включать не нужно.
Путь закрепляется до обработки `--dir`, `--global` и переходов в TUI:
если запустить программу из C:\Work с `--dir E:\Docs`, журнал остаётся в C:\Work.
Папка базы и папка журнала совпадают, когда программа запущена из папки базы.

Формат — текстовый UTF-8, одна JSON-запись на строку. В каждой записи есть:
`time` (UTC), `level`, `event`, `component`, `version`, `pid`, `run_id`, `seq`,
`site` (исходный файл/строка). В `data` — параметры технического события:
идентификатор операции, длительность, результат, код HTTP, объёмы и счётчики.
Идентификатор `run_id` верхнего уровня связывает события одного запуска программы;
`data.run_id` в событиях AI относится к сохранённому заданию генерации карты.

## Что записывается

- Запуск, нормальный выход с кодом, перехваченная паника с именами функций/строками.
- Команды CLI, сеансы TUI/REPL и выполняемые ими операции хранения и моделей.
- Открытие SQLite и баз, чтение/изменение записей, заметок и настроек.
- Импорт, страницы/блоки, OCR и запуск конвертеров, эмбеддинги и файловый индекс.
- Поиск, генерация ответов, HTTP-запросы к моделям, статус и оставшееся время.
- Создание/редактирование карт, источники, история, снимки, экспорт и учебные задания.
- Задания AI: task ID, run ID, части, общий лимит, лимит ответа, токены,
  повторные попытки, ошибки проверки, отмена и публикация.
- Входящие веб-запросы: метод, обезличенный маршрут, статус, размер ответа, время.
  Записываются также обращения к прежним отдельным редакторам карт.
- Telegram: решение проверки доступа, работа обработчиков через общие сервисы,
  запросы к Telegram API, ошибки polling и отправки.
- Ошибки браузера после авторизации: тип, имя скрипта, строка/столбец, если доступны.
  Повторы ограничены одним событием в секунду на пользователя; недоступный сервер
  или ошибка до входа не позволяют доставить браузерное событие в файл.

Это журнал технических операций, а не копия экрана или полного stdout/stderr.
Движения мыши, введённый текст, SQL-тексты/параметры, документы, сообщения Telegram,
запросы/ответы моделей, cookies, пароли и токены не копируются. Динамические части
URL и адреса внешних endpoints записываются хешами. Для ошибок сохраняются
`error_kind`, `error_type`, `cause_type`, доступный код и `error_id`; исходный
`Error()` исключён, потому что провайдер может включить в него секрет или документ.
Прежние вызовы `log.Printf` сохраняют консольный вывод, а в файл попадает
`legacy.log` с хешем сообщения; подробную техническую причину ищите в соседних
структурированных событиях. Приватный текст паники также исключён.

## Файлы и совместная работа

При достижении 10 МиБ `mem-tool.log` переименовывается в
`mem-tool.<дата UTC>.<PID>.<номер>.log`, после чего начинается новый текущий файл.
Если просмотрщик временно запрещает переименование файла (например, в Windows),
запись продолжается в текущий файл с `rotation_deferred=true`; размер временно
может превысить 10 МиБ. Архивирование повторится при следующей записи.
**Архивы автоматически не удаляются.** Для анализа старой ошибки сохраняйте
текущий файл и архивы соответствующего времени.

Несколько программ из одной папки используют один журнал; `component`, `pid`
и `run_id` различают их. Служебный `mem-tool.log.lock` удерживает блокировку только
на время записи/ротации и остаётся пустым на диске. Не удаляйте lock-файл при
работающих программах. После остановки программ архивы можно переносить вручную.
Собственные журналы не индексируются `mem-index` и исключены из Git.

Записи не буферизуются до завершения задания: файл закрывается после каждой
строки. Принудительное завершение процесса или отключение питания может не дать
записать `process.exit`; отсутствие этой записи само по себе не указывает причину.
Если каталог недоступен, диск заполнен или блокировка не получена за две секунды,
в stderr выводится предупреждение. Операция с данными продолжается; запись журнала
при таких условиях не гарантируется. Файлы создаются с правами 0600 на Unix.

## Просмотр в PowerShell

Из папки запуска программы:

```powershell
Get-Content .\mem-tool.log -Tail 50 -Wait
```

Ошибки и предупреждения:

```powershell
Get-Content .\mem-tool.log |
  ForEach-Object { $_ | ConvertFrom-Json } |
  Where-Object { $_.level -in @('ERROR', 'WARN') } |
  Format-List time, component, event, site, data
```

Всю цепочку создания карты удобно искать по task ID или run ID из журнала.
Для сообщения о сбое достаточно приложить журнал и указать примерное время.

## VDS

`mem-web.service` запускается из /var/lib/mem-tool: журнал будет там.
Шаблон `mem-bot.service` теперь запускается из /opt/mem-bot/data, куда разрешена
запись; путь к данным задан абсолютным MEM_BOT_DATA_DIR. Перед обновлением
собственного unit/env замените относительные пути к данным абсолютными.
Рабочая папка должна быть доступна для записи сервисному пользователю.
Изменение шаблонов в репозитории не обновляет уже установленный сервис на VDS.
