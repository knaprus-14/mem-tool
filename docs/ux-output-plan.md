# UX-план: форматированный вывод mem-tool

**Дата:** 27.07.2026
**Запрос Руслана:** при поиске выдача одного цвета, тяжело ориентироваться. Хочется подсветку и табличный формат.

## Проблема

Сейчас вывод `mem search`, `mem recent`, `mem stats` — plain-text одним шрифтом. Семантически связанные куски не отделены визуально. Когда результатов 5-10, приходится вчитываться.

## Решение: 3 фазы

### Фаза 1 — Цвета и базовая структура (1-2 часа)

| Элемент | Цвет | Жирность |
|---------|------|----------|
| ID записи (#50) | жёлтый | bold |
| Score [100%] | зелёный 100% / жёлтый 70-99% / красный <70% | bold |
| Теги | голубой | normal |
| Дата | серый | normal |
| Разделитель между результатами | серый `───` | normal |
| Заголовок команды | magenta | bold |

**Авто-детект TTY:** если вывод идёт в pipe (`mem search ... | grep`), цвета выключаются автоматически. Иначе включены.

**Управление:**
- Флаг `--color=always|auto|never`
- Env `MEM_NO_COLOR=1`

### Фаза 2 — Подсветка запроса в тексте (30 мин)

Разбиваем поисковый запрос на токены, оборачиваем совпадения в жирный/жёлтый. Используем `__подсвет__` формат (без ANSI, чтобы можно было искать grep'ом).

Пример:
```
VDS knaprus: IP __157.22.196.67__, hostname __knaprus.fvds.ru__,
Ubuntu 24.04.3 LTS...
```

### Фаза 3 — Табличный формат для списков (1 час)

`text/tabwriter` из stdlib для аккуратных колонок. Применяется к:

```
┌─ Топ-N mem-base ────────────────────────────────────────────┐
│ ID    │ Score │ Теги                  │ Дата        │ LEN    │
├───────┼───────┼───────────────────────┼─────────────┼────────┤
│ #50   │ 100%  │ vds, infra            │ 2026-07-27  │ 320 B  │
│ #57   │ 92%   │ bot, local-run        │ 2026-07-27  │ 360 B  │
└───────┴───────┴───────────────────────┴─────────────┴────────┘
```

Команды для табличного формата:
- `mem search` — таблица топ-N результатов + превью
- `mem recent` — таблица
- `mem stats` — таблица по бэкендам
- `mem sources` — таблица

## Технические решения

| Что | Выбор | Обоснование |
|-----|-------|-------------|
| Цветовая библиотека | `github.com/fatih/color` | Проверенная, лёгкая (~30 КБ), ANSI-только |
| Детект TTY | `golang.org/x/term` IsTerminal() | Стандарт, корректно на Win/Mac/Linux |
| Таблицы | stdlib `text/tabwriter` | Уже в Go, без зависимостей |
| Подсветка | подстрочный поиск регистро-независимый | Без regex overhead |

## Открытые вопросы для обсуждения

- [x] **Цветовая база:** TrueColor (24-bit) — RGB-палитра, fallback на 16/256 в старых терминалах
- [x] **NO_COLOR:** поддерживать стандарт https://no-color.org/
- [x] **Длина превью:** 200 символов по дефолту + флаг `-full` для показа всей записи
- [x] **Конфиг цветов:** жёстко зашитая дефолтная схема (без `mem config set-color-scheme` пока)

## Fallback-стратегия для цветов

1. **TrueColor** (RGB) → если `COLORTERM=truecolor` или `WT_SESSION` (Windows Terminal) или iTerm2/Kitty/Alacritty
2. **256-color** (`\033[38;5;Nm`) → если `TERM=xterm-256color`
3. **16-color** (стандартный ANSI) → иначе
4. **Plain text** → если `NO_COLOR=1`, или не-TTY, или `--no-color`

Реализация через обёртку в `pkg/ui/style.go`:
```go
// Пример сигнатуры
func Color(c ColorSpec, s string) string {
    if !useColor() { return s }
    if supportsTrueColor() {
        return fmt.Sprintf("\033[38;2;%d;%d;%dm%s\033[0m", c.R, c.G, c.B, s)
    }
    // ... fallback chain
}
```
