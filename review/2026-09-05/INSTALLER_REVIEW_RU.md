# Проверка Windows-установщика

Проверен `deploy/windows.ps1` после повторных отказов установки 1.70.4.
Контрольные проверки используют уже собранные бинарники 1.70.4 и отдельные
временные каталоги. Новая сборка Go для этой проверки не потребовалась.

## Подтверждённая причина отказа в C:\Users\ZMII\bin

ACL каталога прочитан непосредственно в этой сессии:

- `DESKTOP-VMSCDU5\CodexSandboxUsers`: `ReadAndExecute, Synchronize`;
- пользователь `DESKTOP-VMSCDU5\ZMII`: `FullControl`;
- системная учётная запись и администраторы: `FullControl`.

Это согласуется с ограничением сеанса: каталог установки доступен для чтения,
но находится вне разрешённых путей записи. На нём нет признака junction/symlink.
Ошибки возникают уже при создании нового временного файла, до замены exe.
Права каталога в ходе проверки не менялись.

Контрольная установка **тем же блоком кода** в разрешённый временный каталог
успешна. Проверены все три бинарника, SHA-256, единая версия 1.70.4, резервные
копии и сохранение постороннего файла `mem.exe.new`. В имени каталога специально
использованы пробелы и квадратные скобки. Ошибку формирования пути или
неработающий вызов `Copy-Item` этот контрольный сценарий не подтвердил.

## Найденные и исправленные недостатки скрипта

1. **Позднее обнаружение недоступного каталога.** Ранее каждый повторный запуск
   сначала выполнял все тесты и собирал три exe, затем падал на первой записи.
   Теперь отдельная preflight-проверка создаёт, переименовывает и удаляет только
   свой уникальный пробный файл до запуска Go. Файл вместо каталога также
   отклоняется заранее. Успешная проверка не оставляет временных файлов.
2. **Изменение окружения вызывающего PowerShell.** `GOCACHE`, `GOOS`, `GOARCH`
   и `CGO_ENABLED` оставались изменёнными после завершения скрипта. Теперь они
   сохраняются до работы и восстанавливаются в `finally`; исходно отсутствующие
   переменные удаляются, а не превращаются в пустые значения.
3. **Ошибка очистки могла скрывать первоначальный сбой.** Завершающий
   `Remove-Item` при блокировке файла мог выбросить исключение из `finally`.
   Теперь очистка сообщает предупреждение, сохраняя исходное исключение.
   Удаление staging-каталога не рекурсивное и не запрашивает интерактивное
   подтверждение, если в нём остались файлы.

## Выполненные проверки

| Сценарий | Итог |
|---|---|
| Установка всех трёх бинарников в изолированный каталог, до правок | PASS |
| Установка тем же блоком после правок; SHA-256 и версии | PASS |
| Второй целевой exe заблокирован открытым дескриптором | PASS: первый exe восстановлен, полный прежний комплект сохранён |
| Неполный rollback из-за недоступной резервной копии | PASS: остальные файлы восстановлены, оставшиеся backups сохранены |
| Посторонний `mem.exe.new` и путь с пробелами/скобками | PASS |
| Preflight создаёт/переименовывает/удаляет уникальный файл | PASS |
| Целевой путь является обычным файлом | PASS: отказ до вызова Go, содержимое файла сохранено |
| Принудительный отказ шага тестов | PASS: окружение PowerShell восстановлено, включая отсутствующий GOARCH |
| Заблокированный файл при очистке staging | PASS: исходная ошибка сохранена, диалог рекурсивного удаления не возникает |
| Preflight реального C:\Users\ZMII\bin | Ожидаемый отказ доступа за 0,244 с; тесты и сборка не запускались |
| Синтаксис PowerShell и `git diff --check` | PASS |

Тесты установки исполняют фактический transaction-блок установщика, а не его
переписанную копию. Тест восстановления окружения вызывает весь entry script,
подменяя только `go` контролируемым отказом, чтобы не собирать exe повторно.

Логи: `installer-control-before.txt`, `installer-control-after.txt`,
`installer-preflight-tests.txt`, `installer-rollback-after.txt`,
`installer-real-target-preflight.txt`. Права — `bin-access-review.txt`.

Изменены PowerShell-скрипты и документация выпуска 1.70.4. Установка в
`C:\Users\ZMII\bin` остаётся незавершённой из-за прав текущего сеанса;
контрольная установка во временный каталог не является установкой в PATH.
