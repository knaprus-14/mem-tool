# Проверка заметок 1.71.0-alpha.6

Дата: 9 сентября 2026 года. Создание и редактирование ручных заметок в общей
веб-оболочке; редактор настроек из alpha.5 сохраняется.

## Реализовано

- «Добавить заметку» и редактор существующей заметки: текст, название, теги,
  важность. Документные фрагменты не принимаются этим API.
- Векторизация нового/изменённого текста текущей моделью с сохранением точной
  embedding identity. Метаданные меняются без модели и без замены старого вектора.
- Проверка полного состояния записи до/после векторизации, короткая атомарная
  транзакция. Весь корпус не загружается, чужие импорты не восстанавливаются.
- Квитанция попытки в `web_note_writes` сохраняется вместе с записью. Повтор того
  же запроса возвращает прежний ID, новое содержимое с использованным ключом
  отклоняется. Даже если запись позднее удалена другим клиентом, квитанция не
  создаёт её снова. Таблица добавляется при первой успешной веб-записи.
- Общие с поиском лимиты параллельности: два запроса на процесс, один на пользователя,
  до 100 секунд на сохранение; владение базой, CSRF и строгая форма запроса.
- Старые длинные заметки читаются без усечения текста: свыше 2000 символов здесь
  меняются только метаданные. Основные данные записи ограничены 1 МиБ, текст —
  100000 символами. Создание/изменение текста — до 2000 символов.

## Проверки кода

Успешно выполнены:

- `go test ./... -count=1 -timeout=300s` через deploy/windows.ps1;
- `go vet ./...`;
- `node --check internal/webapp/assets/app.js`;
- `git diff --check`;
- сборка трёх Windows/amd64 программ и их команды version;
- сборка Linux/amd64 mem с CGO_ENABLED=0.

Финальные тесты pkg/mem: 39,643 секунды; internal/webapp: 5,704 секунды.

Регрессионные проверки покрывают повтор создания без дубликата/повторной модели,
неправильное содержимое с прежним ключом, изменение метаданных без модели,
актуальность кэша CLI и поиска, устаревшую форму, конкурентную смену важности во
время HTTP-векторизации, отказ модели, отмену, большие тексты, отсутствующую базу,
запрет source-anchored записей, откат заметки при ошибке вставки квитанции,
владение базой, анонимный доступ, CSRF, методы/неизвестные поля и общие лимиты.

Проверка отмены использует искусственный HTTP-сервер с корректным чтением тела
запроса перед ожиданием отключения; его первоначальное зависание в Close устранено
в тестовом helper. Финальный набор завершился без зависаний.

## Ограничения

Истории правок, удаления и восстановления заметок пока нет. Редактор не меняет
метаданные документных фрагментов. Пересчёт всех старых векторов при смене модели
не выполняется. Ключ повторной отправки хранится только до закрытия/перезагрузки
формы: после перезагрузки нужно проверить список перед созданием новой заметки.
Журнал квитанций не очищается автоматически и ограничен 100000 сохранениями на
базу; после лимита доступны прежние CLI-команды. В backup включайте store.db
целиком с квитанциями. Старые версии могут читать базу, но не гарантируют повтор
веб-запросов и не имеют нового редактора.
