# Версионирование mem-tool

Проект использует Semantic Versioning 2.0.0 в формате `MAJOR.MINOR.PATCH`.
Префикс `v` применяется только при отображении и в Git-тегах; каноническое
значение в исходном коде хранится без префикса, например `1.17.0`.

Все поставляемые бинарники одного релиза — `mem`, `mem-index` и `mem-bot` —
используют одну версию из `internal/buildinfo.Version`. Независимые строковые
константы версий в командах запрещены.

## Когда менять номер

- `MAJOR` — несовместимое изменение CLI, формата данных или публичного контракта,
  для которого пользователю нужна явная миграция.
- `MINOR` — новая обратно совместимая функциональность, новая команда, новый
  формат импорта или существенное расширение существующего workflow.
- `PATCH` — обратно совместимое исправление ошибки, безопасности,
  производительности или документации релиза без новой функции.

Примеры:

- `1.17.0 -> 1.17.1`: исправлен сбой `map export-html`;
- `1.17.1 -> 1.18.0`: добавлена новая команда или новый режим карты;
- `1.18.0 -> 2.0.0`: изменён несовместимый формат базы или удалены старые флаги.

Для незавершённых публичных испытаний допустимы prerelease-версии:
`1.18.0-alpha.1`, `1.18.0-beta.1`, `1.18.0-rc.1`. Build metadata вида
`1.18.0+sha.abcdef0` не влияет на порядок версий.

## Процедура выпуска

1. Определить тип изменения: `PATCH`, `MINOR` или `MAJOR`.
2. Обновить `internal/buildinfo.Version` в том же пакете изменений, где появилась
   пользовательская функциональность или исправление.
3. Обновить текущую версию и release notes в `DOCUMENTATION.md`, а при изменении
   команд — также `USAGE_RU.md`.
4. Запустить `go test ./...`, `go vet ./...` и проверку SemVer.
5. Выполнить `deploy/windows.ps1`; скрипт обязан показать одинаковую версию всех
   трёх программ и развернуть их в `C:\Users\ZMII\bin`.
6. Только после успешной проверки создавать коммит/тег и отправлять их в GitHub,
   если пользователь отдельно разрешил эти Git-операции.

Номер версии нельзя повышать только после сборки: версия является частью самого
изменения и должна быть определена до формирования релизного бинарника.
