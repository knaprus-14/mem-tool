# Диагностика пустой модели ответов — alpha.31

11.09.2026. В базе E:\temp\mem-test5 документ SP10.pdf уже импортирован:
интерфейс показывает 129 фрагментов. Лог фиксирует остановки в
`pkg.mem.NewOllamaAnswerProvider`, затем `operation.failed`, до первой порции.
В текущей конфигурации `answer.model` пуст, модель поиска — bge-m3.
Файл mem-tool.log.lock имеет нулевой размер и служит блокировкой журнала;
он не является причиной этой ошибки.

Исправления:

- В разделе графа показана выбранная модель; без неё и при bge-m3 запуск
  блокируется, есть прямой переход в настройки.
- API проверяет модель до добавления задания в очередь. Ошибка возвращается
  как HTTP 400 с безопасным русским пояснением без URL/секретов.
- Старые задания получают конкретное сообщение от worker; повтор запуска
  проверяет текущую модель и редакцию настроек перед возвратом в очередь.
- После изменения настроек требуется новое задание; документ не надо импортировать снова.

Проверки: регрессионные Go-тесты на пустую/embedding-модель, отсутствие записи
в очереди, обработку старого задания, повтор, чужого владельца и HTTP 400 прошли.
Новый JavaScript-тест проверяет блокировку запуска и переход к настройкам;
все шесть тестов graph_documents_test.cjs прошли. Общие `go test ./... -count=1 -timeout=300s`, `go vet ./...`,
проверки синтаксиса JS и git diff --check прошли.

в данной сессии остановилась на `attempt to write a readonly database (8)`;
