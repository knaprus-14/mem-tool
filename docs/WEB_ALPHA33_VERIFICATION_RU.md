# Alpha.33: документ не зависит от безошибочного ответа модели

Дата: 11 сентября 2026 года.

## Диагноз

Последнее задание в E:\temp\mem-test5 остановилось на 56/129. В копии SQLite
сохранены 14 готовых пакетов, пакет 15 failed, пакет 16 pending. В журнале
последняя причина — AnswerTokenLimitError. Сообщение о повторе цитаты из
терминала относится к более раннему запросу и само по себе не объясняет
конечную остановку. До исправления обработчик делил пакеты после ошибок
валидации, но исчерпание бюджета ответа останавливало документ. Публикация
графа ожидала окончания всей порции. Файл mem-tool.log.lock — служебная блокировка.

## Изменение

Полный режим веба и CLI `--all-chunks` использует общий RunKnowledgeDocumentGraph.
Сначала публикуются документ, исходные фрагменты и связи contains. Затем модель
добавляет строго проверенные черновики; derived_from связывает их с документом.
Нет требования подготовить правильный JSON сразу для всей большой порции.

Исходные фрагменты делятся на окна по 6000 символов с перекрытием 256, большие
ответы и превышение контекста дополнительно уменьшают окно. Увеличивать параметры
вручную для полного режима не требуется. Исходный текст и его исходные хеши
не подменяются окнами. После ошибок формы/цитат разрешён один исправляющий запрос.
Предел — 7 обращений на исходное окно, 60 секунд на запрос, 120 секунд на исходный
фрагмент. Два последовательных сбоя сервиса прекращают обращения к нему до
следующего запуска; оставшиеся места получают явные отметки. Отмена и общий
двухчасовой предел сохраняют уже опубликованное.

Таблицы knowledge_document_chunks и knowledge_document_windows хранят состояния
и контрольные точки. Готовый граф публикуется раньше отметки completed; повтор
после аварии безопасен. Одинокая ссылка графа не засчитывает полный смысловой
разбор фрагмента. Повторный запуск сохраняет готовые окна и ручные правки исходных
узлов. Незавершённые места перечислены в покрытии с причинами и координатами.
Счётчики включают также фрагменты, для которых полный разбор ещё не запускался.
Строгий декодер нормативных цитат не изменён.

Добавлены extractor DOCX и текстовый extractor TXT/CSV/TSV/JSON/XML; регистрация
в CLI, очереди веба и файловом выборе. Для текста нет выдуманных физических
страниц; DOCX извлекает текст таблиц, абзацев, сносок и колонтитулов. Неподдерживаемые
элементы DOCX (изображения, формулы Office, диаграммы) требуют проверки и, при
необходимости, экспорта в PDF/OCR. Загрузка ограничена 64 МиБ на файл и 20 файлами
за раз; существующие ограничения веб-базы не сняты. Граф обрабатывает уже извлечённый
текст: повреждение файла, отсутствие OCR-текста или недоступность embeddings при
импорте не превращаются в успешный импорт пустого документа.

## Проверка реальной базы

Исходная база читалась SQLite URI mode=ro и копировалась через backup API в
build/web-alpha/alpha33/repro. Рабочие документы, настройки и база не менялись.
В конце проверки в исходной базе по-прежнему 0 узлов, последнее задание failed 56/129.

1. На копии искусственно возвращался AnswerTokenLimitError для каждого нового
   запроса. Обработка дошла до конца: 129/129 фрагментов в графе, 56 ранее готовых
   сохранены, 73 явно ожидают смыслового разбора. 306 узлов и 229 связей, каждый
   опубликованный источник проверен как current. Это проверка устойчивости,
   а не успешного смыслового извлечения всех фактов.
2. Живая выборка gpt-oss:120b-cloud ограничена тремя запросами. Они заняли 14.2,
   12.3 и 7.8 секунды; полный тест — 36.6 секунды. Приняты ещё два фрагмента:
   смысловой разбор 58/129, остальные 71 сохранены как незавершённые. После третьего
   запроса тест специально имитирует остановку сервиса, чтобы ограничить выборку.
   Это не свидетельство реальной недоступности сервиса на оставшихся страницах.
3. Собранный CLI на копии успешно выполнил --all-chunks --dry-run для document-id
   web:a1c789c0ca8843eea05049da6049cec1 и показал 129 фрагментов; coverage --json
   возвращает места для продолжения. Для загруженного через веб документа нужен
   его document-id либо фактический путь сохранённого источника, не одно имя SP10.pdf.

Материалы в build/web-alpha/alpha33/repro/document-result.json и
live-sample-result.json содержат данные источника и ответы модели; это локальные
тестовые артефакты, не содержимое поставляемых бинарников. Полнота и правильность
смыслового графа всех 129 фрагментов не оценивалась.

## Автоматические проверки

- Неверное числовое требование не публикуется; соседний фрагмент обрабатывается,
  повтор затрагивает только незавершённое место.
- Большой фрагмент более 90 тысяч символов, адаптивное деление по лимиту токенов,
  сохранение исходного текста и продолжение после имитации аварии.
- Все 129 фрагментов при недоступном провайдере, максимум два обращения к сервису.
- Таймаут, отмена, индикация ожидания, ошибка записи прогресса, отсутствие модели.
- Повторный запуск сохраняет ручное название исходного узла.
- TXT/CSV/TSV/JSON/XML сохраняют текст и provenance; DOCX сохраняет абзацы,
  таблицы, сноски, исключает удалённый текст и сообщает об изображениях.
- Очередь и реальный importer для всех шести добавленных расширений с тестовым
  embedding-сервисом; повреждённые и пустые DOCX завершаются явной ошибкой.
- go test ./... -count=1 -timeout=300s, go vet ./..., 32 JavaScript-проверки,
  синтаксис всех JS и git diff --check.

Новая проверка через живой браузер в этой версии не выполнялась. Строгость цитат
подтверждается тестами декодера; она не доказывает полноту извлечения модели.

## Сборка и установка

Все три Windows/amd64 файла находятся в build/web-alpha/alpha33/windows-amd64.
Их версии проверяются командой version, SHA-256 записаны в sha256.json.
Обычный deploy/windows.ps1 остановлен preflight: Access is denied при создании
C:\Users\ZMII\bin\.mem-deploy-probe-245e85ccd72e4138afb2feb1ae1366f2.
Поэтому это подготовленная сборка, не установленный релиз. Проверка настоящих
трёх файлов в C:\Users\ZMII\bin показала alpha.32. Установка требует запуска
обычного deploy/windows.ps1 из пользовательской PowerShell-сессии с доступом
