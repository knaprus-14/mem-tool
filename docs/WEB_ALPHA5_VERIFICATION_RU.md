# Проверка настроек и моделей 1.71.0-alpha.5

Дата: 9 сентября 2026 года. Продолжение этапа 3 общего веб-интерфейса.

## Реализовано

- Редактор выбранной базы: Ollama/Polza и модель поиска, отдельная модель ответов
  Ollama, размер/перекрытие/способ разбиения, таймаут и бюджет ответа.
- Локальный ввод имени модели; серверный список `models` с ролью, backend и именем.
  Текущая модель остаётся доступной для сохранения остальных параметров; новые
  модели должны входить в разрешённый список. Подключение без вариантов отключено
  в серверной форме. Список не является проверкой установки/доступности моделей.
- Явное подтверждение смены embedding-модели без автоматического пересчёта.
  Пустая модель ответов отключает генерацию. Ключ Polza должен быть задан заранее.
- Общая атомарная запись конфигурации, `config.lock` и проверка версии файла,
  прочитанного через LoadConfig/LoadConfigIn. Конфликт веба возвращает HTTP 409.
- Сохранение секретов, адресов, OCR-параметров и неизвестных полей расширений,
  включая вложенные объекты; эти данные не включаются в ответ веб-API.
- Защита клиента от позднего результата сохранения другой выбранной базы/экрана,
  блокирование повторной отправки, статус результата и перечитывание формы.

## Проверки

Успешно выполнены `go test ./... -count=1 -timeout=300s` через `deploy/windows.ps1`,
`go vet ./...`, `node --check internal/webapp/assets/app.js`, `git diff --check`.
Полный цикл тестов и Windows-сборки повторён после заключительного исправления
подписей и устаревшей подсказки. Финальный `pkg/mem` завершился за 33,386 секунды.

Новые регрессионные проверки:

- Два прочитавших клиента: первое сохранение успешно, второе отклоняется без
  изменения файла. Занятая межпроцессная блокировка также отклоняет запись.
- Версия обновляется после сохранения; повторное сохранение и копирование
  конфигурации в другой тестовый каталог работают.
- Неизвестные вложенные поля и скрытые настройки сохраняются, очищенные известные
  поля с `omitempty` не восстанавливаются из старого JSON.
- Локальный и серверный API: сохранение/перечитывание, допустимые модели, неверные
  бюджеты/разбиение, отсутствие подтверждения, устаревшая версия и изменение из CLI.
- Владение базой, анонимный доступ, CSRF, запрет неизвестных полей и методов;
  сервер не принимает произвольную модель вне списка.
- Побайтовое сравнение store.db до/после изменения настроек, сохранность ключа,
  адресов, OCR-пути и температуры, отключение ответов пустой моделью.

## Границы этапа

Сохранение не запускает модели или переиндексацию. Параметры обработки читаются
при запуске задания: ожидающие задания получат новые параметры, выполняющиеся
используют прочитанные. Для старых несовместимых векторов доступен поиск по словам.
Настройки ответа сохраняют диапазоны CLI; веб-ответ дополнительно ограничен
90 секундами модели, 4096 токенами, 48 000 символами контекста и 100 секундами
всего запроса.

Адреса/секреты подключений остаются административной настройкой вне формы.
Список моделей не заменяет полноценные профили подключений и диагностику.
Блокировка работает для клиентов этой версии; старые бинарники и прямые внешние
редакторы её не соблюдают. Конструктор новой Config без прочитанной версии
сохраняет возможность намеренной полной замены. При обычном CLI/TUI/web редактировании
используется проверка прочитанной версии. Схемы SQLite и очереди не изменены.

Редактирование заметок, теги/важность, безопасный пересчёт поколения индекса,
проверка моделей, перенос баз и карты в общей оболочке остаются последующими этапами.
