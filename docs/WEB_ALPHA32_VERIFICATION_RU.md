# Восстановление извлечения SP10 — alpha.32

Дата: 11.09.2026. По скриншоту и чтению SQLite в режиме mode=ro подтверждено:
задание в E:\temp\mem-test5 остановилось на 12-м из 16 пакетов первой порции,
прогресс 44/129. В knowledge_extraction_batches 11 пакетов completed, пакет
с ordinal=11 failed, ещё четыре pending. JSON готовых пакетов сохранён.

Причина остановки: модель gpt-oss:120b-cloud выдаёт неверное размещение/форму
requirement/requirements и несоответствующие исходнику цитаты. Последняя сохранённая
ошибка: во втором одиночном фрагменте первого подпакета цитата statement не прошла
проверку exact nonempty quote. Это ошибка ответа модели; строгая проверка сработала.

## Изменение

В runtime-запрос добавлена явная схема: requirement только у нормативного узла
nodes[i], никогда у корня/связи; statement — объект, остальные части — массивы
объектов citation_id/text. Список citations должен соответствовать реально
процитированным частям. Коррекция различает unknown field, форму, лишние citations
и несовпадение дословной цитаты. Для небольшого ответа/отклонённого узла в повтор
добавляется ограниченный недоверенный кандидат; он не принимается без декодирования.

Строгий декодер и сопоставление исходных цитат НЕ изменялись. Нет исправления слов,
чисел, знаков или автоматического приведения неверной схемы к допустимой.
Дополнительные инструкции передаются при исполнении; исходные System/User плана,
batch IDs и сохранённые digests не изменены. Это сохраняет возможность продолжения.

Веб-сообщение при отклонении содержит номер пакета, сохранённый прогресс и действие
«Продолжить». Пояснено, что покрытие/узлы появляются после публикации всей порции;
готовые пакеты до этого находятся в контрольных точках.

## Продолжение пользователем

После установки alpha.32 перезапустить mem gui и нажать «Продолжить» у задания
44/129. Смена модели/настроек для этого исправления не нужна. Уже сохранённые 11
пакетов не генерируются заново. Непринятые подпакеты внутри ошибочного 12-го пакета
могут запрашиваться повторно: постоянная контрольная точка сохраняется на границе
целого пакета, не каждого рекурсивного подпакета.
