# Проверяемость требований и сверка с источниками

Релиз: 1.71.0-alpha.28.

## Извлечение

Для нормативных узлов `claim`, `constraint`, `procedure` запрос модели предлагает
структуру `requirement`: обязательная `statement` и массивы `conditions`,
`exceptions`, `limits`. Каждая часть — `{citation_id, text}` с дословной цитатой
из переданного модели фрагмента. Сервер отклоняет выдуманные цитаты, чужие
ссылки, пустую основную формулировку и более 32 частей. Числа и единицы не
пересчитываются. Неоконченные требования предлагается не извлекать.

Проверенные части преобразуются в читаемый текст узла с подписями; отдельной
дублирующей схемы хранения нет. Поэтому редактирование, история, контроль
изменения текста, экспорт и учебные карточки получают эти части через прежнее
поле `body`. Источники содержат точные выдержки и их хеши. Замена `body` из
ответа модели исключает попадание непроверенной свободной трактовки в этот
формат; название и смысл классификации всё ещё требуют проверки человеком.

Старые ответы без `requirement` читаются по-прежнему. Новое указание в запросе
не гарантирует, что модель найдёт все условия: проверка подтверждает присутствие
выбранных цитат, но не полноту выбора и не их трактовку. Все новые узлы — draft.
Существующий граф и подтверждения пользователя автоматически не переписываются.

## Сверка

Кнопка «СВЕРИТЬ С ИСТОЧНИКОМ» находится во вкладке «Источники» узла или связи
расширенного графа, в том числе внутри `mem gui`. Она открывает широкое окно
с независимой прокруткой формулировки и источника. При работающем сервере
загружается полный импортированный чанк; сохранённая выдержка выделяется.
Список объектов из того же чанка позволяет вернуться от документа к графу.

Контекст выдаётся по citation ID через прежний защищённый `/api/source` с
`format=text`, с проверкой принадлежности графу, актуальности версии и хеша
текста. Произвольный путь клиента не принимается. Для PDF остаётся отдельная
проверяемая ссылка на физическую страницу. Это ещё не выделение прямоугольника
на странице PDF и не просмотр полного документа внутри окна.

Если источник устарел, остаётся только сохранённая выдержка с предупреждением.
Текст из базы соответствует импортированной редакции; проверка самого файла PDF
выполняется при его открытии. Статический HTML работает с сохранённой выдержкой.

## Оценка по эталону

`mem map eval-labeled` поддерживает поле `required_fragments` каждого ожидаемого
утверждения: до 32 непустых фрагментов, все обязательны. Они сравниваются с
нормализацией регистра и пробельных последовательностей. `aliases` задаёт
проверенные человеком перефразирования; оно не отменяет обязательные фрагменты.

Перед оценкой похожести проверяются критические лексические маркеры: отрицания,
некоторые условия/исключения, пределы, числовые значения, распространённые единицы,
знаки сравнений. Десятичная запятая и точка считаются эквивалентными. При наличии
`body` сравнивается он: совпадение короткого названия больше не скрывает потерю
условия в основном тексте. Из-за этого старые оценки могут стать ниже.

Это консервативный фильтр. Он может отвергать правильные перефразирования и не
обнаруживает все смысловые ошибки (например, перемену субъектов или перестановку
одинаковых чисел между объектами). Он не заменяет размеченный эталон и review.
Точность всего корпуса нельзя вычислять по неполной выборке ожидаемых утверждений.

## Проверка реального материала

С разрешения пользователя получен согласованный снимок `E:\temp\mem-test4`
через SQLite backup из read-only соединения. Оригинал не изменялся; модели не
вызывались. Снимок содержит два PDF, 501 чанк, 1030 узлов и 890 связей.

Проверены семь конкретных фрагментов в пяти узлах СП485: три сохранены в тексте,
четыре отсутствуют. Два отсутствующих фрагмента относятся к одному исключению.
Таким образом, найдены три узла для смыслового review: исключение для агрегатных
АУП-ТРВ-ВД (физическая стр. 44), закрытие противопожарных клапанов (75), требуемый
уровень взрывозащиты (68). Это целевая диагностическая выборка, не процент
достоверности графа и не независимая оценка ответа нейросети.

Частный протокол с исходными выдержками хранится в игнорируемом
`build/web-alpha/alpha28/real-qualifiers-audit.json`. Повторение проверки:

```powershell
$env:MEM_GRAPH_REQUIREMENT_AUDIT = Join-Path $PWD 'build/web-alpha/alpha28/real-qualifiers-audit.json'
go test ./pkg/mem -run TestKnowledgeRequirementRealAuditReplay -v -count=1
Remove-Item Env:MEM_GRAPH_REQUIREMENT_AUDIT
```

Этот тест воспроизводит проверку обязательных фрагментов, не обращаясь к базе
или модели. Без переменной он пропускается; частные данные не входят в исходники.
