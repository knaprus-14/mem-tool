## О проекте

**mem-tool** — это консольная утилита для работы с векторной базой знаний. Она позволяет сохранять текстовые заметки, факты и документы, а затем искать их не по точному совпадению слов, а **по смыслу** (семантический поиск).

Зачем это нужно?
- Вы работаете с AI-ассистентом (Claude, ChatGPT) и накапливаете факты, IP-адреса, команды, архитектурные решения
- Через месяц вы помните, что «там было что-то про сервер», но не помните точных слов
- mem-tool находит запись по смыслу, даже если слова в запросе и в записи не совпадают

Пример:
```
> mem add "Сервер работает на Ubuntu 22.04, Go 1.22, SQLite" -title "VDS конфигурация" -tags "сервер,ubuntu"
> mem search "какая ось на вдс"
  [~] #15 [74%] VDS конфигурация (2026-07-26)
      Сервер работает на Ubuntu 22.04, Go 1.22, SQLite
```

## Как создавался mem-tool

Проект создавался итеративно, от простого к сложному. Каждая версия добавляла новую возможность без поломки предыдущих.

### Версия 1.0 — Основа
Первая версия умела только три вещи:
- `mem add "текст"` — сохранить запись
- `mem search "запрос"` — найти по смыслу
- `mem recent` — показать последние

Текст превращался в вектор (эмбеддинг) через локальную модель **bge-m3** в Ollama, поиск работал по косинусной близости векторов. Хранилище — простой JSONL-файл (одна JSON-строка на запись).

**Почему JSONL?** Это append-only формат: новые записи добавляются в конец файла. Не нужно блокировать базу, нет сложных схем. Для личной базы знаний — идеально.

### Версия 1.1 — Документы и чанкинг
Добавлена работа с файлами и большими документами:
- `mem add-file file.txt` — сохранить файл
- `mem index ./папка/` — проиндексировать папку
- **Чанкинг**: большие документы автоматически разбиваются на куски (чанки)
- Поддержка .txt, .md, .csv, .json, .pdf
- Source-команды: `mem source <id>` и `mem sources`

**Проблема с PDF:** PDF читается двумя способами — через `pdftotext` (poppler-utils) или через Python-скрипт с библиотекой pdfminer.

### Версия 1.2 — Заголовки записей
Раньше записи были безымянными. Теперь у каждой записи может быть заголовок:
- `mem add "текст" -title "Название"`
- В результатах поиска заголовок показывается первой строкой
- В `mem recent` заголовок вместо обрезанного текста
- Если заголовка нет — пишет «(без заголовка)»

### Версия 1.3 — Версия и авторские права
Добавлено отображение версии:
- `mem version` — краткая информация
- `mem` без параметров — версия + справка
- Копирайт: «(c) 2026 Кнап Руслан Юрьевич»

### Версия 1.4 — Фильтр по тегам при поиске
Теги работали только при добавлении, теперь и при поиске:
- `mem search "сервер" -tags "инфраструктура"`
- Фильтр AND-подобный: показываются записи, содержащие хотя бы один из указанных тегов
- Сравнение регистронезависимое

### Версия 1.5 — Фильтр по дате
Поиск во временном диапазоне:
- `mem search "сервер" -from 2026-06-01 -to 2026-07-01`
- Формат даты: YYYY-MM-DD
- Дата создания хранится в RFC3339, при фильтрации парсится

### Версия 1.6 — Порог релевантности (min-score)
Отсев нерелевантных результатов:
- `mem search "сервер" -min-score 0.5`
- По умолчанию 0.0 (не фильтровать)
- Применяется ПОСЛЕ всех бустов (гибрид + реранжирование)

### Версия 1.7 — Гибридный поиск
Векторный поиск находит по смыслу, но пропускает точные совпадения. Гибридный поиск комбинирует оба подхода:

| Что проверяется | Бонус к score |
|----------------|---------------|
| Запрос найден в тексте записи | +0.15 |
| Запрос найден в заголовке | +0.30 |
| Запрос найден в тегах | +0.20 |
| **Максимум** | **1.0** (кап) |

Включён по умолчанию. Отключить: `-vector-only`

### Версия 1.8 — Re-ranking (повторное ранжирование)
После гибридного поиска оценки докручиваются:

| Фактор | Множитель |
|--------|-----------|
| Запись создана менее 7 дней назад | ×1.05 |
| Теги пересекаются со словами запроса | ×1.10 |

Re-ranking не радикально меняет порядок, а лишь «подтягивает» свежие записи и записи с совпавшими тегами.

### Версия 1.9 — Удаление и редактирование
Добавлено управление записями:
- `mem delete <id>` — удалить (безвозвратно, перезапись JSONL)
- `mem edit <id> "новый текст" [-title "Заголовок"]` — изменить (с переэмбеддингом)
- `mem retag <id> -tags "новые,теги"` — изменить теги

### Версия 1.9 — Флаг важности
- `mem add "текст" -important` — пометить как важную при создании
- `mem important <id>` / `mem imp <id>` — переключить флаг
- Важные записи получают буст ×1.15 в реранжировании
- Отображаются с маркером `[!]` везде: search, source, recent

## Архитектура

### Общая схема работы

```
Пользователь → CLI (main.go) → Хранилище (store.go)
                                  ↕
                              JSONL-файл
                                  ↕
                            Эмбеддинги (embed.go)
                                  ↕
                         Ollama / Polza AI API
```

### Хранилище (store.go)

**Формат:** JSONL (JSON Lines) — текстовый файл, где каждая строка — это один JSON-объект.

Структура одной записи в файле:
```json
{
  "id": 15,
  "title": "VDS конфигурация",
  "text": "Сервер работает на Ubuntu 22.04, Go 1.22, SQLite",
  "tags": ["сервер", "ubuntu"],
  "created": "2026-07-26T10:30:00Z",
  "backend": "ollama",
  "dims": 1024,
  "embedding": [0.012, -0.034, ...],
  "source_file": "настройка.txt",
  "chunk_label": "Раздел 2: Установка",
  "chunk_index": 0,
  "total_chunks": 3,
  "important": true
}
```

**Важно:** эмбеддинг хранится прямо в JSON. Это делает файл самодостаточным — не нужно отдельной базы векторов.

**Принцип удаления:** запись помечается `deleted: true` в памяти, затем файл перезаписывается без неё. Никаких tombstone-записей в JSONL.

**Принцип редактирования:** при загрузке файла (`load()`) если встречаются две записи с одинаковым ID — последняя заменяет первую. Это позволяет «редактировать» append-only формат: новая версия записи перезаписывает старую при следующей загрузке.

### Поиск (search)

1. **Векторный поиск:** запрос → эмбеддинг → косинусная близость со всеми записями → сортировка → топ-N
2. **Фильтры** (применяются к результатам векторного поиска):
   - По тегам (`-tags`)
   - По дате (`-from`, `-to`)
3. **Гибридный буст:** полнотекстовые бонусы к векторным оценкам
4. **Re-ranking:** свежесть → совпадение тегов → важность
5. **Min-score:** отсев по порогу
6. **Вывод**

### Эмбеддинги (embed.go)

Два бэкенда:
- **Ollama** (по умолчанию): `bge-m3`, размер вектора 1024, работает локально
- **Polza AI**: OpenAI-совместимый API, размер вектора 1536

Настройка: `mem config set-backend polza` + `mem config set-polza-key <key>`

### Чанкинг (chunk.go)

Большие документы разбиваются на фрагменты. Три стратегии:

| Стратегия | Как режет | Когда использовать |
|-----------|-----------|-------------------|
| `paragraph` (по умолчанию) | По абзацам (двойной перенос строки) | Документы с чёткой структурой |
| `sentence` | По предложениям | Исходный код, списки |
| `fixed` | Фиксированный размер с перекрытием | Когда структура не важна |

Настройка:
```
mem config set-chunk-size 800    # размер чанка в символах (100-10000)
mem config set-chunk-overlap 100 # перекрытие между чанками
mem config set-chunk-strategy sentence
```

Если абзац больше maxSize — он дробится на предложения внутри себя.

**Важно:** Если PDF-извлечение выдаёт текст без границ предложений (нет точек с заглавными буквами), `splitSentences` может не найти, где разорвать. В этом случае предложение режется **фиксированно** — по символам с разрывом по пробелам. Это гарантирует, что ни один чанк не превысит `maxSize` и не вызовет ошибку `"input length exceeds the context length"` в Ollama.

Дополнительная защита в `embed.go`: перед отправкой текста в модель он урезается до 2000 рун. Это safety net на случай, если чанкинг по какой-то причине пропустит слишком длинный текст.

## Полное описание команд

### `mem add <текст>`

Сохранить новую запись.

```powershell
mem add "Сервер: 157.22.196.67"
mem add "Пароль: admin123" -title "Пароль админки" -tags "пароли,администрирование" -important
```

**Флаги:**
| Флаг | Описание |
|------|----------|
| `-title "Название"` | Заголовок записи |
| `-tags "тег1,тег2"` | Теги (через запятую) |
| `-important` | Пометка как важной |

### `mem search <запрос>`

Поиск по смыслу.

```powershell
mem search "какой ip у сервера"
mem search "архитектура" -tags "документация" -from 2026-06-01 -to 2026-07-26
mem search "сервер" -min-score 0.5 -vector-only
```

**Флаги:**
| Флаг | Описание |
|------|----------|
| `-limit N` | Количество результатов (по умолч. 10) |
| `-tags "тег1,тег2"` | Фильтр по тегам |
| `-from 2026-01-01` | Начало диапазона дат |
| `-to 2026-07-01` | Конец диапазона дат |
| `-min-score 0.5` | Порог релевантности (0.0–1.0) |
| `-vector-only` | Только векторный поиск, без гибридного буста |

**Форматы результатов:**
```
[ ] #6 [49%] (без заголовка) (2026-07-25)
   Текст записи...
   [FILE] архитектура.txt | Раздел 3: Авторизация и безопасность | 2/2
   [TAG] документация, архитектура

[~] #15 [74%] VDS конфигурация (2026-07-26)
   Сервер работает на Ubuntu 22.04, Go 1.22, SQLite
   [TAG] сервер, ubuntu

[*] #19 [100%] Боевой сервер (2026-07-26) [!]
   Важная запись: боевой сервер ...
   [TAG] сервер, инфраструктура, важно
```

**Маркеры релевантности:**
- `[*]` — >90% (высокая релевантность)
- `[~]` — >70% (средняя)
- `[ ]` — ≤70% (низкая)
- `[!]` — запись помечена как важная

### `mem recent`

Последние записи.

```powershell
mem recent         # последние 10
mem recent -limit 5
```

### `mem add-file <путь>`

Сохранить содержимое файла. Большие файлы автоматически разбиваются на чанки.

```powershell
mem add-file ./настройка.txt -tags "документация,сервер"
mem add-file ./README.md -important
```

### `mem index <путь>`

Проиндексировать все поддерживаемые файлы в папке (рекурсивно).

```powershell
mem index ./проекты/
mem index C:\МоиДокументы\
```

Поддерживаемые расширения: `.txt`, `.md`, `.csv`, `.json`, `.pdf`

### `mem source <id>`

Детальная информация о записи: полный текст, источник, теги, дата, бэкенд.

```powershell
mem source 15
```

### `mem sources`

Список всех проиндексированных документов с количеством чанков.

### `mem delete <id>` / `mem rm <id>`

Удалить запись (безвозвратно).

```powershell
mem delete 12
```

### `mem edit <id> <новый текст>`

Изменить текст и/или заголовок записи.

```powershell
mem edit 15 "Новый IP: 10.0.0.2"
mem edit 15 -title "Новый заголовок"           # только заголовок
mem edit 15 "Новый текст" -title "Новый заг."  # и текст, и заголовок
```

Если текст изменился — эмбеддинг пересчитывается автоматически.

### `mem retag <id> -tags "новые,теги"`

Заменить теги записи (старые теги теряются).

```powershell
mem retag 5 -tags "сервер,ubuntu,важно"
```

### `mem important <id>` / `mem imp <id>`

Переключить флаг важности записи.

```powershell
mem important 15   # помечает как важную или снимает пометку
```

### `mem stats`

Статистика базы: всего записей, по бэкендам, расположение файла.

### `mem config`

Управление конфигурацией.

```powershell
mem config                               # показать текущую конфигурацию
mem config set-backend ollama            # переключить на Ollama
mem config set-backend polza             # переключить на Polza AI
mem config set-polza-key "sk-..."        # установить API-ключ Polza
mem config set-polza-model "text-embedding-3-small"
mem config set-ollama-model "bge-m3"     # установить модель Ollama
mem config set-chunk-size 800            # размер чанка
mem config set-chunk-overlap 100         # перекрытие чанков
mem config set-chunk-strategy sentence   # стратегия чанкинга
```

### `mem version`

Показать версию и копирайт.

### `mem help`

Показать справку.

## Конфигурация

Файл: `C:\Users\ZMII\.mem\config.json`

```json
{
  "backend": "ollama",
  "store_path": "C:\\Users\\ZMII\\.mem",
  "ollama": {
    "model": "bge-m3",
    "url": "http://localhost:11434"
  },
  "polza": {
    "api_key": "",
    "model": "text-embedding-3-small",
    "url": "https://api.polza.com/v1"
  },
  "chunking": {
    "max_size": 1000,
    "overlap": 100,
    "strategy": "paragraph"
  }
}
```

### Параметры

| Параметр | По умолчанию | Описание |
|----------|-------------|----------|
| `backend` | `ollama` | Бэкенд эмбеддингов: `ollama` или `polza` |
| `chunking.max_size` | 1000 | Максимальный размер чанка в символах (100–10000) |
| `chunking.overlap` | 100 | Перекрытие между чанками (0–1000) |
| `chunking.strategy` | `paragraph` | Стратегия: `paragraph`, `sentence`, `fixed` |

## Формат данных

Хранилище — `store.jsonl` в директории `~/.mem/`. Каждая строка — JSON-объект:

```json
{"id":1,"title":"Пример","text":"Текст записи","tags":["тег1"],"created":"2026-07-26T10:00:00Z","backend":"ollama","dims":1024,"embedding":[...]}
```

**Поля в JSONL:**
| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer | Уникальный номер записи |
| `title` | string (optional) | Заголовок |
| `text` | string | Текст записи |
| `tags` | array of strings (optional) | Теги |
| `created` | string | Дата в RFC3339 |
| `backend` | string | Бэкенд эмбеддинга |
| `dims` | integer | Размерность вектора |
| `embedding` | array of floats | Вектор (эмбеддинг) |
| `deleted` | bool (optional) | Признак удаления |
| `important` | bool (optional) | Флаг важности |
| `source_file` | string (optional) | Исходный файл (для документов) |
| `chunk_label` | string (optional) | Описание чанка |
| `chunk_index` | int (optional) | Номер чанка |
| `total_chunks` | int (optional) | Всего чанков |

## Советы

1. **Используйте заголовки.** Запись с заголовком гораздо понятнее в результатах поиска.
2. **Тегируйте осмысленно.** Теги — основной способ фильтрации. Не бойтесь добавлять много тегов.
3. **Важное помечайте `-important`.** Пароли, ключи, критичные IP — сразу ставьте флаг.
4. **Крупные документы индексируйте через `mem index`.** Чанкинг разобьёт их на куски, каждый будет доступен для поиска отдельно.
5. **Не удаляйте бездумно.** `mem delete` стирает запись навсегда (перезапись JSONL).
6. **Редактирование пересчитывает эмбеддинг.** Если вы просто меняете заголовок — эмбеддинг остаётся старым (текст не изменился).
7. **Резервируйте store.jsonl.** Это простой текстовый файл. Можете закоммитить его в Git или скопировать в облако.

- **my-site** (https://github.com/knaprus/my-site) — веб-приложение на Go + HTMX, для которого изначально задумывался mem-tool
- **Ollama** (https://ollama.ai) — локальный запуск LLM и эмбеддингов
- **Polza AI** (https://polza.com) — API для эмбеддингов (альтернатива Ollama)

---

## Файлы проекта

| Файл | Описание |
|------|----------|
| `main.go` | Главный файл: CLI, флаги, команды, вывод |
| `store.go` | Хранилище: Entry, JSONL, CRUD, поиск |
| `embed.go` | Эмбеддинги: Ollama и Polza бэкенды |
| `chunk.go` | Чанкинг: разбивка документов на фрагменты |
| `indexer.go` | Индексация: обход папок, чтение файлов |
| `config.go` | Конфигурация: загрузка/сохранение JSON |
| `DOCUMENTATION.md` | Этот файл |
