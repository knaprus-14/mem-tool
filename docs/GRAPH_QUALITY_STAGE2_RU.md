## Выявленные проблемы и изменения

Первый прогон выявил массивы строк вместо объектов requirement, отличие
пробелов PDF-цитаты от оригинала, а также обрезанный/невалидный JSON.
В рабочей цепочке страница 44 при 8192 токенах потребовала повтор с 16384
и завершилась тайм-аутом. Этот неуспех сохранён в отчётах.

В промпте теперь есть заполненные примеры объектов условий/исключений/лимитов,
а исправляющий повтор объясняет их форму. При сокращении ответа цитаты
требований исключены из инструкции сокращать обычный body. Это инструкция
модели, не гарантия её соблюдения. Прежние ответы без requirement остаются
совместимыми и требуют обычной проверки человеком.

Разрешено только однозначное сопоставление цитаты при отличиях пробельных
символов; сохранены исходные байты текста и хеши. Изменение чисел, регистра,
отрицания или пунктуации не исправляется автоматически.

Размеченная оценка поддерживает optional `matching.claim_kinds`:
`claim`, `constraint`, `procedure`. Без него оцениваются только claim.
Полный body участвует в оценке, даже если условие находится после 4096 символов.
Повторённая отдельным полем цитата ограничения не ухудшает текстовое сходство,
если каждый дополнительный фрагмент уже дословно присутствует в требовании.
Новые условия и неизвестные поля не отбрасываются; защитные проверки всегда
читают полный body. Это лексическая проверка, не доказательство эквивалентности.

Четыре контрольных требования составлены из текста источника: 6.9.1, 6.9.2,
10.1.2 и первое предложение 11.2.9. Обязательные фрагменты включают исключение
для АУП-ТРВ-ВД, категорию надёжности, условия взрывозащиты и задержку не менее
10 секунд. Эталон не подгонялся под формулировки ответа модели.

Повторная офлайн-проверка последних ответов каждой страницы: **4/4** требований
найдены среди 30 узлов подходящих типов. Выборка не размечает все требования
страниц, не измеряет точность всех узлов/связей и не подтверждает полноту СП485.
Экспертная независимая разметка ещё необходима для общей оценки качества.

Локальные артефакты в копии базы:

- `requirements.manifest.json` — четыре контрольных требования и источники;
- `benchmark/*.json` — промпты, сырые ответы, ошибки и декодированные графы;
- `control-requirements-report.json` — последнее офлайн-сопоставление.

Эти артефакты содержат текст источников, находятся в игнорируемом build,
не включены в поставку и отличаются от обезличенного системного журнала.

## Повторение проверки

Обычный `go test` пропускает сетевой эксперимент. Для проверки сохранённых
ответов из корня репозитория (без вызовов модели):

```powershell
$env:MEM_GRAPH_BENCHMARK_REPLAY = Join-Path $PWD 'build/web-alpha/alpha29/real-corpus'
try {
    go test ./pkg/mem -run '^TestKnowledgeRequirementBenchmarkEvaluation$' -v -count=1
} finally {
    Remove-Item Env:MEM_GRAPH_BENCHMARK_REPLAY
}
```

Для нового вызова существующей модели требуется явно
задать `MEM_GRAPH_LIVE_BENCHMARK` путём к одноразовой копии базы и запустить
`TestKnowledgeLiveRequirementBenchmark`. Тест предназначен для этого корпуса
и сохраняет новые ответы; дальнейшая офлайн-проверка выбирает последние по
времени, включая неудачи. Не запускайте его на оригинале базы.
