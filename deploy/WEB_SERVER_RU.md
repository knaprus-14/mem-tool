# Веб-сервис mem-tool на VDS

Состояние: подготовка и локальные проверки 1.71.0-alpha.27. Сервис на VDS
не установлен. Это отдельное приложение `mem serve`, использующее то же ядро,
что CLI/TUI. Прежние команды `mindmap open` и `map open` сохраняются.

## Схема размещения

Браузер → nginx с HTTPS → `127.0.0.1:8765` → процесс `mem serve` →
каталог `/var/lib/mem-tool`. Очередь и оригиналы находятся рядом с базами.
Сервис запускается от отдельного пользователя `memtool`, секрет входа берётся
из переменной окружения, базы принадлежат конкретному пользователю.

Используйте `mem-web.service`, `web-server.example.json` и `mem-web.nginx.conf`
как шаблоны. До запуска замените пример домена, пути сертификатов и список
моделей. Поле `public_origin` должно точно совпадать с адресом в браузере;
размещайте приложение на отдельном поддомене, в корне `/`.

В `/etc/mem-tool/web.env` задаётся `MEM_WEB_OWNER_TOKEN` длиной не менее 32 символов.
Файл доступен только администратору/группе сервиса. Не помещайте его в Git
или каталог веб-статики. Вход — имя `owner` и этот токен; токен не выводится
в командной строке или диагностике. Настройки моделей разрешает администратор,
веб-формы не принимают адреса серверов, ключи или исполняемые команды.

PDF/DjVu/OCR требуют доступных на VDS инструментов, перечисленных в основном
руководстве. Их наличие и версии нужно проверить на самом сервере. Шаблоны
не устанавливают инструменты, модели или зависимости автоматически.

## Проверка перед внешним доступом

После установки Linux-сборки нужной версии и настройки службы:

```bash
/opt/mem-tool/current/mem version
sudo systemd-analyze verify /etc/systemd/system/mem-web.service
sudo nginx -t
sudo systemctl daemon-reload
sudo systemctl start mem-web.service
curl --fail --header 'Host: mem.example.org' http://127.0.0.1:8765/healthz
curl --fail https://mem.example.org/readyz
```

Проверьте вход, создание отдельной тестовой базы, загрузку Markdown, повтор
той же загрузки, обработку, поиск, карту и перезапуск службы. Проверьте
изолированного второго пользователя и отсутствие доступа к его API/файлам.
Cookie должен иметь `Secure`, `HttpOnly`, `SameSite=Strict`; запросы с другим
Host/Origin отклоняются. Порт 8765 наружу не публикуется.

Базовые лимиты уже работают: 64 МиБ на файл, 1 ГиБ оригиналов и 1000 оригиналов
на базу, 20 активных заданий, два одновременных интерактивных запроса в процессе.
Это не общая квота диска: SQLite, OCR и история также занимают место. До
многопользовательского выпуска задайте ограничения файловой системы/раздела
и наблюдайте свободное место, память и время запросов на реальном корпусе.

## Резервное копирование остановленного сервиса

`web_backup.py` работает на Python 3.10+ без сторонних пакетов. Он архивирует
управляемый каталог сервиса, проверяет каждую SQLite-базу, SHA-256 всех файлов
и пробное распаковывание. До начала должны быть остановлены все пишущие
процессы, включая CLI/ботов, если они используют те же базы. Повторное чтение
файлов обнаруживает изменения во время копирования, но не заменяет остановку.

```bash
sudo systemctl stop mem-web.service
sudo python3 /opt/mem-tool/tools/web_backup.py backup \
  --data /var/lib/mem-tool \
  --output /var/backups/mem-tool/manual-20260909.zip --writers-stopped
sudo systemctl start mem-web.service
sudo python3 /opt/mem-tool/tools/web_backup.py verify \
  /var/backups/mem-tool/manual-20260909.zip
```

Каталог назначения должен существовать. Архив содержит приватные документы,
настройки базы и, если они там сохранены, ключи моделей. Храните его вне сайта
с ограниченным доступом; внешнее зашифрованное хранение настраивается отдельно.
`/etc/mem-tool` не входит в архив — конфигурацию службы и секреты обслуживает
администратор отдельно. Ссылки/reparse points и внешние базы каталога отклоняются.
Внешние файлы, когда-либо привязанные в локальном редакторе, не копируются:
сохраняются их ссылки и цитаты. Лимит утилиты — 100000 файлов / 100 ГиБ;
для проверки нужно дополнительное место размером с распакованные данные.

Для расписания разместите `web-backup.sh` и `web_backup.py` в
`/opt/mem-tool/tools`, принадлежащем root, и установите оба шаблона
`mem-web-backup.service` / `mem-web-backup.timer`. Скрипт останавливает службу
и через trap возвращает её, если она была запущена. Он не удаляет старые архивы.
Настройте удержание/свободное место, уведомления systemd и сначала выполните
один ручной запуск. Таймер по умолчанию — 03:30 по времени сервера с задержкой
до 15 минут; это окно недоступности сервиса.

## Пробное и аварийное восстановление

```bash
sudo python3 /opt/mem-tool/tools/web_backup.py restore \
  /var/backups/mem-tool/manual-20260909.zip \
  --destination /var/lib/mem-tool-recovery-check
```

Каталог назначения не должен существовать. Утилита проверяет архив в соседнем
временном каталоге и только после успеха переименовывает его. Живые данные
не перезаписываются. Контрольные суммы/SQLite проверяются до передачи результата.

Это аварийная копия для восстановления **по прежним абсолютным путям**.
В пробном каталоге проверяются содержимое и целостность; запускать оттуда
сервис нельзя: каталог баз ещё ссылается на исходные пути. Для аварийной замены
сначала остановите все процессы, сохраните неисправный каталог под отдельным
именем и восстановите архив точно на прежнее место. Затем восстановите
владельца `memtool`, административные настройки и запустите совместимую версию.
Автоматического переноса путей Windows → Linux эта утилита не выполняет.

Откат бинарника допустим только при совместимости схемы. Перед обновлением
сохраняйте и архив, и предыдущую сборку; при несовместимой схеме откатывайте
вместе данные и бинарник. Сначала проверяйте восстановление на отдельном VDS
с теми же путями, без подключения к рабочему каталогу.

## Что проверено в текущей среде

Автотесты Go проверяют Host/Origin/CSRF, владельцев, задания, ревизии и новые
операции карт. Python-тесты проверяют копию/восстановление, запрет перезаписи,
повреждённый SHA-256, лишние/повторяющиеся пути и повреждённую SQLite-базу.
Проверка реального nginx/systemd/Linux не выполнена: WSL в этой сессии отвечает
`Wsl/EnumerateDistros/Service/E_ACCESSDENIED`. Конфигурации остаются шаблонами
до указанных серверных проверок. Полный паритет команд графа/AI и перенос
источников между ОС остаются в `docs/WEB_ROADMAP_RU.md`.


## Дополнение alpha.27: перенос и место

См. [перенос базы и квоты](../docs/WEB_COMPLETION_RU.md). Новые параметры:
`max_workspace_bytes` (по умолчанию 4294967296), `max_user_bytes` (17179869184).
Обновите nginx-конфигурацию с лимитом 2 ГиБ для импорта переносимого ZIP.
Модели архива должны быть разрешены в `models`; ключи и адреса подключений
на целевом сервере настраиваются заново. Для жёсткого дискового ограничения
используйте квоты ОС; резервируйте временное место для снимка и архива.
