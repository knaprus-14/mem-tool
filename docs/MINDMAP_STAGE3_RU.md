## Работа с оригиналом

1. В документе создайте текстовую аннотацию или откройте существующую.
2. Нажмите «Области PDF», затем «Показать оригинальную страницу».
3. Выделите прямоугольник либо задайте слева/сверху/ширину/высоту в процентах.
4. Сохраните область. Её координаты, страница, автор и hash файла записываются в базу.

Страница строится из проверенной закрытой копии PDF. Требуется установленный
рендерер из настроек импорта; программа не устанавливает инструменты. При
подменённом, недоступном или непроверенном оригинале нельзя сохранить видимость
подтверждённой области. Текстовая цитата и её история остаются доступны.
Для области доступны добавление и просмотр; редактирования/удаления области нет.
Архивирование всей аннотации сохраняет данные. До 100 областей на запись и 10000
на базу; координаты нормализованы относительно физической страницы.

## Перенос и происхождение

«Экспорт аннотации» сохраняет одну открытую запись. JSON содержит логический
идентификатор документа, редакцию, координаты фрагмента, точную цитату, контекст,
комментарий, цвет, архивный статус и области. Абсолютных путей и внутренних ID
строк нет. API позволяет выбрать несколько записей явно. Markdown предназначен
для чтения, а не обратного импорта.

Импорт сначала показывает совпадения и предупреждения. Подтверждение закреплено
за проверенным файлом и состоянием локальных источников. При изменении основания
требуется новый просмотр. Недоступная или неоднозначная привязка сохраняется в
архиве без автоматического открытия файла. Автор и даты из чужого пакета остаются
внешними метаданными; фактический импортёр и происхождение записаны отдельно.
Смена компьютера сама по себе не подтверждает источник.

Перепривязка создаёт новую аннотацию с новой цитатой, переносит сохранённый
комментарий и цвет и записывает автора операции. Старую запись не изменяет.
Области PDF и связи карт остаются у старой записи: их перенос требует отдельного
осмысленного решения. История перепривязок позволяет открыть обе записи.
Повтор отправки использует прежний идентификатор. После перезагрузки браузера
сначала проверьте сохранённые записи: черновики отправки хранятся в памяти вкладки.

## Из цитаты в граф знаний

В сохранённой аннотации откройте «Объекты графа». Выберите тип — заметка, вопрос,
карточка, гипотеза, решение или задача — и введите собственное название и текст.
Создаётся ручной черновик с точной цитатой. Он не получает статус проверенного
только потому, что создан человеком. Ссылка открывает конкретный узел графа;
в его действиях «Аннотации источника» возвращает к сохранённой цитате.

Связь хранит автора, исходные ревизию аннотации и содержание узла. Список
различает снимок при создании и текущее состояние. Последующие правки заметки
не переписывают автоматически body узла, а его редактирование не изменяет цитату.
Недоступный узел не стирает историю связи. До 1000 связей на аннотацию, 10000
и 64 МиБ на базу. Новый нативный пакет со всей историей и такими связями ещё
не реализован: простой JSON аннотаций переносит только сами аннотации и области.

## Программа M0–M6

Этот выпуск закрывает связанные части SRC03/SRC04, TRU03/TRU09, NAV06, AI03
и обмена аннотациями. Он не завершает весь каталог из 120 направлений.
Для каждого пункта необходимо отдельно различать существующий код, реализованное
расширение и выполненную приёмку. Условия M3 требуют отложенного размеченного
корпуса и сравнения с baseline; M4 требует учебного пилота. Автоматические тесты
не являются результатом этих экспериментов.

Итоговый реестр содержит все 120 исходных критериев: 28 реализованы по коду
с указанными проверками, 68 выполнены частично, 16 пока не реализованы,
8 требуют эмпирической приёмки. Эти оценки не означают завершения M0–M6.
Среди оставшихся задач — общий слой понятий для видов карты, сохранение контекста
чтения, редактируемый outline, перенос всей базы объектов с прежними ID и историей,
единая учебная история с ответом до раскрытия, совместная проверка и независимая
оценка качества на корпусе документов. У каждого пункта в реестре сохранены
исходное требование, кодовое основание, конкретный остаток и граница проверки.

## Поиск цитаты после обновления документа — alpha.4

В сохранённой аннотации выберите «Выбрать новый источник», затем «Найти цитату
в новой версии». Поиск использует сохранённый текст цитаты и текущие фрагменты
того же документа и логического расположения. Он показывает каждое точное
совпадение отдельно: страницу, блок, диапазон символов Unicode и контекст.
Выберите нужное место, проверьте старую и новую привязки и подтвердите запись.
Ни один результат, даже единственный, не применяется автоматически.

Поиск не исправляет пробелы, переносы, регистр или Unicode-нормализацию и не
склеивает соседние фрагменты. Он проверяет до 1024 фрагментов и 8 МиБ текста;
один фрагмент — до 2 МиБ, суммарные данные записей — до 64 МиБ. По умолчанию
показывает до 20 совпадений, по команде — до 50. При превышении пределов
показывает неполноту. Для перенесённой цитаты без подтверждённой локальной
привязки остаётся ручной выбор; совпадение имени файла не считается основанием.

## Истёкшие результаты фоновых заданий — alpha.4

Graph export/learning хранит временные результаты в памяти до десяти минут;
при достижении лимитов результат может быть освобождён раньше. После этого API
временно возвращает понятный статус `expired`: до часа после истечения или
вытеснения, не более 128 записей на менеджер. Частый опрос не продлевает срок.
После превышения этих пределов либо перезапуска ID снова становится неизвестным.
Это не долговечная очередь. Сохранённые учебные запуски остаются в истории базы
независимо от срока хранения временного задания.

## Проверка и поставка

Для alpha.3 прошли полный `go test ./... -count=1 -timeout=300s`, `go vet ./...`,
125 JavaScript-тестов в 18 наборах, проверка синтаксиса 23 файлов и двух встроенных
скриптов HTML. Все три Windows-программы собраны, сверены по SHA-256 и проверены
командами версии.

В браузере alpha.3 на изолированной синтетической базе проверены Unicode-цитата
и цвет, пять областей PDF и масштаб, JSON/Markdown-экспорт, создание ручного узла
графа и обратный переход к цитате, ручная перепривязка с предпросмотром и история
старой/новой записей. Текст PDF-фикстуры подготовлен отдельно: это проверка
интерфейса и хранения, а не качества OCR или извлечения формул.

Загрузка тестового JSON через браузер отклонена автоматической проверкой
разрешений. Браузерная приёмка импорта не завершена; серверные и компонентные
тесты импорта прошли. Запрет не обходился через другой способ загрузки.

Установка alpha.3 в `C:\Users\ZMII\bin` остановлена на проверке доступа:
`Deployment target ... is not writable ... Access to the path ... is denied`.
Три проверенные программы доступны в `build/mindmap-alpha3/bin`; подготовленная
сборка не означает, что установленная в PATH версия обновлена.

Итоговая alpha.4 также прошла полный `go test ./... -count=1 -timeout=300s`,
`go vet ./...`, **137 JavaScript-тестов в 18 наборах** и 23 проверки синтаксиса.
После перезапуска из alpha.3 сохранены аннотация, цвет, пять областей, связь с
графом и история. Новая область получила номер 6 без перестановки прежних.
Синтетическая вставка абзаца с emoji сместила цитату: в браузере показаны два
кандидата `[50,64)` и `[108,122)`. До подтверждения запись не создавалась;
после выбора второго сохранена именно эта позиция, а прежняя `[35,49)` осталась
неизменной. Читатель подсветил второе вхождение. Старые области и источник узла
графа помечены устаревшими. Ошибок в консоли браузера не обнаружено.

Отдельный дополнительный regression проверяет вставку абзаца с единственным
совпадением: найден новый диапазон и pin, автоматической записи нет. Этот
целевой Go-прогон прошёл после полного набора; изменён только тест.

Обычный release workflow выполнил тесты, сборку и проверку версий. Копирование
его staging в папку проекта сначала остановилось из-за собственного QA-процесса;
после остановки процесса три уже проверенных файла скопированы из сохранённого
