## Восемь воспроизведённых дефектов

| ID | Исправление | Проверка |

## Дополнительные замечания

- **Кэш и FTS.** Add/Delete обновляют поколение кэша в той же транзакции, что и
  запись. FTS использует долговечный журнал ID изменённых строк. Первое
  построение остаётся полным; обычные изменения синхронизируются отдельно,
  включая изменения из другого процесса. Тест с аудитом SQL подтверждает:
  обновление одной записи удаляет/вставляет только её FTS-строку и сохраняет
  нетронутые строки. Количественный выигрыш на пользовательском корпусе не измерялся.
- **Каталог файлов.** Добавлены индексы ID → позиция и path → позиция.
  Проверены удаление со сдвигом позиций, последующий UPSERT, повторное открытие
  и независимость возвращаемых копий. SQL UPSERT выполняется одним выражением.
- **Структура проекта.** Обработчики CLI разделены по областям; три HTML-ресурса
  перенесены в `pkg/mem/web` и включаются через `go:embed`. Сравнение чтением с
  исходными raw-литералами из HEAD подтвердило совпадение всех трёх ресурсов
  с учётом правила Go об удалении CR из raw-строк. Синтаксический тест JavaScript
  knowledge map через Node прошёл без Skip.
- **Текстовый импорт.** Единое ограниченное чтение UTF-8 для add-file/index/
  Markdown import: до 64 MiB на текстовый файл, отказ для NUL/неверного UTF-8,
  проверка отмены context в Markdown extractor. Тесты используют временные
  файлы, включая файл размером выше лимита.
- **Telegram.** `/import` больше не обещает обработать присланный файл и
  прямо объясняет доступный локальный способ импорта.
- **Windows deployment.** Проверяется версия staged-комплекта до установки;
  временные имена уникальны. При ошибке сохраняются staging и резервные
  бинарники с указанием пути. `deploy/windows_test.ps1` исполняет реальные
  rollback/cleanup-блоки на временных файлах: один отказ восстановления
  не удаляет резервные копии и не затрагивает посторонние файлы.

## Данные прежних версий

Миграции схемы добавочные. Рабочие пользовательские базы и исходные документы
в этой проверке не переиндексировались. Для старых документов физический
отпечаток нельзя восстановить достоверно по одному текущему файлу: нужен
повторный `mem import` либо `mem index` для простых текстов.

Историческое расхождение аннотации и файла из R1 может уже иметь свежие
метаданные без каких-либо признаков ошибки. Для такого каталога нужен явный
`mem-index scan <корень> -enrich -embed`. Это описано в `USAGE_RU.md` и release notes.

## Итоговая проверка и выпуск

Итог штатного test/build/deploy записан в `release-1.70.4.txt`.
`go test ./... -count=1 -timeout=300s` прошёл: 9 пакетов с тестами,
`pkg/ui` без тестов. `pkg/mem` — 34,564 с. `go vet ./...`, форматирование Go
и `git diff --check` прошли.
Аварийный сценарий установщика прошёл (`deploy-recovery-test.txt`).

Визуальные браузерные сценарии и локальный race detector не выполнялись:
браузерный доступ был отклонён в ревью, GCC/Clang для Windows race отсутствуют
в PATH. Новые проверки используют изолированные базы, локальные HTTP-моки и
`httptest`; живые Ollama/Polza/Telegram, крупные пользовательские PDF и VDS не проверялись.

Все три Windows/amd64 бинарника собраны; команды `version` staged-комплекта
успешно показывают **1.70.4**. SHA-256 и размеры записаны в
`release-1.70.4-manifest.json`. Комплект сохранён по адресу:

```text
C:\Users\ZMII\AppData\Local\Temp\mem-tool-windows-build-286a8b0dffc740f59d17d7b2b16e5d19
```

Первая установка остановилась до замены файлов из-за работающего `mem.exe`.
Пользователь закрыл программу; повторная проверка подтвердила отсутствие
процессов mem/mem-index/mem-bot. Повторный штатный запуск снова успешно выполнил
все тесты (9 пакетов; `pkg/mem` — 30,852 с), сборку и staged version smoke.

**Повторная установка заблокирована правами этого сеанса:** `Copy-Item` на
строке 104 `deploy/windows.ps1` получил `Access denied` при создании
`C:\Users\ZMII\bin\mem.exe.<unique-id>.new`. До замены установленных файлов
скрипт не дошёл. Все три установленные программы проверены и по-прежнему
показывают **1.70.3**; посторонние файлы и их метаданные сохранены, временных
incoming-файлов в каталоге установки нет.

Повторный проверенный комплект 1.70.4 сохранён в:

```text
C:\Users\ZMII\AppData\Local\Temp\mem-tool-windows-build-ec87580eece14355b7c99cccf597e116
```

Его SHA-256 совпадают с первой сборкой. Журнал повторного запуска —
`install-1.70.4.txt`, контрольные суммы и установленные версии —
`install-1.70.4-manifest.json`. Сборка готова, установка не завершена.
