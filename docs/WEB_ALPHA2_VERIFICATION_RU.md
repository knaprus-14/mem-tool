# Проверка веб-импорта 1.71.0-alpha.2

Дата: 9 сентября 2026 года. Реализована первая часть второго этапа из
[плана](WEB_ROADMAP_RU.md): отдельные файлы и сохраняемые задания обработки.

## Автоматические проверки

- `go test ./... -count=1 -timeout=300s` через `deploy/windows.ps1` — успешно.
- `go vet ./...` — успешно.
- `node --check internal/webapp/assets/app.js` — успешно.
- `git diff --check` — без ошибок; остаются предупреждения Git о нормализации
  окончаний строк в части ранее изменённых файлов.

Новые проверки выполнялись на отдельных временных базах и локальном тестовом
HTTP-сервисе векторов. Реальные документы и платные модели не использовались.

Проверены:

- загрузка через HTTP → очередь → извлечение Markdown → запрос векторов →
  запись фрагментов → появление документа в API библиотеки;
- сохранение метаданных, ID источника и очереди; повторное открытие очереди;
- возврат прежнего задания для одинакового содержимого, отсутствие новых
  фрагментов при повторном импорте и сохранение `web:` ID в обычном импортёре;
- отмена ожидающего и активного задания, новая попытка после отмены/прерывания;
- отказ второму обработчику той же базы, пока первый держит OS-lock;
- восстановление после атомарной записи документа до завершения задания —
  без повторных запросов векторов;
- явный статус незавершённого задания вместо автоматического повторного импорта;
- сохранение статуса постороннего импорта: веб-писатель не выполняет recovery
  чужих процессов;
- запрет чтения, загрузки, отмены и повторной попытки для другого владельца,
  отказ анонимному запросу и запросу без CSRF;
- отказ неподдерживаемому имени/формату, файлу больше 64 МиБ и переполненной
  очереди; удаление временных файлов отвергнутой загрузки;
- отказ изменённому сохранённому оригиналу до вызова модели;
- отсутствие создания `web-jobs.db` при чтении списка заданий в нетронутой базе.

## Браузер

Проверены первый запуск, создание отдельной базы, форма добавления документов,
переход в раздел обработки и отсутствие ошибок в консоли. При ширине окна 390 px
форма не создаёт горизонтального переполнения.

Выбор тестового файла для загрузки через браузер отклонён автоматической
проверкой разрешений: инструмент сообщил, что разрешение на загрузку на localhost
не выдано. Этот отказ не обходили. Поэтому выбор файла, отправка формы и живое
обновление заполненного списка заданий не подтверждены браузерной проверкой;
сквозной импорт и управление заданиями подтверждены HTTP/Go-тестами выше.

## Сборка и установка

`deploy/windows.ps1 -Target ./build/web-alpha/windows-amd64` успешно выполнил
общие тесты, сборку всех трёх Windows/amd64 программ, проверку версий, копирование
и сравнение SHA-256 в отдельной папке репозитория. Хэши и версии находятся в
`build/web-alpha/windows-amd64/verification.json`.

Собран Linux/amd64 `mem` с `CGO_ENABLED=0`:
`build/web-alpha/linux-amd64/mem`. Запуск на Linux и VDS не проверялся.

Обычная установка через `deploy/windows.ps1` остановлена preflight: запись
пробного файла в `C:\Users\ZMII\bin` получила `Access denied` до тестов/сборки.
При финальной проверке в этом каталоге все три программы имеют версию
**1.71.0-alpha.1**. Alpha.2 размещена только в проверочной папке репозитория.
На VDS ничего не развёрнуто.

Go завершил проверки и сборки успешно, несмотря на предупреждения об отсутствии
доступа к телеметрии и stat-кэшу модулей. Использовались доступный временный
`GOCACHE`, `GOPROXY=off`, `GOTOOLCHAIN=local`; зависимости не устанавливались.

## Границы проверки

Поддерживаемые PDF/DjVu/OCR используют существующий импортёр; новые реальные
PDF/DjVu через браузер в этом прогоне не загружались. Общие тесты импортёра прошли.
Качество поиска и реальных нейросетевых моделей этот тестовый сервис не измеряет.

Впереди: рекурсивные папки, обновление существующего документа новой редакцией,
полная миграция путей/истории/карт, глобальные квоты и резервное копирование,
веб-поиск/ответы и редактирование настроек. Публичный запуск сервиса не заявляется.
